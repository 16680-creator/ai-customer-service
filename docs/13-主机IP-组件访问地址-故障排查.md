## 4. 临时访问内部组件

在 `k8s-master` 执行下面命令，然后从 Windows 浏览器访问。

先确认组件已经部署出来：

```bash
kubectl get svc -n ai-customer-service
kubectl get pods -n ai-customer-service -o wide
```

如果 `svc/nacos` 或 `svc/minio` 不存在，说明基础设施还没部署。先在 Jenkins 运行 `DEPLOY_MODE=infra-only`，或手动执行 `deploy/scripts/k8s-apply-infra.sh`。

Nacos：

```bash
kubectl port-forward -n ai-customer-service svc/nacos 8848:8848 --address 0.0.0.0
```

```text
http://192.168.56.10:8848/nacos
```

默认账号密码通常为：

```text

```

MinIO：

```bash
kubectl port-forward -n ai-customer-service svc/minio 9001:9001 --address 0.0.0.0
```

```text
http://192.168.56.10:9001
```

默认账号密码为：

```text
minioadmin / minioadmin
```

Elasticsearch：

```bash
kubectl port-forward -n ai-customer-service svc/elasticsearch 9200:9200 --address 0.0.0.0
```


## 6. 常见故障

### 6.1 Jenkins 连不上 Kubernetes

错误：

```text
dial tcp 192.168.56.10:6443: connect: no route to host
```

处理：

```bash
ping -c 3 192.168.56.10
nc -vz 192.168.56.10 6443
sudo -u jenkins kubectl get nodes -o wide
```

如果 master 虚拟机刚启动，执行：

```bash
sudo swapoff -a
sudo systemctl restart kubelet
sudo ss -lntp | grep 6443
kubectl get nodes -o wide
```

### 6.2 Docker Hub 镜像拉取失败

错误：

```text
failed to resolve reference "docker.io/library/..."
connect: connection refused
```

处理：项目 Dockerfile 和 K8s YAML 已改为 `docker.m.daocloud.io` 镜像入口。worker02 还需要配置 Docker：

```bash
cd ~/ai-customer-service
git pull
sudo REGISTRY=192.168.56.12:5000 bash deploy/scripts/setup-jenkins-docker-insecure-registry.sh
sudo systemctl restart docker
```

### 6.3 Kubernetes 拉本地镜像失败

错误：

```text
ImagePullBackOff
server gave HTTP response to HTTPS client
```

三台节点都执行：

```bash
cd ~/ai-customer-service
sudo REGISTRY=192.168.56.12:5000 bash deploy/scripts/setup-containerd-insecure-registry.sh
sudo systemctl restart containerd
sudo systemctl restart kubelet
```

当前环境使用的是 HTTP 本地仓库 `192.168.56.12:5000`。如果看到 `http: server gave HTTP response to HTTPS client`，说明节点的 containerd 仍在按 HTTPS 拉镜像，重点检查：

```bash
sudo grep -n "registry\|config_path" /etc/containerd/config.toml
sudo cat /etc/containerd/certs.d/192.168.56.12:5000/hosts.toml
```

期望包含：

```text
config_path = "/etc/containerd/certs.d"
server = "http://192.168.56.12:5000"
```

### 6.4 MySQL 等待超时

错误：

```text
Waiting for 1 pods to be ready...
error: timed out waiting for the condition
```

检查：

```bash
kubectl get pods -n ai-customer-service -o wide
kubectl describe pod -n ai-customer-service mysql-master-0
kubectl logs -n ai-customer-service mysql-master-0
kubectl get pvc -n ai-customer-service
kubectl get storageclass
```

常见原因：

```text
local-path-provisioner 没安装
mysql 镜像拉取失败
节点磁盘空间不足
旧 PVC 数据异常
```

### 6.5 业务服务 CrashLoopBackOff

现象：

```text
api-gateway          CrashLoopBackOff
user-service         CrashLoopBackOff
ai-chat-service      CrashLoopBackOff
```

优先看日志：

```bash
kubectl logs -n ai-customer-service deployment/api-gateway --previous --tail=120
kubectl logs -n ai-customer-service deployment/user-service --previous --tail=120
```

常见原因是基础设施没有部署，`svc` 中缺少 `nacos`、`redis`、`elasticsearch`、`rocketmq-namesrv`、`minio`。业务服务依赖这些组件，尤其网关和所有业务服务都要连接 `nacos:8848`。

处理顺序：

```text
1. 先部署基础设施：DEPLOY_MODE=infra-only，DEPLOY_INFRA 勾选
2. 确认 nacos / redis / elasticsearch / rocketmq / minio Pod 都是 READY 1/1
3. 再部署业务服务：DEPLOY_MODE=deploy-only，指定 VERSION
```

如果 Nacos 是 `0/1 Running`，先查 Nacos 日志：

```bash
kubectl logs -n ai-customer-service deploy/nacos --tail=200
kubectl describe pod -n ai-customer-service -l app=nacos
```

如果日志里是数据库表不存在、连接 MySQL 失败，先确认数据库初始化是否执行过。首次部署应勾选 `INIT_DATABASE`；已经部署过可手动执行初始化脚本后重启 Nacos：

```bash
NAMESPACE=ai-customer-service bash deploy/scripts/k8s-init-mysql.sh
kubectl rollout restart deploy/nacos -n ai-customer-service
```

如果 RocketMQ 仍是 `ContainerCreating`，先查事件，一般能看到镜像拉取、挂载、资源或节点问题：

```bash
kubectl describe pod -n ai-customer-service -l app=rocketmq-namesrv
kubectl describe pod -n ai-customer-service -l app=rocketmq-broker
kubectl get events -n ai-customer-service --sort-by=.lastTimestamp | tail -n 80
```

基础设施都 Ready 后，再重启业务服务：

```bash
kubectl rollout restart deploy/api-gateway deploy/user-service deploy/knowledge-service deploy/ai-chat-service deploy/search-service deploy/message-service deploy/notify-service -n ai-customer-service
kubectl get pods -n ai-customer-service -o wide -w
```

### 6.6 Spring AI 依赖版本错误

错误：

```text
'dependencies.dependency.version' for org.springframework.ai:spring-ai-openai-spring-boot-starter is missing
```

处理：Spring AI 1.0.0 使用：

```xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-openai</artifactId>
</dependency>
```

### 6.7 API Key 泄露

如果 Jenkins 日志打印了真实 `OPENAI_API_KEY`，这个 key 应立即在服务商后台作废并重新生成。Jenkinsfile 中应使用 `password` 参数，并在写入 Secret 前 `set +x`，避免日志回显。
