# 项目配置文件和目录说明

本文档用于快速判断项目里每个主要文件夹、配置文件、部署脚本是做什么的。修改配置前，建议先看这一份，再去看具体文件。

---

## 1. 顶层目录说明

| 路径 | 作用 | 是否经常修改 |
|---|---|---|
| `ai-cs-common/` | 公共模块，放通用返回对象、异常、工具类、公共实体等，被其他微服务依赖 | 偶尔 |
| `ai-cs-gateway/` | API 网关服务，统一入口、路由转发、鉴权过滤、跨域配置 | 经常 |
| `ai-cs-user/` | 用户服务，处理用户、登录、账号相关能力 | 经常 |
| `ai-cs-knowledge/` | 知识库服务，处理知识文档、MinIO 文件、知识库数据 | 经常 |
| `ai-cs-chat/` | AI 对话服务，集成 Spring AI / OpenAI 兼容接口，处理聊天和 RAG 对话 | 经常 |
| `ai-cs-search/` | 搜索服务，连接 Elasticsearch，提供全文搜索能力 | 经常 |
| `ai-cs-message/` | 消息服务，连接 RocketMQ，处理异步消息 | 经常 |
| `ai-cs-notify/` | 通知服务，包含 WebSocket 推送能力 | 经常 |
| `deploy/` | 部署目录，包含 Docker Compose、Kubernetes YAML、初始化脚本、运维脚本 | 经常 |
| `docs/` | 项目文档目录，记录环境、部署、排错、访问地址 | 经常 |
| `.git/` | Git 本地仓库数据目录，不要手动修改 | 不改 |
| `.idea/` | IntelliJ IDEA 工程配置，本地开发环境文件 | 少改 |
| `.agents/`、`.codex-tmp/` | AI / Codex 工具临时或配置目录 | 不改 |

## 2. 顶层配置文件说明

| 文件 | 作用 | 关键内容 |
|---|---|---|
| `pom.xml` | Maven 父工程配置，统一管理所有模块、依赖版本、插件版本 | `modules`、Spring Boot / Spring Cloud / Spring AI / MyBatis / RocketMQ 等版本 |
| `Jenkinsfile` | Jenkins Pipeline 流水线配置 | 拉代码、环境检查、写 Kubernetes Secret、部署基础设施、构建镜像、推送镜像、部署服务 |
| `docker-compose.yml` | 单机 Docker Compose 部署方案 | 本地一键启动基础设施和服务，主要用于非 K8s 场景 |
| `.dockerignore` | Docker 构建时忽略文件 | 避免把 `.git`、`docs`、`target` 等无关内容打进构建上下文 |
| `.gitattributes` | Git 换行符规则 | 强制脚本、YAML、Jenkinsfile 使用 LF，避免 Linux 执行脚本失败 |
| `.gitignore` | Git 忽略规则 | 忽略编译产物、IDE 文件、日志、临时文件 |

## 3. 微服务模块通用结构

除 `ai-cs-common` 外，每个业务服务基本都有下面这些文件：

| 文件 / 目录 | 作用 |
|---|---|
| `pom.xml` | 当前微服务的 Maven 依赖配置 |
| `Dockerfile` | 当前微服务的 Docker 镜像构建文件 |
| `src/main/java/` | Java 业务代码 |
| `src/main/resources/application.yml` | 当前服务运行配置 |

Dockerfile 当前采用多阶段构建：

```text
第一阶段：使用 Maven 镜像编译 jar
第二阶段：使用 JRE 镜像运行 jar
```

当前 Dockerfile 基础镜像已使用国内镜像入口：

```text
docker.m.daocloud.io/library/maven:3.9-eclipse-temurin-17
docker.m.daocloud.io/library/eclipse-temurin:17-jre-jammy
```

## 6. Kubernetes YAML 文件说明

### 6.1 基础设施 YAML

| 文件 | 部署对象 | Service 类型 | 镜像 | 集群内访问 | 外部访问 |
|---|---|---|---|---|---|
| `deploy/k8s/namespace.yaml` | `Namespace/ai-customer-service` | 无 | 无 | 无 | 无 |
| `deploy/k8s/mysql.yaml` | `mysql-master`、`mysql-slave` StatefulSet | `ClusterIP` | `docker.m.daocloud.io/library/mysql:8.0` | `mysql-master:3306`、`mysql-slave:3306` | `port-forward` |
| `deploy/k8s/nacos.yaml` | `nacos` Deployment | `ClusterIP` | `docker.m.daocloud.io/nacos/nacos-server:v2.3.2` | `nacos:8848`、`nacos:9848` | `port-forward` 后访问 `/nacos` |
| `deploy/k8s/redis.yaml` | `redis` StatefulSet | `ClusterIP`、`Headless` | `docker.m.daocloud.io/library/redis:7` | `redis:6379` | `port-forward` |
| `deploy/k8s/elasticsearch.yaml` | `elasticsearch` StatefulSet | `ClusterIP` | `docker.m.daocloud.io/library/elasticsearch:8.12.0` | `elasticsearch:9200`、`elasticsearch:9300` | `port-forward` |
| `deploy/k8s/rocketmq.yaml` | `rocketmq-namesrv`、`rocketmq-broker` Deployment | `ClusterIP` | `docker.m.daocloud.io/apache/rocketmq:5.1.4` | `rocketmq-namesrv:9876`、`rocketmq-broker:10911`、`rocketmq-broker:10909` | 默认集群内使用 |
| `deploy/k8s/minio.yaml` | `minio` StatefulSet | `ClusterIP` | `docker.m.daocloud.io/minio/minio:latest` | API `minio:9000`、控制台 `minio:9001` | `port-forward` |

这些基础设施 YAML 的职责：

| 文件 | 主要配置内容 | 依赖关系 | 常见状态问题 |
|---|---|---|---|
| `deploy/k8s/mysql.yaml` | MySQL 主库、两个从库、Service、PVC、ConfigMap | 被 Nacos 和业务服务依赖 | PVC 没创建、local-path 未安装、旧数据异常 |
| `deploy/k8s/nacos.yaml` | Nacos 注册中心和配置中心，端口 `8848/9848`，连接 `mysql-master` | 依赖 MySQL 和数据库初始化 SQL | `0/1 Running` 通常要看 MySQL 连接或表结构 |
| `deploy/k8s/redis.yaml` | Redis StatefulSet、普通 Service、Headless Service、PVC | 被消息、会话、缓存能力依赖 | 镜像拉取失败、PVC 等待 |
| `deploy/k8s/elasticsearch.yaml` | Elasticsearch 单节点 StatefulSet、Service、PVC | 被搜索服务依赖 | 内存不足、PVC 等待、启动慢 |
| `deploy/k8s/rocketmq.yaml` | Namesrv、Broker、两个 ClusterIP Service | 被消息服务和通知服务依赖 | `ContainerCreating` 时先看 `describe pod` 和事件 |
| `deploy/k8s/minio.yaml` | MinIO StatefulSet、API `9000`、控制台 `9001`、PVC | 被知识库文件能力依赖 | PVC 等待、镜像拉取失败 |

当前 VMware 三节点环境的固定入口：

| 类型 | 地址 |
|---|---|
| Jenkins | `http://192.168.56.12:8080` |
| 本地 Docker Registry | `http://192.168.56.12:5000/v2/_catalog` |
| Kubernetes API | `https://192.168.56.10:6443` |
| 业务网关 NodePort | `http://192.168.56.10:30080`、`http://192.168.56.11:30080`、`http://192.168.56.12:30080` |

Nacos、MinIO、Elasticsearch、MySQL 默认没有固定浏览器入口，调试时从 `k8s-master` 做端口转发：

```bash
kubectl port-forward -n ai-customer-service svc/nacos 8848:8848 --address 0.0.0.0
kubectl port-forward -n ai-customer-service svc/minio 9001:9001 --address 0.0.0.0
kubectl port-forward -n ai-customer-service svc/elasticsearch 9200:9200 --address 0.0.0.0
kubectl port-forward -n ai-customer-service svc/mysql-master 3306:3306 --address 0.0.0.0
```

对应访问地址：

```text
Nacos: http://192.168.56.10:8848/nacos
MinIO Console: http://192.168.56.10:9001
Elasticsearch: http://192.168.56.10:9200
MySQL: 192.168.56.10:3306
```

注意：`port-forward` 窗口关闭后访问会断开。正式固定暴露需要把 Service 改成 `NodePort`、Ingress 或 LoadBalancer。

## 7. deploy/scripts 脚本说明

| 脚本 | 作用 | 常用场景 |
|---|---|---|
| `deploy/scripts/k8s-apply-infra.sh` | 部署 Kubernetes 基础设施，包括 MySQL、Nacos、Redis、ES、RocketMQ、MinIO | Jenkins 首次部署或手动部署基础设施 |
| `deploy/scripts/k8s-init-mysql.sh` | 等待 MySQL 主库 Ready，并导入 `deploy/mysql/init.sql` | 首次初始化数据库 |
| `deploy/scripts/k8s-build-push.sh` | 构建 7 个微服务 Docker 镜像，并推送到本地 Registry | Jenkins 构建镜像 |
| `deploy/scripts/k8s-deploy-services.sh` | 应用业务服务 YAML，并更新镜像版本 | Jenkins 部署业务服务 |
| `deploy/scripts/setup-local-registry.sh` | 在 worker02 启动本地 Docker Registry | 初始化本地镜像仓库 |
| `deploy/scripts/setup-jenkins-docker-insecure-registry.sh` | 配置 Docker 允许推送 HTTP Registry，并设置镜像加速 | worker02 / Jenkins 机器 |
| `deploy/scripts/setup-containerd-insecure-registry.sh` | 配置 containerd 允许从 `192.168.56.12:5000` 拉 HTTP 镜像 | 三台 K8s 节点都要执行 |
| `deploy/scripts/check-deploy.sh` | 检查部署状态 | 部署后排查 |
| `deploy/scripts/verify-deploy.sh` | 验证部署结果 | Docker Compose 方案排查 |
| `deploy/scripts/init-host.sh` | 初始化主机环境 | 老的多主机部署方案 |
| `deploy/scripts/deploy-host1.sh` | 部署 host1 上的组件 | Docker Compose 多主机方案 |
| `deploy/scripts/deploy-host2.sh` | 部署 host2 上的组件 | Docker Compose 多主机方案 |
| `deploy/scripts/deploy-host3.sh` | 部署 host3 上的组件 | Docker Compose 多主机方案 |
| `deploy/scripts/deploy-vars.example.sh` | 多主机部署环境变量示例 | 复制后按实际 IP 修改 |

当前 Kubernetes + Jenkins 流程主要使用：

```text
k8s-apply-infra.sh
k8s-init-mysql.sh
k8s-build-push.sh
k8s-deploy-services.sh
setup-local-registry.sh
```

## 10. Jenkinsfile 阶段说明

| 阶段 | 作用 |
|---|---|
| 拉取代码 | 从 Gitee 仓库拉取当前 `master` 分支代码 |
| 环境检查 | 检查 Docker、kubectl、Kubernetes 集群是否可用 |
| Maven 测试 | 根据 `SKIP_TESTS` 参数决定是否运行测试 |
| 写入 Kubernetes Secret | 创建或更新 `aics-secrets`，保存 AI API Key、Base URL、模型名 |
| 部署基础设施 | 根据 `DEPLOY_INFRA` 或 `DEPLOY_MODE=infra-only` 部署中间件 |
| 构建并推送镜像 | 构建 7 个微服务镜像并推到 `192.168.56.12:5000` |
| 部署业务服务 | 应用业务服务 YAML，并滚动更新镜像 |
| 部署验证 | 查看节点、Pod、Service 状态 |

常用 Jenkins 参数：

| 参数 | 作用 |
|---|---|
| `REGISTRY` | 本地镜像仓库，当前为 `192.168.56.12:5000` |
| `NAMESPACE` | Kubernetes 命名空间，当前为 `ai-customer-service` |
| `VERSION` | 镜像版本，留空则使用 Jenkins 构建号 |
| `DEPLOY_MODE` | 部署模式：完整、只构建、只部署、只部署基础设施 |
| `SERVICES` | 要处理的服务列表 |
| `SKIP_TESTS` | 是否跳过 Maven 测试 |
| `DEPLOY_INFRA` | 是否部署基础设施 |
| `INIT_DATABASE` | 是否初始化数据库 |
| `VERIFY_DEPLOY` | 是否执行部署后验证 |
| `OPENAI_API_KEY` | AI 接口密钥，必须用 Jenkins 密码参数保存 |
| `OPENAI_BASE_URL` | OpenAI 兼容接口地址 |
| `OPENAI_MODEL` | 模型名 |

## 12. 修改配置时的建议顺序

1. 改业务代码：优先看对应微服务的 `application.yml` 和 `pom.xml`。
2. 改镜像构建：看对应服务的 `Dockerfile` 和根目录 `.dockerignore`。
3. 改 Jenkins 流程：看 `Jenkinsfile` 和 `deploy/scripts/k8s-*.sh`。
4. 改 Kubernetes 部署：看 `deploy/k8s/*.yaml` 和 `deploy/k8s/services/*.yaml`。
5. 改数据库初始化：看 `deploy/mysql/init.sql`。
6. 改本地镜像仓库：看 `setup-local-registry.sh`、`setup-jenkins-docker-insecure-registry.sh`、`setup-containerd-insecure-registry.sh`。
7. 查访问地址：看 `docs/10-主机IP-组件访问地址-故障排查.md`。
