## 一、现状盘点

### 1.1 ai-cs-chat 现有 AI 能力

| 能力 | 实现位置 | 现状 |
|---|---|---|
| 基础对话 | `ChatServiceImpl.chat()` | ✅ 会话历史（内存 Map）+ 超 20 条自动 LLM 摘要压缩 + 过滤 `<think>` 标签 |
| RAG 对话 | `chatWithRag()` | ✅ Chroma 向量库 + bge-m3 向量化，Top-5、阈值 0.5，检索结果注入 Prompt |
| 工具调用 | `OrderQueryService`（2 个 `@Tool`） | ✅ 仅支持按订单号/用户 ID 查订单，数据为 mock |
| 流式对话 | `chatStream()` | ⚠️ 桩代码，只返回状态，无真实 SSE/WebSocket |
| 知识库管理 | `KnowledgeBaseController` | ✅ 文本/PDF/TXT 入库、语义检索测试 |

### 1.2 工程现有 AI 技术栈

| 技术 | 落点 | 状态 |
|---|---|---|
| LLM 对话（OpenAI 兼容，DeepSeek） | `ai-cs-chat` ChatClient | ✅ 已用 |
| RAG 向量检索 | Chroma + bge-m3 + TokenTextSplitter + QuestionAnswerAdvisor | ✅ 已用（基础版） |
| Tool/Function Calling | `OrderQueryService` | ✅ 已用（单轮、2 个工具） |
| 会话历史 LLM 摘要压缩 | `compressHistory()` | ✅ 已用 |
| 商品语义相似推荐 | `ai-cs-product` ProductVectorService | ✅ 已用（基础版） |
| 图片描述（视觉） | `ImageDescriptionService` | ⚠️ Noop 占位，未接真实视觉模型 |
| 本地哈希 Embedding | `HashEmbeddingModel` | ⚠️ 仅开发兜底 |

> 结论：当前 AI 技术栈 ≈ 单模型对话 + 基础 RAG + 单轮工具调用 + 向量推荐，属入门水平。

## 二、可补充的 AI 功能（结合业务）

### 🔴 P0：补齐基础体验短板（不改架构，价值最高）

1. **真正的流式对话（SSE/WebSocket）**
   - 业务价值：打字机式输出，用户体感从"等 10 秒"变为"1 秒开始读"
   - 落地：`chatStream()` 改为响应式 `Flux` 流 + 前端 EventSource；或复用 `ai-cs-notify` 的 WebSocket 推送
2. **会话/记忆持久化（内存 → Redis/MySQL）**
   - 业务价值：当前 `ConcurrentHashMap` 重启即丢、多实例不同步、换会话即"失忆"
   - 落地：接 `ai-cs-message` 的 `ChatSession`/`ChatMessage` 表；再升级到用户级长期记忆（偏好、历史诉求、会员等级）
3. **RAG 多轮追问**
   - 业务价值：`chatWithRag` 不带历史，用户问"那怎么退款？"AI 不知道"那"指什么
   - 落地：历史消息 + 检索上下文一起进 Prompt
4. **RAG 引用溯源（带出处回答）**
   - 业务价值：客服回答必须可查证，用户/坐席能看到依据资料
   - 落地：回答时返回命中文档片段及元数据（文档名/页码/相似度），前端卡片展示
5. **用户身份绑定 + 数据权限**
   - 业务价值：`sessionId` 任意传，`queryOrdersByUserId` 可查任何人订单，真实业务不可接受
   - 落地：网关 JWT 解析 userId 注入会话上下文，工具调用按当前用户过滤

### 🟠 P1：业务工具扩展（把电商核心业务变成 AI 能力）

| 工具域 | 具体能力 | 对应现有模块 |
|---|---|---|
| 商品工具 | 查商品/规格/价格/库存、商品对比、按需求推荐 | `ai-cs-product`（复用 ProductVectorService） |
| 售后工具 | 退款/退货/换货申请、进度查询、运费险说明 | `ai-cs-order` 扩展 |
| 优惠/营销工具 | 查可用优惠券、满减规则、最优凑单建议 | `ai-cs-order` Coupon / PromotionService |
| 购物车工具 | 加购、改数量、清空、结算试算 | `ai-cs-order` CartService |
| 物流工具 | 物流轨迹、预计送达时间 | 订单模块 + 第三方物流 API |
| 账户工具 | 个人信息、地址簿、积分/余额 | `ai-cs-user` |
| 检索工具 | 跨知识库/帮助中心混合检索 | `ai-cs-search`（ES）+ 向量检索 |

### 🟡 P2：从"回答问题"升级到"客服运营闭环"

- 情感分析 + 人工坐席转接（带上下文移交，接 `ai-cs-notify`）
- 会话摘要 + 工单自动生成
- 意图识别与智能路由（售前/订单/售后/投诉/闲聊）
- 高频问题聚类（发现知识库缺口，反哺 RAG 运营）
- 智能质检 + 满意度分析

### 🟢 P3：多模态 + 主动服务

- 语音客服：ASR（语音转文字）+ TTS（文字转语音）
- 图片理解：订单截图、发票、商品图识别处理（接 `ImageDescriptionService`）
- 主动触达：订单发货/签收/超时未付款节点 AI 生成个性化消息（`ai-cs-message` + `ai-cs-notify`）
- 购物车挽回：加购未支付用户主动推荐优惠
- 智能回访：售后完结后 AI 回访收集满意度

### 🔵 P4：安全合规（上线前必须补）

- 内容安全：敏感词过滤、违规内容审核
- PII 脱敏：手机号/身份证/银行卡自动脱敏
- Prompt 注入防护：输入校验 + 系统提示词加固
- 高风险意图强制人工兜底 + 提示词/模型 A/B 灰度

### 🟣 P5：数据洞察

- 对话分析看板：会话量、解决率、平均响应时长、转人工率
- 智能周报：AI 自动生成客服运营周报
- 预测预警：投诉风险、流失风险提前识别

## 三、缺失的 AI 技术（技术缺口分析）

### 3.1 多模态 AI（当前几乎空白）

| 缺失技术 | 业务场景 | 优先级 |
|---|---|---|
| 视觉理解（VLM） | 用户上传商品图/订单截图/发票/售后照片，AI 自动识别处理 | 🔴 高 |
| OCR 文字识别 | 截图/发票/快递单号提取 | 🟠 中 |
| ASR 语音识别 | App 语音输入 / 电话客服渠道 | 🟠 中 |
| TTS 语音合成 | AI 回复播报、IVR 语音客服 | 🟠 中 |
| 图像生成 | 营销海报、商品详情图、促销素材 | 🟢 低 |

### 3.2 RAG 进阶技术

| 缺失技术 | 说明 | 优先级 |
|---|---|---|
| 混合检索（Hybrid Search） | ES BM25 + 向量检索融合（RRF），"型号+问题"混合查询效果显著提升 | 🔴 高 |
| Rerank 重排序 | 召回 Top-20 → bge-reranker 精排 Top-5，RAG 精度提升最明显 | 🔴 高 |
| 引用溯源（Citation） | 回答带资料出处/页码，可查证、可复核 | 🔴 高 |
| 查询改写 / 多路召回 | 口语问题改写后再检索（HyDE、multi-query） | 🟠 中 |
| Text2SQL（NL2SQL） | "我上个月买了多少东西" → 结构化查询业务库 | 🟠 中 |
| GraphRAG / 知识图谱 | 商品-订单-用户关系推理（需图数据库如 Neo4j） | 🟢 低 |
| 文档格式扩展 | 现仅 PDF/TXT；缺 DOCX/Excel/HTML/Markdown/网页爬取 | 🟠 中 |
| 知识库自动同步/增量更新 | 数据变更 → MQ → 重新向量化 | 🟠 中 |

### 3.3 Agent / 编排技术

| 缺失技术 | 说明 | 优先级 |
|---|---|---|
| 多步 Agent 工作流（ReAct/规划-执行循环） | 现为单轮工具调用，缺"规划→调多工具→反思→再回答"循环 | 🔴 高 |
| 记忆系统（ChatMemory） | Spring AI 有 `ChatMemory`/`MessageWindowChatMemory` 抽象但未使用 | 🔴 高 |
| 意图路由（Intent Routing） | 问题先分类再选工具链/知识库/人工，现靠提示词硬撑 | 🔴 高 |
| MCP（Model Context Protocol） | 标准化接入订单/商品/物流等工具，避免工具多了维护爆炸 | 🟠 中 |
| 多 Agent 分工 | 售前/售后/投诉 Agent 分流，各自带工具与知识库 | 🟠 中 |

### 3.4 传统 NLP / ML 技术（均未使用）

| 缺失技术 | 业务价值 | 优先级 |
|---|---|---|
| 情感分析 | 识别愤怒/投诉 → 自动转人工，客服平台核心兜底 | 🔴 高 |
| 文本分类（意图识别） | 售前/售后/物流/投诉 自动分流 | 🔴 高 |
| NER 实体抽取 | 抽取订单号、商品名、地址填充工具参数 | 🟠 中 |
| 文本聚类 | 高频问题聚类 → 知识库缺口、FAQ 优化 | 🟠 中 |
| 语义匹配/FAQ 命中 | 常见问题直接命中缓存，省 Token 秒回 | 🟠 中 |
| 推荐系统 | 对话上下文 + 用户行为的商品推荐 | 🟢 低 |

### 3.5 LLM 工程化 / 生产化（文档有、代码无）

| 缺失技术 | 现状 | 优先级 |
|---|---|---|
| 流式输出（SSE/WebSocket） | `chatStream()` 桩代码，未用 WebFlux | 🔴 高 |
| 超时/重试/熔断/降级 | 学习文档有示例（Resilience4j），代码未实现 | 🔴 高 |
| 多模型路由/分级模型 | 单一 deepseek-chat | 🟠 中 |
| LLM 响应缓存 | FAQ 命中直接返回，省 Token | 🟠 中 |
| Token 成本统计与配额 | 无计量、无预算控制 | 🟠 中 |
| LLM 可观测性（追踪） | 无 OpenTelemetry/Langfuse 类全链路追踪 | 🔴 高 |
| Prompt 版本管理 / A-B 灰度 | System Prompt 硬编码在 `SpringAiConfig` | 🟠 中 |

### 3.6 安全合规

| 缺失技术 | 说明 | 优先级 |
|---|---|---|
| 内容安全 / Moderation | 敏感词、违规内容过滤 | 🔴 高 |
| PII 脱敏 | 手机号/身份证/银行卡自动脱敏 | 🔴 高 |
| Prompt 注入防护 | 输入校验 + 提示词加固 | 🔴 高 |
| 对话审计 / 合规留痕 | 存储加密、导出、审计 | 🟠 中 |

### 3.7 向量检索与 AI 基础设施

| 缺失技术 | 说明 | 优先级 |
|---|---|---|
| 生产级向量库 | Chroma 单机；生产换 Milvus/Qdrant/ES 向量/pgvector | 🟠 中 |
| 模型网关/统一 LLM 入口 | 网关层统一鉴权、限流、计量、多模型路由 | 🟠 中 |
| 模型微调（Fine-tuning） | 用历史客服对话微调领域风格 | 🟢 低 |
| 评估体系（RAGAS/LLM-as-Judge） | golden dataset 回归，量化改动影响 | 🔴 高 |
| 调度/定时任务 | 主动触达、知识库定期重建、会话清理 | 🟠 中 |

## 四、推荐落地路线

```
第 1 步（1~2 周）  生产化底座：流式输出 + 超时重试降级 + 会话持久化 + 用户身份绑定
第 2 步（2~4 周）  RAG 进阶 + 业务工具：混合检索 + Rerank + 引用溯源 + 商品/售后/优惠券工具
第 3 步（持续）    运营闭环：情感转人工 → 会话摘要工单 → 高频问题聚类
第 4 步（按需）    多模态/主动服务 + 安全合规（上线前完成） + 数据洞察
```

架构前置建议：尽早将 `ai-cs-chat` 演进为**统一 Agent 编排层**（意图路由 → 多工具 → 多轮记忆 → 多模型），并建立 **RAG/对话评估集**（LLM-as-Judge），避免加功能后大方法不可维护、改动无量化指标。
