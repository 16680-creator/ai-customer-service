## 一、结论摘要（2026-08-07 时点，已过期）

**当时前端确实有很多后端功能没有覆盖，主要集中 3 个方面：**

1. **电商交易核心链路整体缺失**：购物车 → 结算 → 下单 → 订单管理 → 支付，前端几乎没有（`去结算` 跳转的 `/checkout` 页面不存在）。
2. **AI 能力只用了基础对话**：RAG 对话、流式对话、向量知识库管理均未接入前端。
3. **商品/知识库管理不完整**：缺详情、编辑、删除、分类管理、知识库详情。

## 三、缺失功能详情（2026-08-07 快照）

### 3.1 电商交易链路断裂（当时最严重）

- 前端页面路由只有 10 个：`/login / /chat /user /knowledge /message /notify /search /product`（+购物车在？）
- **CartView 的「去结算」按钮跳转 `/checkout`，但该路由/页面不存在 → 死链**
- 缺失页面：结算页、订单列表页、订单详情页、支付页
- 后端 order 的 5 个接口 + cart 的 checkout/confirm 全部闲置

### 3.2 AI 能力未充分利用

- ChatView 仅调用 `/chat/send`，**RAG 对话（/chat/rag）与流式对话（/chat/stream）未接**
- chat 服务的**向量知识库管理**（入库/检索）没有前端入口，KnowledgeView 用的是 ai-cs-knowledge 的文档管理（两套体系未打通）

### 3.3 管理功能不完整

- 商品：无详情/编辑/删除/分类管理 UI
- 知识库：无详情查看

## 七、给求职者的用法（新增）

这篇文档在面试里可以这样用：

- 讲"前后端联调"时：**用一份真实的覆盖分析表**说明你怎么发现"后端 5 个订单接口没人调"，而不是空谈"我负责前后端联调"。
- 讲"工程习惯"时：说明你会给文档打**状态标记**（历史快照 vs 现行结论），避免团队按过期文档排期。
- 讲"取舍"时：勾选状态为什么先放前端（成本低），什么情况下必须落库（多端一致、跨设备）。
