# 20 - 前端功能覆盖分析（后端接口 vs 前端调用）

> 分析日期：2026-08-07
> 方法：逐页扫描前端 View 的 API 调用，与后端全部 Controller 接口对比

---

## 一、结论摘要

**前端确实有很多后端功能没有覆盖，主要集中 3 个方面：**

1. **电商交易核心链路整体缺失**：购物车 → 结算 → 下单 → 订单管理 → 支付，前端几乎没有（`去结算` 跳转的 `/checkout` 页面不存在）。
2. **AI 能力只用了基础对话**：RAG 对话、流式对话、向量知识库管理均未接入前端。
3. **商品/知识库管理不完整**：缺详情、编辑、删除、分类管理、知识库详情。

## 三、缺失功能详情

### 3.1 电商交易链路断裂（最严重）

- 前端页面路由只有 10 个：`/login / /chat /user /knowledge /message /notify /search /product`（+购物车在？）
- **CartView 的「去结算」按钮跳转 `/checkout`，但该路由/页面不存在 → 死链**
- 缺失页面：结算页、订单列表页、订单详情页、支付页
- 后端 order 的 5 个接口 + cart 的 checkout/confirm 全部闲置

### 3.2 AI 能力未充分利用

- ChatView 仅调用 `/chat/send`，**RAG 对话（/chat/rag）与流式对话（/chat/stream）未接**
- chat 服务的**向量知识库管理**（入库/检索）没有前端入口，KnowledgeView 用的是 ai-cs-knowledge 的文档管理（两套体系未打通）

### 3.3 管理功能不完整

- 商品：无详情/编辑/删除/分类管理 UI
- 知识库：无详情查看

## 四、建议优先级

| 优先级 | 内容 |
|---|---|
| 🔴 P0 | 补齐电商交易链路：结算页（checkout/confirm）→ 下单（order/create）→ 订单列表/详情/取消 → 支付 |
| 🟠 P1 | ChatView 接入 RAG 对话 + 流式对话 + 向量知识库管理页 |
| 🟡 P2 | 商品详情/编辑/删除、分类管理；知识库详情查看 |

## 五、其他发现

1. **ProductView 图片上传直连 `http://localhost:8088/product/upload-image`**（绕过网关），建议统一走网关 `/api/product/upload-image`。
2. Dashboard 无任何 API 调用（纯展示）。
3. cart 的「勾选」由前端本地维护 `selectedIds`，未调用 `/cart/select`，与后端购物车勾选状态可能不一致。
