### 已覆盖的输入和流程

- 登录：缺失、`null`、空字符串、纯空白用户名/密码；合法请求保持业务委托。
- JSON：语法不完整、`String` 字段收到对象、Long ID 收到非数字；统一 HTTP 400 + `Result.code=400`。
- 注册：必填、密码最短 6 字符、用户名最多 64 字符、密码最多 72 字符。
- 多字节密码：额外按 UTF-8 **72 字节**限制校验；24 个三字节中文字符注册并登录，25 个则拒绝。
- 更新：缺失 ID 返回 400，本人更新正常落库；不再因授权表达式空指针产生 500。
- 资料更新白名单：即使请求夹带 `role=admin/status=0/deleted=1`，数据库中的用户名、密码、角色、状态和删除标记保持不变。
- 注册到登录：首次创建成功，重复创建保留原 `code=1002`，正确密码签发 token，错误密码保留 `code=1003`。
- 持久化：密码为 BCrypt 哈希而非明文；默认角色/状态正确；`createTime/updateTime` 非空；中文错误响应按 UTF-8 字节断言。
- 路径 ID：非数字输入返回 400，不进入业务层。

## 3. 本次修复的实际问题

1. 注册直接接收未校验实体，空值、短密码及超长输入会进入 Service/数据库。
2. 更新表达式 `#p0.id.toString()` 对空 ID 求值失败；改为空安全表达式并使用更新分组校验。
3. `HttpMessageNotReadableException` 与参数类型转换异常进入 500 兜底；现统一映射为 400。
4. 用户实体声明了 `@TableField(fill=...)`，但模块没有 `MetaObjectHandler`；H2 实测注册因审计时间写入 `NULL` 失败，现已补齐自动填充。
5. Boot 4 MVC 测试使用独立 `webmvc-test`、`security-test` starter；切片测试需保留公共 Web 自动配置，不能只 mock MVC 后声称验证了异常映射。
6. E2E 复现普通用户在更新昵称时夹带 `role=admin` 后真实提权；通用资料更新现显式清除账号安全字段和客户端审计字段，角色/状态管理须由独立授权接口负责。
