# 交付手册模板（Delivery Playbook Template）

> **这是什么**：FDE 在客户现场交付软件时必须产出的一份文档。它决定了客户能不能自己把系统跑起来、能不能签字验收、出了问题能不能自己查。
>
> **怎么用**：复制本文件 → 重命名为 `<客户简称>-交付手册-v1.0.md` → 逐节把【填写指引】替换为实际内容 → 交付前删掉所有【填写指引】和【示例】标记。
>
> **合格标准**（用这条自检是否写到位）：
> - 客户的**业务负责人**只看第 1、2、7 章，就能判断"这东西是不是我要的、什么时候能验收"。
> - 客户的**运维/技术团队**只看第 6、8、9 章，就能独立完成部署、回滚和日常排障，不需要给你打电话。
> - **任何一章出现"详见内部文档""问 XX 即可"，即为不合格。**

## 1. 一页纸摘要（给业务负责人看）

> 【填写指引】本章禁止出现技术名词。写完后交给一个非技术的同事读，他读不懂就重写。

**我们要解决的问题**

【填写指引】一句话，用客户自己的话，写他现在的痛。示例：
> 客服团队 12 人，每天约 800 通咨询里有 6 成是重复的退换货政策问题；新人培训要 2 周才敢独立接待，旺季人手不够直接掉转化。

**我们交付了什么**

【填写指引】3 条以内，写"客户能用它做什么"，不写"用了什么技术"。示例：
> 1. 一个客服工作台：客户提问时自动给出标准答案和出处，客服确认后一键发送。
> 2. 一个知识库管理页：运营自己上传政策文档，当天生效，不需要研发介入。
> 3. 一套升级机制：AI 答不上来或客户情绪激动时，自动转人工并带上完整上下文。

> 【填写指引】本章的判定标准：**客户运维照着敲，不问人，就能跑起来。** 每一步都要有：命令 + 预期输出 + 耗时 + 失败怎么办。

**6.1 部署前检查**

```bash
# 一键自检：环境依赖 + 端口 + 容器状态
```

## 附：填写样例（AI 智能客服平台）

以下是本项目作为参考样例的填写示范，替换为客户实际情况即可。

**§1 一页纸摘要**

> 客服团队每天处理约 800 通咨询，其中退换货政策、物流时效、发票开具三类重复问题约占 6 成；新客服需培训 2 周才能独立接待。
>
> 本次交付三样东西：一个带知识库的客服工作台（提问即给标准答案与出处）、一个运营自助维护知识库的后台（当天生效、不依赖研发）、一套人工转接机制（AI 答不上来时带着上下文转人工）。

**§2 交付范围**

| | 内容 |
|---|---|
| In Scope | 对话服务、知识库服务（含文档向量化与检索）、客服工作台页面、运营后台、部署脚本与自检脚本、本手册 |
| Out of Scope | 不改造客户现有 CRM；不做工单系统的双向同步；不承担客户原始文档的录入与校对 |
| 明确不做 | 不承诺特定模型效果的准确率数字，仅承诺检索链路可用性与降级行为 |

**§4 前置条件**（关键项）

| 项 | 要求 |
|---|---|
| 出网 | AI 对话服务需访问外部模型 API（`api.siliconflow.cn` 等）；若不开放，改用内网 Ollama 部署 |
| 向量库 | Chroma 需 `v2 API`，地址与业务库同主机，端口 8000 |
| 注册中心 | Nacos，命名空间固定为 `aics`，服务分组 `DEFAULT_GROUP` |
| JDK | 17+（实测使用 21） |

**§6.4 常见部署失败**（真实踩坑记录）

| 现象 | 根因 | 处置 |
|---|---|---|
| 启动报 410，提示 v1 API deprecated | 远程 Chroma 只提供 v2 API，旧版 Spring AI 走 v1 | 升级 Spring AI 至 1.1.4+，并配置 `tenant-name` / `database-name` |
| 集合明明存在却报 404 | Spring AI 1.0.0 存在错误消息字符串比对缺陷 | 同为升级到 1.1.4 修复 |
| 运行期报找不到向量库地址 | Chroma 主机从部署机不可达 | 先用自检脚本第 3 层「中间件协议态」确认 `8000` 端口与 heartbeat |

**§7.2 性能验收**（示例目标值）

| 指标 | 目标值 | 测量方法 |
|---|---|---|
| 非流式问答响应 P95 | ≤ 5s | 压测工具 50 并发、500 次请求取样 |
| 流式首 token 时间 | ≤ 2s | 前端打点统计 |
| 缓存命中时响应 | ≤ 200ms | 热门问答缓存命中路径 |

**§9 运维交接**（本项目可用工具）

| 交接项 | 内容 |
|---|---|
| 自检 | `deploy/scripts/check-local.ps1`（本机）/ `deploy/scripts/verify-deploy.sh`（三主机） |
| 监控 | Prometheus + Grafana + Tempo（`deploy/observability/`） |
| 部署 | `deploy/docker-compose/` 分层编排 / `deploy/k8s/` 清单 / `Jenkinsfile-k8s` |
| 排障 | `docs/13-主机IP-组件访问地址-故障排查.md` |
