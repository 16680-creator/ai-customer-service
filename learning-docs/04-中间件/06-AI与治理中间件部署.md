## 一、问题：代码有依赖，部署没有服务

扫描发现：

| 中间件 | 代码使用 | 改造前问题 |
|--------|----------|------------|
| Chroma | chat/knowledge/search 的 Spring AI Chroma vector store，端口 8000 | compose/k8s 缺服务，重启风险丢向量 |
| Neo4j | chat GraphRAG（Bolt 7687） | 完全无部署物 |
| XXL-Job Admin | order `XxlJobConfig`，执行器默认关闭 | 有建表 SQL，无 Admin 容器，任务不能调度 |
| Sentinel Dashboard | chat Sentinel starter | 无控制台，规则无法可视化管理 |

这类问题叫**部署漂移**：代码、配置、基础设施三个层面没有一起演进。

### Secret 前置条件

Neo4j 与 XXL Admin 的密码/Token 绝不能写入 Git。部署前：

```bash
cp deploy/k8s/middleware-secrets.example.yaml /secure/path/middleware-secrets.yaml
# 编辑真实密码后（不要提交）
kubectl apply -f /secure/path/middleware-secrets.yaml
bash deploy/scripts/k8s-apply-infra.sh
```

模板中的 `neo4j-secret`、`xxl-job-admin-config` 与 Deployment 的 `secretKeyRef` 一一对应，
没有 Secret 时 Pod 会保持 Pending/ContainerCreating，这是正确的 fail-closed 行为。

## 四、配置与网络

- 本地服务的 Chroma 默认 `CHROMA_PORT=8000`，compose 内服务名为 `chroma`；
  容器化业务服务须将 CHROMA host 配为 `http://chroma`（而非 application.yml 的 localhost 默认）
- Neo4j 业务连接须使用 `bolt://neo4j:7687`（容器/K8s 内）与 Secret 中的密码
- order 启动 XXL 执行器：`XXL_JOB_ENABLED=true`，本地 Admin 地址
  `XXL_JOB_ADMIN=http://xxl-job-admin:8080/xxl-job-admin`（宿主进程则 localhost:8099）
