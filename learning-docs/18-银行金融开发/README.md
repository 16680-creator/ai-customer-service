# 银行金融开发（Java 银行岗方向）

> 本专题是 `learning-docs` 的 **第十八个模块**（`18-银行金融开发`），回答一个问题：**一个零金融经验的 Java 后端，怎么在最短时间里达到"银行开发岗位 JD 所要求的那种熟悉"**。
> 本模块针对的岗位要求原文：
> **「拥有金融行业研发工作经验者优先，熟悉银行柜面系统、结算现金管理、网络金融等相关业务系统研发运维工作，了解银行业信息安全管理规范。」**
> **最大特色**：不做学术综述。每篇按"这个系统是什么 → 一笔业务在里面怎么流 → 需求会怎么写 → 代码要防什么 → 面试怎么答"组织；凡是能落到本仓库真实代码的能力（幂等、对账、状态机、脱敏、熔断），都给出 `文件:行号` 级对照；本项目做不到的部分（复式记账、冲正、日切、密评）用 ⚠️/❌ 显式标注，不假装银行系统。
> 前置阅读：[00-学习路线总览](../00-学习路线总览/README.md)、[01-银行IT体系与岗位全景](./01-银行IT体系与岗位全景.md)

## 一、为什么要单独学"银行金融开发"

`01`~`17` 教你**通用工程能力**（Spring、数据库、中间件、性能、稳定性、云原生）。银行岗的筛人逻辑不同：**工程能力只是及格线，能不能听懂业务、守不守得住生产红线，才是区分度**。

| 场景 | 只有通用后端能力 | 补了本模块 |
|---|---|---|
| 面试官问"你了解柜面系统吗" | "不就是个后台管理页面？" | 能说清交易码、经办-复核-授权三分离、柜面流水与核心账务流水的边界 |
| 需求写"现金池按层级归集" | 不知道在说什么 | 知道是账户树 + 定时/定额上存下拨 + 池内计价，跑批密集 |
| 被问"支付、清算、结算有什么区别" | 三个词混着用 | 能给时间线：信息流先动、清算算差额、结算才改账户余额 |
| 一笔跨行转账超时了 | 直接重试 | 知道超时是**未知态**不是失败，先原交易查询、再冲正、必要时挂账 |
| 做账时余额只更新一个字段 | 觉得没问题 | 知道复式记账的不变式是"账不平就是 bug"，余额必须能与发生额勾对 |
| 配置里要填一个口令 | 直接写进 yml | 知道银行的"密钥不落代码库"红线与三员分立、堡垒机留痕 |
| 简历上的支付/对账项目 | 写成"接了个支付宝" | 能翻译成"渠道流水一致性、单边账检测、幂等分层、T+1 对账" |

一句话：**通用能力决定你能不能进面，业务与安全认知决定你能不能过面、以及入职第一年会不会踩红线。**

## 五、速查表（面试前 10 分钟看这一页）

### 支付 / 清算 / 结算（一句话版）

| 环节 | 动的是什么 | 典型系统 | 谁负责 |
|---|---|---|---|
| 支付 | 客户的**请求**与指令 | 手机银行、网银、柜面、开放 API | 渠道系统 |
| 清算 | **信息流 + 差额计算**（谁该给谁多少） | 银联、网联、大小额、CIPS | 清算机构 / 人民银行 |
| 结算 | **资金真的动了**（清算账户余额变更） | 人民银行清算账户、备付金账户 | 央行 / 托管行 |

### 中国支付清算体系一览（记定位差异，别背时间）

| 系统 | 归谁运营 | 定位 | 清算方式 |
|---|---|---|---|
| 大额实时支付系统（HVPS） | 人民银行 | 金额大、时效高、跨行走这条 | 逐笔全额实时（RTGS） |
| 小额批量支付系统（BEPS） | 人民银行 | 代发工资、缴费等小额批量 | 定时场次、轧差净额（DNS） |
| 网上支付跨行清算系统（IBPS） | 人民银行 | 7×24 互联网跨行小额 | 实时、净额 |
| 银联 | 特许清算机构 | 银行卡跨行交易（含线下 POS） | 净额清算 |
| 网联 | 特许清算机构 | 第三方支付机构 ↔ 银行（断直连后） | 净额清算 |
| CIPS | 人民币跨境支付系统运营机构 | 人民币跨境清算结算 | 混合（全额为主） |
| SWIFT | 报文联行组织 | 提供**报文与标准**，不替你完成资金结算 | — |

### 高频术语（一句话人话版）

| 术语 | 人话 |
|---|---|
| 日切 | 把系统营业日期从 T 推进到 T+1 的动作，期间部分交易要停 |
| 头寸 | 某个账户（或在央行）此刻能动用的钱够不够 |
| 轧差 | 多方应收应付互相抵扣，只结算差额 |
| 二清 | 没有牌照的机构先收钱再分钱（资金二次清算），违规 |
| 冲正 | 把一笔联机交易的效果原路抹掉，与"退款"不是一回事 |
| 单边账 | 一边记账成功、另一边没记（最常见的对账差错） |
| 长款 / 短款 | 我方账上多出的差额 / 我方账上少掉的差额 |
| 热点账户 | 大量并发同时更新同一个账户，行锁把 TPS 打死 |
| 积数计息 | 每天累加"余额×天数"，到结息日用累计积数×日利率 |
| 三员分立 | 系统管理员、安全管理员、审计管理员由不同人担任 |
| 断直连 | 支付机构不再直连银行，改经网联/银联处理 |
| 柜面 | 柜员操作的工作台，本身不记账，账务在核心 |
| 信创 | 芯片/OS/数据库/中间件的国产化替代 |

### 个人银行结算账户分类（最常考的硬知识）

| 类别 | 开立方式 | 能干什么（方向） |
|---|---|---|
| I 类 | 面对面核验（柜面/智能设备人工审核） | 全功能：存款、理财、支付、转账、存取现金、大额 |
| II 类 | 可远程开立，绑定 I 类账户核验 | 限额理财与支付消费，现金存取受约束 |
| III 类 | 可远程开立，验证强度最低 | 小额消费与缴费，余额上限最严 |

> 具体限额与功能边界以人民银行现行制度及各银行公告为准，面试答"方向 + 为什么越远程越严"比背数字更稳。

### 信息安全管理规范的四个层次

| 层次 | 内容 | 对你的约束强度 |
|---|---|---|
| 法律 | 网络安全法、数据安全法、个人信息保护法、密码法 | 红线（有个人责任） |
| 监管规章与指引 | 信息科技风险、外包风险、业务连续性、数据治理等 | 检查项（行内制度据此定） |
| 行业标准 | 等级保护（基本标准 `GB/T 22239`）、金融行业标准、密码行业标准 | 落地依据（等保测评、密评） |
| 行内制度 | 本行信息科技管理办法、开发规范、投产规程、红线清单 | **天天管着你的一层** |

### 金额与精度的三条铁律

| 铁律 | 做法 |
|---|---|
| 禁止二进制浮点存钱 | `BigDecimal`（用字符串构造）+ 数据库 `DECIMAL(18,2)` 或按"分"存整数 |
| 舍入必须显式 | 每个 `setScale` 都写清 `RoundingMode`，比较用 `compareTo` 不用 `equals` |
| 账必须能对平 | 借贷平衡校验、余额 = 上期余额 + 发生额，跑批后自动核对并告警 |

## 七、初学者常见的六个误区

| 误区 | 真相 |
|---|---|
| "银行开发就是写核心系统" | 核心系统只有少数人碰得到；大量岗位在渠道、现金管理、报送、风控、运维工具上。先看清 [01 篇的系统版图](./01-银行IT体系与岗位全景.md) |
| "业务是业务的事，我把代码写好就行" | 银行的"制度性约束"（授权、复核、留痕、上报）本身就是代码量的大头，不懂业务就估不准工作量（[08 篇](./08-反洗钱账户管理与监管合规.md) 有映射表） |
| "柜面系统就是银行核心" | 柜面是发起与操作台，账务在核心。把两者混了，面试一追就穿（[03 篇](./03-柜面系统与集中作业.md)） |
| "超时了就是失败，重试就行" | 联机交易超时是**未知态**。盲目重试会造成重复付款——这是资损事故（[09 篇第五节](./09-金融级一致性与对账实战.md)） |
| "银行技术很落后，去了学不到东西" | 落后的是部分平台，难的是并发下把账做对、变更不出事。分布式核心、单元化、两地三中心是另一种技术深度（[01](./01-银行IT体系与岗位全景.md)、[02](./02-核心系统与会计账务引擎.md)） |
| "安全合规是安全团队的事" | 数据分级、脱敏、防重放、密钥管理、生产数据不落地全是开发每天写的代码。踩了红线是个人与行内双重责任（[07 篇](./07-银行业信息安全管理规范.md)） |

## 八、学习方法建议

1. **先啃 02，再读其他**：借贷记账、科目、日切这三个概念立起来之后，柜面/清算/现金管理三篇里 80% 的名词会自动归位。读不懂 02 就回头读第 01 篇的版图。
2. **每个业务域都用同一套问句过一遍**：这笔交易信息流怎么走 → 谁记账 → 记成什么分录 → 超时了怎么办 → 怎么对账 → 监管要求留什么痕。六问答不出来，就是那篇没读透。
3. **把 JD 的四句话当成 exam syllabus**：[03](./03-柜面系统与集中作业.md)/[04](./04-支付清算体系与报文.md)+[05](./05-现金管理与资金头寸.md)/[06](./06-网络金融与电子渠道.md)/[07](./07-银行业信息安全管理规范.md) 各对应一句。每篇读完做一次"3 分钟口述"，说不清就重读。
4. **能力对照必须动手**：09 篇的练习（补借贷分录表、扩展 `compensate()` 做差错台账、写流水 diff）都能在本仓库真跑。做完你就有了一个"讲得清对账与幂等"的作品，比背概念有说服力。
5. **数字与条文不要硬背**：本模块刻意对限额、门槛、时限采取"描述方向 + 以现行版本为准"的写法——银行监管口径年年改，**面试官考的是你有没有正确的口径意识**，不是你能不能背出一个可能过期的数字。
6. **诚实是加分项**：零金融经验投银行岗，最好的策略是"用工程能力换业务入门速度"。[11 篇 F 组](./11-银行岗面试题库与简历映射.md) 给了具体话术，别把自己包装成做过银行系统。
