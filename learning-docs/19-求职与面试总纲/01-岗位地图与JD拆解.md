## 一、先选赛道：Java 后端的五种岗位形态

同样是"Java 后端"，日常工作和面试侧重完全不同。**先认清形态，再决定简历怎么写。**

| 形态 | 典型公司 | 日常在做什么 | 面试侧重 | 与本项目匹配度 |
|---|---|---|---|---|
| **A. 业务后端（电商/交易/支付）** | 阿里、美团、拼多多、有赞、SHEIN | 订单、库存、优惠、支付、履约 | 业务建模 + 一致性 + 高并发 | ★★★★★ 主线完全对口 |
| **B. 平台/基础架构（中间件、网关、框架）** | 字节、蚂蚁、腾讯、各公司技术中台 | 网关、RPC、消息、配置、可观测 | 原理深度 + 源码 + 自研能力 | ★★★★ 网关/限流/LB 可讲，但缺自研 RPC |
| **C. 数据/风控/营销** | 银行科技、消金、风控厂商 | 规则引擎、特征、报表、对账 | SQL + 数据链路 + 业务理解 | ★★★ 对账/CDC/OLAP 可迁移 |
| **D. AI 应用（Java + LLM）** | AI 创业公司、大厂 AI 平台、传统公司 AI 组 | RAG、Agent、Prompt 工程、模型接入 | AI 工程化 + 后端功底 | ★★★★ 稀缺组合，但岗位总量小 |
| **E. 交付/FDE/驻场** | 云厂商、SaaS、行业软件 | 客户现场部署、联调、排障 | 沟通 + 全栈 + 排障 | ★★★ 有 `docs/fde/` 与自检脚本，但成长性差 |

**结论（针对本仓库）**：

```text
主投：A（业务后端）+ D（AI 应用）        —— 你的项目正好是"交易 + AI"双主线
冲刺：B（平台/基础架构）                 —— 网关限流、最少连接 LB、幂等组件是抓手
兜底：E（交付/FDE）                      —— 有部署自检脚本和交付文档，但不建议长期
备选：C（数据/风控）                     —— 仅当你对 14-数据工程 模块有兴趣
```

> 不要五条线同时投。**简历只能有一个主角**，其余作为"加分项"出现在最后一行。

## 二、市场分层：不同公司到底考什么

| 层级 | 代表 | 一面 | 二面 | 三面 | 算法权重 | 对项目的期待 |
|---|---|---|---|---|---|---|
| **一线大厂** | 阿里/字节/腾讯/美团/拼多多 | 八股深挖 + 手撕中等题 | 项目深挖 + 场景设计 | 交叉面 + 软素质 | ★★★★★ | 有规模、有数据、有取舍 |
| **二线/中厂** | 有赞/携程/贝壳/货拉拉 | 八股 + 项目 | 项目 + 设计 | 技术负责人 | ★★★☆ | 能独立负责一个模块 |
| **中小厂/创业** | 各行业 SaaS、AI 创业 | 八股较浅 + 项目 | 项目 + 能不能马上干活 | 老板/CTO | ★★ | 全栈、能扛事 |
| **外包/驻场** | 中软国际、软通、法本 | 基础题 | 项目真实性 | 很少有三面 | ★ | 能干活、能出差 |
| **国企/银行科技子公司** | 工银科技、建信金科、城商行 | 基础 + 业务 | 项目 + 稳定性 | 合规/背景 | ★★ | 稳定、能写文档、懂规范 |

**关键差异**：

- 大厂考的是**"你为什么这么设计"**，中厂考的是**"你做过什么"**，中小厂考的是**"你能不能马上上手"**。
- 同一份简历，投大厂要突出"取舍与数据"，投中小厂要突出"独立交付与全栈"。
- **银行科技是另一套评价体系**（业务认知 + 合规 + 稳定性），见 [18 模块](../18-银行金融开发/README.md)，不要用互联网简历硬投。

## 三、面试四轮地图与精力分配

| 轮次 | 考察什么 | 占总分 | 你要准备的材料 | 本项目可用素材 |
|---|---|---|---|---|
| **一面**（同事面） | Java 基础、集合、并发、JVM、MySQL、Redis、框架使用 | **50%** | 八股速览表 + 项目 3 分钟版 | 01/02/03/04 模块 |
| **二面**（组长面） | 项目深挖、场景设计、排查思路 | **30%** | 项目 10 分钟版 + 3 个难点故事 | 幂等、状态机、支付对账、限流 |
| **三面**（总监/交叉面） | 系统设计、技术视野、软素质 | **15%** | 04 系统设计八题 + 07 话术 | 架构图、取舍理由 |
| **HR 面** | 稳定性、动机、薪资、文化匹配 | **5%** | 07 话术 + 薪资区间 | 职业规划 |

> **最重要的一条结论**：真正拉开差距的是**二面的"项目能不能讲三层"**。
> 一面决定你及格，二面决定你拿什么档位的 offer。

**"讲三层"是什么意思**：

```text
第一层（做过）：我们用了 Redis 分布式锁，用 Redisson 的 RLock。
第二层（懂原理）：Redisson 用 Hash 结构存重入次数，后台看门狗每 10s 续期到 30s，
                  所以业务执行时间超过锁过期时间也不会被别的线程抢锁。
第三层（有取舍/踩坑）：但看门狗只在"不指定 leaseTime"时生效，我们一开始传了 30s，
                  结果长事务把锁提前释放了，后来改成不传 leaseTime + 业务侧加超时兜底。
```

能讲三层，面试官会默认你"真的做过"；只讲第一层，会被归到"背过面试题"。

## 四、3 分钟读 JD：四步拆解法

### Step 1：硬门槛（30 秒，一票否决）

| 项 | 看什么 | 处理 |
|---|---|---|
| 学历/专业 | "本科及以上""计算机相关专业" | 不满足但差距小 → 仍可投（内推可破）；差距大 → 跳过 |
| 年限 | "3-5 年" | 差 1 年可投；差 2 年以上基本没戏（除非岗位写"能力优先"） |
| 地点/出差 | "能接受出差""驻场" | 直接影响生活质量，先确认 |
| 语言 | 外企要求英语口语 | 没准备就别浪费简历 |

### Step 2：技术栈关键词（1 分钟，判断匹配度）

把 JD 里的技术词分成三档，**只统计你达到 ★★ 以上的**：

| JD 措辞 | 真实含义 | 面试深度 |
|---|---|---|
| **精通** | 用过 3 年以上、读过源码、能讲取舍 | 会追问到实现细节和源码 |
| **熟悉** | 用过、知道原理、能独立排障 | 会问"为什么用它""出问题怎么查" |
| **了解** | 知道概念、看过文档 | 一般只问概念，答不上来不致命 |
| **有 X 经验优先** | 加分项，不是门槛 | 有就主动提，没有别硬编 |

### Step 3：业务域（1 分钟，决定故事怎么选）

JD 写"电商/交易/支付" → 讲订单、库存、支付、对账；
JD 写"内容/社区" → 讲 Feed、IM、搜索；
JD 写"AI/大模型" → 讲 RAG、Agent、成本治理；
JD 写"金融/银行" → 讲一致性、审计、合规（并参考 18 模块）。

### Step 4：隐藏信息（30 秒，判断坑）

| JD 措辞 | 可能的真实含义 |
|---|---|
| "抗压能力强""能适应快节奏" | 加班多 |
| "0-1 建设""从零搭建" | 没前人积累，什么都得自己干 |
| "全栈工程师""Java + 前端 + 运维" | 团队小，一个人干三个人的活 |
| "接受优秀应届生" | 预算低，或者岗位流动性大 |
| "长期驻场""客户现场" | 外包/交付岗 |
| "有股权/期权" | 现金给不到位 |

## 七、投递策略

### 7.1 两版简历

| 版本 | 主角 | 技术栈排序 | 适用 JD |
|---|---|---|---|
| **A. 业务后端版** | 交易链路（订单/支付/售后） | Java → Spring Cloud → MySQL/Redis/MQ → 幂等/状态机/对账 → （AI 一行） | 电商、支付、SaaS、金融科技 |
| **B. AI 应用版** | AI 客服（RAG/Agent） | Java → Spring AI → RAG 评测 → Agent 状态机 → Spring Cloud | AI 创业、大厂 AI 平台、传统公司 AI 组 |

两版共用同一批项目事实，只调顺序和详略。**不要一份简历投所有岗位。**

### 7.2 渠道优先级

```text
内推（最高） > 公司官网/招聘官网 > BOSS 直聘（打招呼要带 3 行亮点）> 猎头 > 招聘会 > 海投
```

### 7.3 节奏

| 阶段 | 动作 |
|---|---|

## 九、本项目的最优叙事（三段模板）

> 不是让你背稿，是让你**先有骨架，再填自己的细节**。数字部分留空，等压测/RAG 评测数据出来再填。

### 9.1 30 秒版（自我介绍里用）

```text
我做过一个 12 模块的 Spring Cloud 微服务项目，主线是 AI 智能客服 + 电商交易。
技术上我比较有把握的是三块：
第一，网关的分布式限流和最少连接负载均衡；
第二，交易链路的幂等、状态机和支付对账；
第三，基于 Spring AI 的 RAG 检索和 Agent 编排。
我这次想找的是（业务后端 / AI 应用）方向，能把这些能力用在真实业务上。
```

### 9.2 3 分钟版（一面项目介绍）

```text
背景：想做一个"能对话、能查知识库、能直接办业务"的客服系统，所以除了 AI 对话，
      还必须有商品、订单、支付、售后这些真实业务链路，否则 AI 只能聊天。
挑战：① 多服务下的一致性（下单要扣库存、支付要改订单状态）；
      ② AI 回答要可溯源、要能兜底（模型不可用时不能整个系统挂掉）；
      ③ 写操作不能让模型直接执行（售后申请必须用户确认）。
方案：① 交易侧用"本地事务 + 事务消息 + 补偿对账"保证最终一致，写操作加幂等键；
      ② AI 侧做 RAG（混合检索 + Rerank + 引用溯源），模型调用加超时/重试/熔断/降级；
      ③ Agent 侧用显式状态机 + 工具白名单 + 二次确认 + 人工转接。
结果：（待填：RAG 评测指标、压测 P95、转人工成功率）
```

### 9.3 10 分钟版（二面深挖）

```text
架构（1 分钟）→ 一条主链路（3 分钟，建议选"下单→支付→回调→对账"）
→ 一个难点（3 分钟，建议选"幂等 + 状态机 + 补偿"三件套）
→ 一个取舍（2 分钟，建议选"为什么用状态机不用 if-else"或"为什么消息最终一致而不是 Seata AT"）
→ 一个反思（1 分钟，建议选"如果重做，我会先做单体再拆"）
```

> **"反思"这一段是加分项**。能说出"哪里做过头了"的人，比只会吹的人可信得多。

## 十二、常见误区

| 误区 | 纠正 |
|---|---|
| "JD 要求 3 年，我只有 1 年，不敢投" | 年限是筛选项不是硬门槛，**内推可破**；先投，被拒不亏 |
| "技术栈没写全，简历会被刷" | 写上去的每个词都会被追问，**少写但写深**比多写但都浅强 |
| "项目是学习项目，不好意思讲" | 诚实讲"个人项目"不丢分，**编造生产数据**才丢分 |
| "八股背完就能过" | 一面靠八股，二面靠项目，**三面靠视野** |
| "先海投，面多了就会了" | 拿最想去的公司练手 = 浪费机会；先投 3 家练手公司 |
| "银行/国企技术落后，不去" | 银行科技子公司的稳定性与业务壁垒是另一条赛道，见 [18](../18-银行金融开发/README.md)，别用互联网标准评判 |
