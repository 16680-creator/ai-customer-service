# 06 - 项目刁钻追问 50 题

> **目标**：一面考"你会不会"，二面考"你是不是真做过"。这一篇专治**第二刀**。
> **前提**：[docs/00 架构图](../../docs/00-项目总览与架构图.md)、[01 岗位地图](01-岗位地图与JD拆解.md)、[04 系统设计八题](04-系统设计八题.md)。
> **纪律**：每题都给"**答法边界**"——哪些能说、哪些不能说、说不了怎么退。**不要背答案，要背边界。**

---

## 一、面试官为什么问刁钻问题

| 表面问题 | 真实意图 |
|---|---|
| "就这点数据为什么上微服务？" | 测你有没有**技术判断**，是不是照着教程搭 |
| "你的 QPS 多少？" | 测你说的"高并发"有没有**数据支撑** |
| "如果重做你会怎么改？" | 测你有没有**反思能力** |
| "这个是你做的吗？" | 测**真实性**（细节一问就露） |

**通用心法**：

1. 先承认边界（"这个项目是个人项目，规模不大"），再讲判断（"但我刻意练的是……"）。
2. 不会就说不会，然后给"如果要做我会怎么想"。
3. 每个回答都带一个**取舍**或**踩坑**，这是"真做过"的信号。

## 二、八类追问

### A. 规模与必要性（最容易被问倒）

| # | 追问 | 他在试探 | 答法边界 |
|---|---|---|---|
| 1 | 就这点数据，为什么上微服务？ | 是否过度设计 | **承认**："个人项目确实不需要 12 个服务，我是刻意练分布式能力。" 再给判断："真实业务在团队 > 20 人、领域边界清晰时才拆。" |
| 2 | 拆这么多服务，运维不累吗？ | 是否有成本意识 | 讲成本：部署复杂度、链路排障、数据一致性；再讲本项目的补偿（compose 一键起、check-local 自检、K8s 清单） |
| 3 | 单体能不能做？ | 是否理解演进 | 能。讲"单体优先，遇到瓶颈再拆"，并说清拆分触发条件（团队规模/发布频率/资源隔离） |
| 4 | 为什么 12 个而不是 3 个？ | 边界划分 | 按业务域拆（用户/商品/交易/支付/AI/消息），不是按技术层拆 |
| 5 | 服务之间怎么调用？为什么不用 RPC？ | 技术选型 | Feign（HTTP）够用；RPC（Dubbo/gRPC）在极致性能/多语言时才必要；本项目服务少、调用链短 |
| 6 | 网关是不是瓶颈？ | 单点意识 | 是无状态集群，可水平扩；限流在网关是为了保护后端，不是网关自己扛不住 |

### B. 技术选型（"为什么不用 X"）

| # | 追问 | 他在试探 | 答法边界 |
|---|---|---|---|
| 7 | 为什么用 Seata，不用 TCC/本地消息表？ | 分布式事务理解 | AT 对业务侵入小；TCC 要写三个方法、幂等/悬挂要自己处理；本地消息表适合"只涉及一个本地库 + MQ"。**本项目支付链路就是本地消息表思路（事务消息）** |
| 8 | 为什么用 RocketMQ 不用 Kafka？ | MQ 选型 | RocketMQ 有事务消息、延迟消息、死信，贴合交易；Kafka 吞吐更高、生态好，适合日志/流。项目里做了**双栈抽象**（`aics.mq.type` 切换） |
| 9 | 为什么用 Chroma 不用 Milvus？ | 向量库选型 | 数据量小（知识库文档级）、部署轻；Milvus 适合亿级向量、需要独立集群。选型看**数据量/召回要求/运维成本** |
| 10 | 为什么自研 JWT 不用 OAuth2？ | 安全认知 | 内部系统、只有自家前端，JWT 两层（网关验签 + 服务信任头）够用；OAuth2 适合**第三方接入/开放平台** |
| 11 | 为什么用 Redis 限流不用 Sentinel？ | 限流层次 | 两个都用：网关做**边缘限流**（保护后端），Sentinel 做**应用内限流**（保护自身）。不是二选一 |
| 12 | 为什么用 MyBatis-Plus 不用 JPA？ | ORM 选型 | 复杂查询/分页/SQL 可控性；JPA 适合领域模型简单、以对象为主的场景 |
| 13 | 为什么不用 Spring Cloud Gateway 自带的限流？ | 细节 | 用的就是它（`RedisRateLimiter`），另外自研了本地滑动窗口做 Redis 故障兜底 |

### C. 一致性与正确性（重灾区）

| # | 追问 | 他在试探 | 答法边界 |
|---|---|---|---|
| 14 | 下单怎么保证不超卖？ | 并发正确性 | DB 原子扣减（`stock >= n`）+ 失败抛异常让事务回滚；Redis 预扣只做前置，**最终以 DB 为准** |
| 15 | 重复下单怎么防？ | 幂等 | 用户维度 Redisson 锁（`waitTime=0` 快速失败）+ 幂等键；锁在事务外 |
| 16 | 支付回调重复怎么办？ | 幂等 | `confirmPay` 先查状态，已支付直接返回；状态机拒绝非法迁移 |
| 17 | 消息重复消费怎么办？ | 幂等 | 消费侧按业务键幂等（订单号 + 状态），不是靠 MQ 的"精确一次" |
| 18 | 支付成功但订单没改怎么办？ | 可靠性 | 三层：事务消息保证"流水落库 ⇒ 消息必达"；消费重试；`syncByQuery` 主动查单 + 对账补偿 |
| 19 | 事务消息真能保证不丢吗？ | 原理 | 半消息 → 本地事务 → commit/rollback → 回查。**能保证"本地事务成功则消息最终可达"**，不能保证"绝对不重复" |
| 20 | 分布式事务回滚了，但 MQ 消息已发？ | 边界 | 本项目注释里明确承认：MQ 不是 Seata 资源。兜底是消费侧幂等（查不到订单直接返回）；**有资金副作用的动作不能裸发**，要么事务消息，要么 AFTER_COMMIT |
| 21 | 缓存和 DB 怎么保证一致？ | 缓存一致性 | 先更新 DB 再删缓存 + 延迟双删 + 过期兜底；强一致就别缓存 |
| 22 | 你们的"最终一致"窗口多久？ | 可运维性 | 正常秒级（MQ 消费），异常靠对账 T+1；要监控"未终态订单"数量 |

### D. 性能与容量

| # | 追问 | 他在试探 | 答法边界 |
|---|---|---|---|
| 23 | 你的系统 QPS 多少？ | 数据真实性 | **没有实测就不编**："架构上按 5 QPS/用户限流设计，压测脚本已写，本机环境（无 Docker）还没跑出基线，所以我不给数字。" 见 [docs/27](../../docs/27-性能基线报告.md) |
| 24 | 瓶颈在哪？ | 定位能力 | 按链路说：网关（可扩）→ 应用（无状态）→ DB（写瓶颈）→ 外部 LLM（不可控）。写链路瓶颈在 MySQL 行锁与库存热点 |
| 25 | 怎么优化慢查询？ | SQL 能力 | `EXPLAIN` 看 type/key/rows/Extra；索引覆盖、避免函数、深分页改 `search_after`/游标 |
| 26 | 热点库存怎么扛？ | 高并发 | 库存分桶、请求排队（MQ）、本地缓存预筛、限购 |
| 27 | 连接池怎么配？ | 资源意识 | 每服务 Hikari 10；按 `(核心数 × 2 + 磁盘数)` 估，再看 DB `max_connections` 和实际等待 |
| 28 | 线程池怎么配？ | 并发 | CPU 密集 ≈ 核数+1；IO 密集按等待时间比；必须有界队列 + 拒绝策略 + 监控 |

### E. 安全与权限

| # | 追问 | 他在试探 | 答法边界 |
|---|---|---|---|
| 29 | 用户 A 能不能查用户 B 的订单？ | 越权 | `getOrderDetail(userId, orderNo)` 双条件查询，userId 来自网关透传而不是前端参数 |
| 30 | 网关怎么防伪造 X-User-Id？ | 信任边界 | 网关验 JWT 后**覆盖**该头；内网服务只信任网关。外部不能直连服务端口（K8s NetworkPolicy/安全组） |
| 31 | 文件上传有什么风险？ | 安全 | 白名单后缀 + 大小限制（5MB）+ 重命名 + 类型校验；不能只看后缀，要校验魔数 |
| 32 | Prompt 注入怎么防？ | AI 安全 | 输入安全检查（`SafetyGuardService`）+ 工具白名单 + 写操作二次确认 + 输出过滤 |
| 33 | 敏感信息怎么处理？ | 合规 | 日志脱敏（`PiiMasker`）、摘要化存储、密钥不进仓库（Nacos/环境变量） |

### F. 故障与运维

| # | 追问 | 他在试探 | 答法边界 |
|---|---|---|---|
| 34 | Redis 挂了系统还能用吗？ | 降级设计 | 限流切本地兜底；缓存降级读 DB（要限流保护）；锁失效要防止并发写——**优先保正确性，宁可拒绝** |
| 35 | MQ 挂了怎么办？ | 可用性 | 生产端本地重试 + 降级同步调用（牺牲性能）；消费端堆积告警 + 扩容 |
| 36 | 数据库主库挂了？ | 高可用 | 主从切换（MHA/Orchestrator），从库有延迟会丢数据；金融场景要评估 RPO |
| 37 | 服务发布怎么不丢请求？ | 发布 | 优雅停机（30s）+ 就绪探针 + 滚动更新 + 网关摘流 |
| 38 | 线上接口变慢怎么排查？ | 方法论 | 看监控（P99/错误率）→ 看链路（traceId）→ 看日志 → 看 DB/GC → 复现。顺序不能反 |
| 39 | 怎么发现服务挂了？ | 可观测 | 健康检查 + Prometheus 告警 + 日志关键字 + 业务指标（下单成功率） |

## 三、最狠的 10 题（详细答法）

### 3.1 "就这点数据为什么上微服务？"

```text
先承认：个人项目、没有真实流量，按业务规模确实不需要 12 个服务。
再讲动机：我刻意练的是"服务边界怎么划、跨服务一致性怎么保"，这是单体里练不到的。
再给判断：真实业务里，团队 < 10 人、领域边界不清时，单体 + 模块化更划算；
         拆分的触发条件是发布频率冲突、资源隔离需求、团队规模。
最后收：如果重做，我会先单体，把交易链路跑通，再按边界拆 3 个服务。
```

### 3.2 "你的 QPS 多少？"

```text
不编数字：目前没有实测基线。
给设计值：网关按用户 5 QPS/突发 10 限流；30 req/s 压测下理论放行 160/900。
给证据链：k6 脚本在 scripts/loadtest，报告在 docs/27，环境缺 Docker/k6 所以还没跑。
给下一步：环境就绪后 40 分钟能出基线。
```

> 这句"没有实测所以不给数字"本身就是加分项——多数候选人会编。

### 3.3 "支付回调丢了怎么办？"

```text
第一层：渠道回调失败会重试（指数退避）。
第二层：我们主动查单 syncByQuery，定时扫描"支付中"的流水。
第三层：对账补偿，渠道账单 vs 本地流水，处理单边和金额不一致。
另外：回调本身走事务消息，保证"流水落库 ⇒ 订单必达"。
```

### 3.4 "事务消息真能不丢？"

```text
它能保证：本地事务成功 ⇒ 消息最终被投递（半消息 + 回查）。
它不能保证：绝对不重复（消费端必须幂等）、消息顺序（除非用顺序消息）。
所以我们的答案是"至少一次 + 消费幂等"，不是"精确一次"。
```

### 3.5 "Redis 挂了限流怎么办？"

```text
限流依赖 Redis，这是已知单点。
兜底：切本地滑动窗口（RateLimitFilter，配置 enabled 可切回），
      单机配额不准但能挡住大部分流量；同时告警。
原则：宁可限得不准，也不能不限（不限 = 后端被打穿）。
```

### 3.6 "这个是你做的吗？"

```text
是个人项目，从 0 写到 12 个模块。可以随便挑一个点深问：
比如下单为什么锁在事务外、支付为什么用事务消息、Agent 为什么要状态机。
```

> 只要每个点都能讲三层，个人项目反而比"参与大项目但只拧螺丝"更有说服力。

### 3.7 "缓存和 DB 一致性怎么保证？"

```text
没有强一致，只有最终一致 + 过期兜底。
写：更新 DB → 删缓存（不是更新缓存），必要时延迟双删。
读：缓存 miss → 回源 → 回填。
兜底：TTL + 对账/重试；强一致场景直接读 DB，不加缓存。
```

### 3.8 "Agent 会不会乱操作？"

```text
会，所以做了四道闸：
① 状态机限定每一步能调哪些工具；
② 写操作必须二次确认（Token + 摘要 + 超时）；
③ 工具参数校验 + 权限校验；
④ 全链路轨迹审计，可回溯。
```

### 3.9 "如果重做你会怎么改？"

```text
① 先单体后拆：先把交易链路和 AI 链路跑通，再按边界拆。
② 测试先行：先补集成测试（事务/幂等），再堆功能——这次就是靠集成测试才发现事务失效。
③ 数据先行：先把压测基线跑出来，再谈"高并发"。
```

### 3.10 "你最大的不足是什么？"

```text
没有真实生产流量和故障演练，很多结论是"设计上成立"而不是"线上验证过"。
我能补的是：把能本地验证的都验证掉（集成测试、压测、故障注入），
不能验证的明确标注边界，不吹。
```

## 四、反问清单（面试最后 5 分钟）

| 问什么 | 为什么问 |
|---|---|
| 团队目前的技术栈和下一步演进方向？ | 看是否匹配、是否有成长 |
| 这个岗位最看重的能力是什么？ | 判断自己是否匹配，也为后续准备 |
| 团队的分工和 code review 流程？ | 看工程规范 |
| 新人上手一般多久？有没有导师？ | 看培养机制 |
| 团队最近遇到的最大技术挑战？ | 看技术密度（也给自己埋话题） |

**不要问**：加班多不多（换问"团队平时的发布节奏"）、工资多少（HR 面再谈）、公司会不会倒。

## 五、答不上来怎么办（诚实策略）

```text
1. 不硬编："这个我没做过/没深入，我按理解说一下思路，您看对不对。"
2. 给类比："类似的是我们项目里的 X，区别在于……"
3. 给学习路径："如果要做，我会先查 A，再验证 B。"
4. 收回到会的地方："这块我确实弱，但我对 Y 比较熟，可以展开。"
```

> 面试官能接受"不会"，不能接受"装会"。装会被追问两句就崩，而且会被记进评价。
