# 求职与面试总纲（19 模块）

> 本专题是 `learning-docs` 的**第十九个模块**，也是全库唯一一个"不教新技术、只教把已有技术卖出去"的模块。
> 前面 18 个模块回答"这个知识点是什么"，本模块只回答三个问题：**市场要什么 → 我有什么 → 怎么证明**。
>
> **主攻方向：Java 后端。** AI 能力（Spring AI / RAG / Agent）作为差异化加分项，不单独作为主赛道。
> 银行科技方向已有独立出口，见 [18-银行金融开发/11-银行岗面试题库与简历映射](../18-银行金融开发/11-银行岗面试题库与简历映射.md)，本模块不重复。

---

## 一、为什么需要这个模块

2026-10 对全库做了一次"文档覆盖 × 求职需求"比对，结论是**技术侧已经溢出，求职侧几乎空白**：

| 现状证据 | 说明 |
|---|---|
| 技术文档 242 篇 / 约 4.8 万行、19 个模块 | 覆盖 Java、Spring、DB、中间件、AI、前端、运维、测试、性能、稳定性、算法、计基、云原生、效能、银行 |
| 面试专练只有 **7 处** | 散在 [02/18](../02-Spring微服务/18-Spring面试专练与追问链.md)、[03/10](../03-数据库与ORM/10-数据库面试专练.md)、[05/向量库 05](../05-AI集成/05-向量数据库/05-面试专练与追问链.md)、[05/面试题 10 篇](../05-AI集成/面试题/README.md)、[06/14](../06-前端开发/14-前端面试题精选.md)、[11/11](../11-数据结构与算法/11-高频面试题清单.md)、[18/11](../18-银行金融开发/11-银行岗面试题库与简历映射.md) |
| 没有**总索引** | 不知道该按什么顺序刷、哪些题重复、哪些模块根本没准备 |
| 通用 Java 后端岗的**简历材料为零** | 只有 18 模块的银行岗映射表 + `docs/fde/` 的 Case Study 框架 |
| **没有可量化数据** | 压测脚本已写但基线未跑（见 [00/05 缺口总账 B 类](../00-学习路线总览/05-技术缺口分析与补全计划.md)），简历写不出 QPS/P95 |
| 真实缺陷没有变成面试素材 | 自调用事务失效、`slave.cnf` 复制过滤漏库、`pay.sandbox` 死配置、K8s 清单缺口——都只写在文档脚注里 |

一句话：**缺的不是知识，是"知识 → 岗位语言"的翻译层。**

## 二、模块定位：三层漏斗

```text
第一层  市场要什么   →  01 岗位地图与 JD 拆解      （判断投不投、差多少）
第二层  我有什么     →  02 简历与项目包装           （把项目翻译成岗位语言）
                        03 八股总索引与刷题顺序     （把 7 处专练串成一条线）
                        05 手撕代码清单与 30 天计划 （面试硬通货）
第三层  怎么证明     →  04 系统设计八题             （设计题答题框架）
                        06 项目刁钻追问 50 题       （扛住第二刀）
                        07 面试流程与话术           （自我介绍/反问/谈薪）
                        08 面试复盘与投递管理       （把每次面试变成资产）
```

> 与全库写法一致：**每个结论都要能落回本仓库的文件**（给 `文件:行号`），
> 本项目不具备的能力显式标注 ❌ / ⚠️，**不把个人学习项目包装成生产系统**。

## 五、三条使用路径

### 路径 A：30 天冲刺（已有 Java 基础，目标 1 个月内面试）

| 周 | 做什么 | 对应篇目 |
|---|---|---|
| 第 1 周 | 读 01，选 3 个真实 JD 做拆解，用自评表定位短板；同时刷 03 的高频表 | 01、03 |
| 第 2 周 | 写 02 的简历 + 项目一页纸；练 04 的系统设计框架（先做 3 题） | 02、04 |
| 第 3 周 | 05 手撕 20 题（每天 1~2 题）；06 刁钻追问对着镜子答一遍 | 05、06 |
| 第 4 周 | 07 话术 + 模拟面试；08 建立投递表，开始投递 | 07、08 |

### 路径 B：90 天系统补强（基础一般，先补技术再求职）

```text
第 1~4 周：Java 基础 + JVM + 并发（01-Java基础 8 篇）→ 补 09 面试专练（待写）
第 5~8 周：Spring 15~18 + MySQL 06/10 + Redis/RocketMQ/ES（04 模块）
第 9~11 周：12-性能工程 + 13-稳定性工程 + 16-云原生（把"做过"升级成"讲得深"）
第 12 周：回到本模块，走路径 A 的第 2~4 周
```

### 路径 C：面试前 72 小时（急救）

1. 读 01 的"面试四轮地图" + 自己的自评表；2. 过 03 速览表；3. 手撕 5 道最高频；4. 07 的自我介绍与反问清单；5. 06 的 10 道必答题。

## 六、写法纪律（三条，比内容更重要）

1. **不编造数据。** 没有实测的 QPS、用户量、可用性一个都不写。性能基线出来之前，简历只写机制与架构，不写数字（见 [docs/27-性能基线报告](../../docs/27-性能基线报告.md)）。
2. **每个 JD 词条必须能落回本仓库。** 01 的映射表里，凡是标注"★★★ 能讲到原理"的，都必须给出 `文件:行号`；给不出的降级为 ★ 并写进"补强动作"。
3. **区分"我做过"和"我知道"。** 做过 = 有代码/有测试/有踩坑记录；知道 = 只读过文档。简历与面试只把前者写成"做过"。

## 八、常见误区

| 误区 | 为什么错 | 正确做法 |
|---|---|---|
| 把"文档写了 4.8 万行"当能力证明 | 面试官不看你读了多少，只看你能讲多深 | 用"三层追问法"自测：每讲一个技术点，能否再答两层"为什么" |
| 背八股不讲项目 | 八股决定及格，项目决定档位 | 每道八股都准备一个"我们项目里对应的是……" |
| 简历堆满技术名词 | 写上去的每一个词都会被追问 | 只写能讲到 ★★ 以上的；★ 的词条宁可不写 |
| 只准备技术面 | 反问、谈薪、稳定性同样刷人 | 07 篇至少花 2 小时 |
| 一开始就海投 | 拿最想去的公司练手，浪费机会 | 先投 3 家"练手公司"，复盘后再投目标公司 |
