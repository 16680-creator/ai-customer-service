# 生产实践（20 模块）

> 本专题解决一个前 19 个模块没系统回答的问题：**这些东西在真实生产里到底怎么用、会怎么坏、坏了怎么办。**
>
> 前面模块讲"知识是什么"，本模块讲"**生产怎么打**"：
> 什么技术在真实公司里用、为什么选它、它有哪些坑、出了事怎么定位、面试官会怎么问。

---

## 一、为什么单开一个模块

2026-10 盘点了全库 248 篇文档，发现一个结构性缺口：

| 已有 | 缺 |
|---|---|
| 框架怎么用（Spring/MyBatis/Redis/MQ） | **同一类技术在什么场景下不该用** |
| 单个组件原理 | **多组件串起来后，线上出问题从哪查** |
| 性能/稳定性方法论（12/13 模块） | **具体命令与处置动作**（SOP 级） |
| 面试题散在 7 处 | **没有按"生产真实问题"组织的题库** |

## 二、AI 时代：该"了解"还是该"精通"？

你的判断**对了一半**，但需要拆开看：

```text
L1 知道它能干什么、什么时候用    → AI 可以帮你列，面试也够用（选型层）
L2 知道怎么配、怎么接、怎么调    → AI 能生成 80%，你能改就行（落地层）
L3 知道它怎么坏、为什么坏、怎么修 → AI 帮不上，这是人的价值（生产层）
```

**结论**：

- **广度（L1）要够**：知道有哪些选项，才能做对选型——这部分 AI 确实能加速。
- **深度（L3）不能省**：线上 CPU 100%、连接池耗尽、MQ 堆积时，AI 给的是"可能原因清单"，
  真正定位靠的是**你对栈、GC、锁、网络的理解**。
- **建议配比**：广度 60% / 深度 40%，深度只压三个点：
  ① JVM + 并发；② MySQL + Redis；③ 分布式一致性。

> 一句话：**AI 让"会用"贬值，让"会判断、会排障"升值。**

## 五、三条使用路径

### 路径 A：面试前（2 小时）

1. 读 [01](01-生产技术栈全景与选型.md) 的"选型表"和"生产细节 10 条"；
2. 读 [02](02-生产问题排查手册.md) 的"30 秒判断"栏；
3. 背 [19/03](../19-求职与面试总纲/03-面试高频问题与答法.md) 的答法骨架。

### 路径 B：项目要上生产（半天）

1. 按 [01](01-生产技术栈全景与选型.md) 第六节过一遍"上线前自检"；
2. 把 [02](02-生产问题排查手册.md) 的命令整理成自己的排查卡片；
3. 确认监控、告警、日志、回滚四件事就位。

### 路径 C：线上出事（立刻）

1. 打开 [02](02-生产问题排查手册.md)，按**现象**找对应章节；
2. 先止损（回滚/降级/限流），再定位；
3. 事后按 [13/06 RCA](../13-稳定性工程/06-RCA根因分析与复盘.md) 复盘。

## 六、写作纪律

1. **只写生产真会遇到的**：不写"理论上可能"的边角问题。
2. **每条问题给命令**：不能只说"看日志"，要给具体命令和判读标准。
3. **区分"现象"与"根因"**：同一现象可能有 5 个根因，按概率排序。
4. **标注版本差异**：JDK 8/17/21、MySQL 5.7/8.0、Spring Boot 2/3 的差异要写清。
5. **不编案例**：本仓库没有真实生产流量，案例要么来自 [docs/28](../../docs/28-故障案例库.md)，要么标注"通用模式"。
