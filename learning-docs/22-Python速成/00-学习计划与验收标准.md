# 00 · 学习计划与验收标准

> 原则：**每个学习单元必须有可执行、可验证的产出**。看懂了不算，跑通了才算。
> 每天 1~1.5 小时。下面两套计划按你的时间选一套。

## 四、每日学习闭环（15 分钟成本，收益最大）

```text
① 读 1 篇文档（30 min）
② 打开 python REPL / 写 code/ 下对应脚本，把文档里每个示例敲一遍（15 min）
③ 用自己的业务场景改写一个例子（10 min）   ← 这一步最关键
④ 记录 1 条"和 Java 不一样的地方"到自己的笔记（5 min）
```

第 ③ 步的例子：学到 `@dataclass`，不要抄书上的 `Point(x, y)`，而是写你自己的 `Order`、`PaymentRecord`。**用熟悉的问题练陌生的语法**，认知负荷都在语法上，效果最好。

## 六、时间不够时的最小路径

只有 3 小时：**读 02 篇 + 03 篇容器部分 + 13 篇速查表**，然后直接去看 `ai-cs-py-chat` 源码。遇到不懂的语法点回查对应篇。这是"以赛代练"路线，适合紧急上手改代码。

只有 1 天：7 天计划压成一天，D1-D4 上午，D5-D7 下午，晚上写练习。会累，但能到"能改代码"的状态。

## 七、常见自我怀疑与回答

| 疑问 | 回答 |
|---|---|
| "动态类型没安全感" | 类型注解 + mypy 能补回 90% 的检查，而且是在你要求的时候才检查，不是强制的 |
| "性能是不是很差" | 纯 Python 比 Java 慢 10~50 倍，但你的瓶颈几乎永远在数据库和网络。CPU 密集处用 numpy/多进程/或干脆写 Java |
| "要不要学完所有语法" | 不要。Python 有大量语法糖你一年都用不上（`__slots__`、元类、描述符）。先会用 20% 覆盖 95% 场景 |
| "看过就忘" | 正常。唯一解法是写代码。本目录的 14 篇题库就是为此设计的 |
