# 01 · 环境搭建与工具链

> 这一篇的作用：把 **Maven/Gradle 的思维**整体替换成 **venv + pip/uv** 的思维。
> 这是 Java 开发者最容易出错、也最容易忽视的一环——Python 的"依赖地狱"比 Java 更隐蔽，因为它没有 `mvn dependency:tree` 那样的默认约束。

---

## 一、先把对应关系摆出来

| 你熟悉的 | Python 世界的对应物 | 差异要点 |
|---|---|---|
| JDK（语言 + 虚拟机） | CPython 解释器 | 没有单独的 JVM，**解释器就是运行时** |
| `JAVA_HOME` | 不加环境变量也行，但 PATH 里要有 `python` | Windows 上容易装出多个版本互相打架 |
| Maven / Gradle | `pip` / `uv` / `poetry` | 没有"构建"概念，只有"安装依赖" |
| `pom.xml` | `pyproject.toml`（现代）/ `requirements.txt`（传统） | 前者是标准，后者是锁清单 |
| `~/.m2/repository` | `~/.cache/uv`、`~/.cache/pip` 或项目内 `.venv/Lib/site-packages` | 依赖默认**装进项目目录**，不是全局仓库 |
| `target/classes` | 无（字节码缓存是 `__pycache__/`，自动生成） | 不产生可分发产物，除非你打包成 wheel |
| JUnit | pytest | pytest 更简洁，断言就是 `assert` |
| `mvn test` | `pytest` / `uv run pytest` | 没有生命周期，直接调测试运行器 |
| `mvn package` | `uv build` → wheel/sdist | 只在要发布库时才需要 |
| `@SpringBootApplication` 启动 | `uvicorn app.main:app` | 启动命令在外部，不在代码里 |
| JVM 参数调优 | 环境变量 + uvicorn worker 参数 | 无 JVM，无 GC 调优 |

**最关键的一条**：Java 的依赖是"全局缓存 + 项目引用"；Python 的依赖是"**每个项目一个独立环境**"。搞混这一点会产生 80% 的"我这里能跑你那里不能跑"问题。

## 二、安装 Python

### Windows

```powershell
# 方式一：winget（推荐，本机已有 Python 3.12/3.13 说明装过）
winget install -e --id Python.Python.3.12

# 方式二：官网安装包 https://www.python.org/downloads/
#   安装时务必勾选 "Add python.exe to PATH"
```

验证：

```bash
python --version     # Python 3.12.x
py --version         # Windows 的版本选择器，py -3.12 可指定版本
```

> **坑**：Windows 上 `python` 可能是 Microsoft Store 的占位程序，敲进去跳应用商店。用 `where python` 确认路径，或改用 `py`。

### 多版本共存

```bash
py -3.12 --version
py -3.13 --version
py -3.12 -m venv .venv     # 用指定版本建环境
```

Java 里你会同时留 JDK 8/17/21，Python 同理。**项目间版本差异比 Java 更敏感**（3.8 之前没有海象运算符，3.10 之前没有 `match`，3.12 之前没有 PEP 695 泛型语法）。

## 三、虚拟环境：必须养成的肌肉记忆

### 为什么必须有

```text
不建 venv 的后果：
  项目 A 要 requests==2.25
  项目 B 要 requests==2.32
  → 全局 site-packages 只能装一个 → 一个项目必然坏掉
```

Java 里这个问题由 Maven 的隔离 classpath 解决了；Python 没有隔离，**必须靠 venv 手动隔离**。

### 标准流程（venv）

```bash
cd ai-cs-py-chat

# 创建（在项目根生成 .venv/ 目录，等同 JDK + 独立依赖目录）
python -m venv .venv

# 激活
source .venv/Scripts/activate      # Git Bash / Linux / macOS
# .venv\Scripts\activate           # cmd
# .venv\Scripts\Activate.ps1       # PowerShell

# 激活后提示符前会出现 (.venv)
(.venv) $ which python
/d/Projects/Persion/ai-customer-service/ai-cs-py-chat/.venv/Scripts/python

# 退出
deactivate
```

### uv（强烈推荐，现代替代品）

`uv` 用 Rust 写的，比 pip 快 10~100 倍，且自带依赖解析器和锁文件——**这是 Python 生态这些年最接近 Maven 体验的东西**。

```bash
# 安装 uv
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
# 或
pip install uv

# 创建环境 + 装依赖（一条命令，自动读 pyproject.toml）
uv sync

# 临时跑个脚本（自动管理环境，不污染）
uv run python script.py

# 加依赖（会自动写回 pyproject.toml 并更新 uv.lock）
uv add fastapi uvicorn

# 加开发依赖
uv add --dev pytest ruff mypy
```

对照表：

| Maven | uv |
|---|---|
| `mvn dependency:resolve` | `uv sync` |
| 手改 pom 加 `<dependency>` | `uv add xxx` |
| `pom.xml` | `pyproject.toml` |
| 无（Maven 无锁文件） | `uv.lock` |
| `mvn test` | `uv run pytest` |

## 四、`pyproject.toml`：现代 Python 项目的"pom.xml"

```toml
[project]
name = "ai-cs-py-chat"
version = "0.1.0"
description = "AI 对话服务（FastAPI + OpenAI 兼容协议）"
requires-python = ">=3.10"
dependencies = [
    "fastapi>=0.115",
    "uvicorn[standard]>=0.30",
    "openai>=1.50",
    "pydantic-settings>=2.4",
    "python-dotenv>=1.0",
]

[project.optional-dependencies]
dev = ["pytest>=8.0", "pytest-asyncio>=0.24", "httpx>=0.27", "ruff>=0.6", "mypy>=1.10"]

[tool.ruff]
line-length = 100
target-version = "py310"

[tool.pytest.ini_options]
asyncio_mode = "auto"
testpaths = ["tests"]
```

与 pom.xml 逐项对照：

| pom.xml | pyproject.toml |
|---|---|
| `<groupId>/<artifactId>/<version>` | `[project] name / version` |
| `<properties><java.version>` | `requires-python` |
| `<dependencies>` | `dependencies` |
| `<scope>test</scope>` | `[project.optional-dependencies].dev` |
| `<build><plugins>` 配置 | `[tool.xxx]` 段（各工具独立命名空间） |
| `<repositories>` | 一般不需要（PyPI 默认），私有源配 `[[tool.uv.index]]` |

### 传统 `requirements.txt`

```text
fastapi==0.115.0
uvicorn[standard]==0.30.6
openai==1.51.0
pydantic-settings==2.5.2
```

```bash
pip install -r requirements.txt
pip freeze > requirements.txt     # 导出当前环境（注意会带上无关包）
```

> 两者取舍：**新项目用 pyproject.toml**；`requirements.txt` 仍广泛存在于部署脚本和 Dockerfile 中，要能读。本项目 `ai-cs-py-chat` 用的就是 `requirements.txt`。

## 五、IDE 与工具配置

### VSCode（推荐，轻量）

必装扩展：

| 扩展 | 作用 | 对应 Java 世界 |
|---|---|---|
| Python (Microsoft) | 语言支持 + 调试 | Language Support for Java |
| Pylance | 类型检查 + 智能补全（基于 pyright） | 类似 Eclipse JDT 的语义分析 |
| Ruff | lint + format（一个顶 flake8+isort+black） | Checkstyle + Spotless |
| Python Debugger | `launch.json` 断点调试 | JDI |

`.vscode/settings.json`：

```json
{
  "python.defaultInterpreterPath": "${workspaceFolder}/.venv/Scripts/python.exe",
  "python.analysis.typeCheckingMode": "basic",
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff",
    "editor.formatOnSave": true,
    "editor.codeActionsOnSave": { "source.organizeImports": "explicit" }
  }
}
```

### PyCharm

- 便宜方案用 Community 版，够用（FastAPI 的 Endpoints 面板是 Professional 才有）
- `Settings → Project → Python Interpreter → Add Local Interpreter → Existing`，指向 `.venv/Scripts/python.exe`
- 快捷键可切到 IntelliJ 键位方案，零成本迁移

## 六、调试：从 `System.out.println` 到 `pdb`

### 最朴素的方式（Java 程序员最爱）

```python
print(f"debug: order={order!r}, type={type(order)}")   # f-string + !r 显示 repr
```

### 内置调试器 pdb

```python
def calc(a, b):
    breakpoint()        # 等价于 import pdb; pdb.set_trace()
    return a / b
```

常用命令（对照 jdb/IDEA）：

| pdb | IDEA 调试 |
|---|---|
| `n` (next) | Step Over |
| `s` (step) | Step Into |
| `r` (return) | Step Out |
| `c` (continue) | Resume |
| `p expr` | Evaluate Expression |
| `pp expr` | 美化输出 |
| `l` (list) | 看当前行上下文 |
| `w` (where) | 调用栈 |
| `q` (quit) | 终止 |

### 事后调试（Java 没有的爽点）

```bash
python -m pdb script.py       # 从头调试
python -m pdb -c continue script.py   # 崩溃后自动进入现场
```

### rich / icecream：比 print 好用

```python
from icecream import ic
ic(order)          # 自动带上变量名和值，输出到 stderr
```

## 七、REPL：Python 的杀手级学习工具

```bash
python            # 进入交互式解释器
```

```python
>>> 1 / 3
0.3333333333333333
>>> import json
>>> json.dumps({"b": 1, "a": 2}, ensure_ascii=False)
'{"b": 1, "a": 2}'
>>> help(json.dumps)          # 看文档
>>> dir(json)                 # 看有哪些函数
```

**学习建议**：本目录的每个代码片段，都先粘到 REPL 里跑一遍再复制进文件。这是 Python 学习效率最高的方式——没有编译等待，立刻看到结果。

更好的 REPL：

```bash
pip install ipython
ipython           # 语法高亮、自动补全、%timeit、!shell 命令
```

## 八、本项目 `ai-cs-py-chat` 的实际启动流程

```bash
cd D:/Projects/Persion/ai-customer-service/ai-cs-py-chat

# 项目自带一键脚本（Windows）
./scripts/run.ps1

# 手动等价操作
python -m venv .venv
source .venv/Scripts/activate
pip install -r requirements.txt
cp .env.example .env           # 然后编辑填 LLM_API_KEY
uvicorn app.main:app --reload --port 8000

# 验证
curl http://localhost:8000/api/health
# → {"status":"up"}
```

`uvicorn app.main:app` 这行的读法（**和 java -jar 完全不同**）：

```text
uvicorn          ASGI 服务器（相当于内嵌 Tomcat）
app.main         Python 模块路径 app/main.py
:app             模块里的变量名 app = FastAPI(...)
--reload         改代码自动重启（开发用，生产必须去掉）
```

> 对照：`java -jar app.jar` 是"运行一个自带容器的包"；`uvicorn app.main:app` 是"用外部服务器加载一个对象"。Python 没有"打包成可执行 jar"的默认路径。

## 九、环境踩坑速查

| 现象 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'fastapi'` | 没激活 venv，或装到了别的解释器 | `which python` 确认路径；`python -m pip install ...` |
| 装了包但 IDE 还是红线 | IDE 解释器指向全局 | 重新选 `.venv` 里的解释器 |
| `pip` 命令找不到 | 没建 venv 或 PATH 问题 | 用 `python -m pip` 永远安全 |
| PowerShell 禁止运行脚本 | 执行策略 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| 中文乱码 `UnicodeDecodeError: 'gbk'` | Windows 默认编码是 GBK | 读写一律显式 `encoding="utf-8"`（见 06 篇） |
| 全局装包污染 | 忘了 venv | 立刻删除重装；养成"先建 venv"的反射 |
| 多版本冲突 | 多个 Python 在 PATH | 用 `py -3.12` 或 uv 管理 |
