# 03 · 数据类型与容器

> 这一篇解决一个具体问题：**Java 的 `List/Map/Set` 那套经验，怎么迁移到 Python 的 `list/dict/set/tuple` 上。**
> 重点不是"有哪些方法"，而是三类容易出错的地方：**可变性、拷贝语义、哈希契约**。

---

## 一、四种容器的定位

| Python | Java 最近对应 | 有序 | 可变 | 可哈希（能当 dict 键） | 典型用途 |
|---|---|---|---|---|---|
| `list` | `ArrayList` | ✅ | ✅ | ❌ | 绝大多数有序数据 |
| `tuple` | 无（类似 `record` 的不可变部分） | ✅ | ❌ | ✅（元素都不可变时） | 固定结构、函数返回多值、dict 键 |
| `dict` | `LinkedHashMap` | ✅（3.7+ 保证插入序） | ✅ | ❌ | 键值映射 |
| `set` | `HashSet` | ❌ | ✅ | ❌ | 去重、成员判断 |
| `frozenset` | `Collections.unmodifiableSet` | ❌ | ❌ | ✅ | 需要当键的集合 |

```python
# ---- 本段讲：四种容器的字面量写法，先记"长相" ----
# 这段只是创建语法对照，不涉及行为差异；后面各节逐个展开。
# Java 对照：List/Map/Set 要 new + 泛型声明，Python 用括号字面量一步到位。
lst  = [1, 2, 3]          # 方括号 → list，对应 ArrayList：有序、可变、可重复
tup  = (1, 2, 3)          # 圆括号 → tuple，不可变；Java 没有等价物（近似 record 的只读快照）
dct  = {"a": 1, "b": 2}   # 花括号+冒号 → dict，对应 LinkedHashMap：3.7+ 保证插入顺序
st   = {1, 2, 3}          # 花括号+只有值 → set，对应 HashSet：去重、无序、成员判断 O(1)
fs   = frozenset({1, 2})  # 不可变集合 → 因此可哈希，能当 dict 键（Java 的 unmodifiableSet 不能）
```

> **注意**：`{}` 是空字典，不是空集合！空集合必须写 `set()`。这是新手高频错误。

```python
# ---- 本段讲：为什么空集合必须写 set() ----
# `{}` 在 Python 语法里被固定解释为"空字典"，因为字典字面量更常用，历史沿用至今。
# 这是 Java 程序员没有的心理负担：Java 里 new HashMap<>() 和 new HashSet<>() 一眼可分。
type({})        # <class 'dict'>，空花括号是字典，不是集合
type(set())     # <class 'set'>，空集合只能调内置构造函数 set() 创建
```

## 二、list：你的主力容器

### 创建与初始化

```python
# ---- 本段讲：list 的六种创建方式 + 二维列表「共享内层」陷阱 ----
# 创建方式本身很好懂：字面量、乘法复制、range 转换、字符串拆分、推导式。
# 真正要盯住的是后半段：`*` 复制的是「引用」，所以二维列表会三行共用同一个内层对象。
[]                          # 空列表；Java 写 new ArrayList<>()
[1, 2, 3]                   # 字面量；Java 没有等价的 List.of(1,2,3) 不可变语义，这里是可变列表
[0] * 5                     # [0,0,0,0,0]      Java 的 Arrays.fill；注意元素是同一个不可变 int，安全
list(range(5))              # [0,1,2,3,4]      range 是惰性序列，list 才真正物化（Java 的 IntStream.range）
list("abc")                 # ['a','b','c']    字符串可迭代 → 逐字符拆成列表
[x * 2 for x in range(3)]   # [0,2,4]          列表推导式，等价 Java 的 map + collect

# 二维列表：⚠️ 经典陷阱
bad = [[0] * 3] * 3         # ❌ 三行是同一个列表对象！外层 * 只是把同一个引用复制三份
bad[0][0] = 9               # 改第 0 行第 0 列，实际改的是那个被共享的内层列表
print(bad)                  # [[9,0,0],[9,0,0],[9,0,0]]  三行一起变，因为它们是同一个对象

good = [[0] * 3 for _ in range(3)]   # ✅ 每个内层独立：推导式每轮都重新求值 [0]*3，产生新对象
good[0][0] = 9                        # 这次只命中第 0 行自己的内层列表
print(good)                  # [[9,0,0],[0,0,0],[0,0,0]]  只有第一行变
```

### 常用方法（对照 Java）

| 操作 | Java | Python | 复杂度 |
|---|---|---|---|
| 追加 | `add(e)` | `append(e)` | 均摊 O(1) |
| 批量追加 | `addAll(c)` | `extend(c)` | O(k) |
| 插入 | `add(i, e)` | `insert(i, e)` | O(n) |
| 按索引取 | `get(i)` | `lst[i]` | O(1) |
| 按索引删 | `remove(i)` | `pop(i)` | O(n) |
| 删末尾 | — | `pop()` | O(1) |
| 按值删 | `remove(obj)` | `remove(v)`（不存在抛 ValueError） | O(n) |
| 查找下标 | `indexOf(o)` | `index(v)` | O(n) |
| 包含 | `contains(o)` | `v in lst` | O(n) |
| 长度 | `size()` | `len(lst)` | O(1) |
| 清空 | `clear()` | `clear()` | O(n) |
| 排序 | `Collections.sort` | `sort()` / `sorted()` | O(n log n) |
| 反转 | `Collections.reverse` | `reverse()` / `reversed()` | O(n) |
| 拷贝 | `new ArrayList<>(l)` | `l.copy()` / `l[:]` | O(n) |

```python
# ---- 本段讲：list 增删改查的 API，与 Java ArrayList 逐个对应 ----
# 关注两点：① Python 的方法名更短（append/pop 而非 add/remove）；
#          ② pop(0)/insert(0,·) 是 O(n)，头部操作多就换 deque（本文末尾有）。
fruits = ["apple", "banana"]              # 初始化；Java: new ArrayList<>(List.of("apple","banana"))
fruits.append("cherry")         # ['apple','banana','cherry']   尾部追加，等价 add(e)，均摊 O(1)
fruits.extend(["date", "elder"])# 批量：把可迭代对象逐个追加，等价 addAll(c)（注意不是 add 一个列表）
fruits.insert(0, "avocado")     # 头插：在下标 0 处挤入，后面元素整体后移，O(n)，等价 add(0,e)
last = fruits.pop()             # 弹末尾：删除并返回最后一个元素，O(1)；Java 要 list.remove(size-1)
first = fruits.pop(0)           # 弹头部（O(n)）：删除下标 0，Java 的 remove(0) 同样是 O(n)

fruits.remove("banana")         # 按值删：从左往右找第一个相等元素，找不到抛 ValueError（Java 的 remove(Object) 返回 boolean）
idx = fruits.index("cherry")    # 找下标：等价 indexOf，找不到抛 ValueError 而不是返回 -1

# 切片赋值（Java 没有，非常强）
nums = [0, 1, 2, 3, 4, 5]        # 原始 6 个元素
nums[1:3] = [10, 20, 30]        # [0,10,20,30,3,4,5]  长度可变：把下标 1~2 两格换成三个值，列表变长
del nums[0]                     # 删指定下标：del 是语句不是方法，等价 remove(0)
nums.clear()                    # 清空：等价 clear()，保留列表对象本身
```

### 排序的两种姿势

```python
# ---- 本段讲：sort() 原地排序 vs sorted() 返回新列表，以及 key 函数 ----
# 这是 Python 排序的全部心智模型：只提供一个 key 函数，把元素映射成"可比较的键"。
# Java 要写 Comparator 链，Python 用 lambda + 元组就能表达多字段。
# 原地排序（= Collections.sort）
nums = [3, 1, 2]         # 待排序列表
nums.sort()              # 原地排：直接改 nums 自身，返回 None（不返回新列表，别写 nums = nums.sort()）
print(nums)              # [1,2,3]

# 返回新列表（= Stream.sorted().collect()）
nums = [3, 1, 2]         # 重新初始化，方便对比
new = sorted(nums)       # 内置函数 sorted：接受任意可迭代，返回新 list，原列表不动
print(nums, new)         # [3,1,2] [1,2,3]   ← 原列表保持原顺序

# 自定义比较：key 函数（比 Java Comparator 简洁）
orders = [
    {"no": "A", "amount": 300},   # 每单是一个 dict，排序时按下标键取字段
    {"no": "B", "amount": 100},
    {"no": "C", "amount": 200},
]
orders.sort(key=lambda o: o["amount"])              # 按金额升序：key 把每条订单映射成数字再比较
orders.sort(key=lambda o: o["amount"], reverse=True) # reverse=True 表示降序，等价 Java 的 Comparator.reversed()

# 多字段排序：返回元组即可
orders.sort(key=lambda o: (o["amount"], o["no"]))   # 元组按字典序比较：先比 amount，相等再比 no

# 稳定排序 → Python 的 sort 是稳定的，可以分步排（先排次要字段，再排主要字段）
# 「稳定」= 键相同的元素保持原有相对顺序，等价 Java 的 Collections.sort（TimSort，也是稳定排序）
```

```java
// Java 等价
orders.sort(Comparator.comparingInt(o -> o.getAmount()).reversed());
```

### 切片（**Python 独有的高频能力**）

```python
# ---- 本段讲：切片 [start:stop:step] 的完整规则 ----
# 记一条公式：start 默认为 0，stop 默认到末尾，step 默认 1，区间永远左闭右开。
# 负下标从末尾倒数（-1 是最后一个）；step 为负时方向反转，start/stop 的默认值也随之互换。
# Java 没有切片，等价代码是 subList(from, to) 再 new ArrayList<>(...)，且 subList 是视图不是拷贝。
a = [0, 1, 2, 3, 4, 5]       # 6 个元素，下标 0~5（负下标 -6~-1）

a[1:4]      # [1,2,3]       左闭右开：含 1 不含 4
a[:3]       # [0,1,2]       start 省略 → 从 0 开始
a[3:]       # [3,4,5]       stop 省略 → 取到末尾
a[-2:]      # [4,5]         最后两个：-2 表示倒数第二个
a[:-2]      # [0,1,2,3]     去掉最后两个
a[::2]      # [0,2,4]       步长 2：每隔一个取一个
a[::-1]     # [5,4,3,2,1,0] 反转：step=-1 表示从右往左走
a[4:1:-1]   # [4,3,2]       反向切片：从 4 开始往左，到 1 停止（不含 1）

# 切片返回新列表（浅拷贝）
b = a[:]        # 全切片 = 浅拷贝，得到新的 list 对象；元素仍是共享引用
b[0] = 99       # 改 b 的第 0 格 → 只是让 b[0] 指向新 int，不影响 a
print(a[0])     # 0，不受影响

# 字符串、元组同样支持切片
"hello"[1:3]    # 'el'     str 不可变，切片必然返回新字符串
```

## 三、dict：用得比 list 还多

### 创建

```python
# ---- 本段讲：dict 的七种创建方式 ----
# 最常用的是字面量 {} 和 zip 合并；后者相当于 Java 里两个 List 手动配对再 put。
# 注意最后一行 fromkeys：所有键会共享同一个值对象，值是可变类型时是坑（07_quiz.py 有验证）。
{}                              # 空字典；Java: new LinkedHashMap<>()
{"a": 1, "b": 2}                # 字面量：键必须是可哈希对象（int/str/tuple 等）
dict(a=1, b=2)                  # 关键字构造：键只能是合法标识符字符串，这里得到 {'a':1,'b':2}
dict([("a", 1), ("b", 2)])      # 从「键值对组成的可迭代」构造，等价 Java 里遍历 entry 逐个 put
dict(zip(["a","b"], [1,2]))     # 两个列表合并 —— 高频；zip 把两个序列按位置拉成 (k,v) 对
{k: v for k, v in pairs}        # 推导式：pairs 需是 (键,值) 二元组序列，边遍历边建字典
dict.fromkeys(["a","b"], 0)     # {'a':0,'b':0}  批量建键，值是同一个 0（不可变所以安全）
```

### 取值：**永远优先用 `get`**

```python
# ---- 本段讲：dict 取值为什么必须优先用 get() ----
# 核心差异：Java 的 Map.get 取不到返回 null，Python 的 d[key] 取不到直接抛 KeyError。
# 所以「可能不存在」的键一律用 d.get(k, 默认值)，语义等于 Optional.orElse。
d = {"a": 1}                # 只有一个键的字典

d["a"]              # 1                下标语法取值，键必须存在
d["missing"]        # ❌ KeyError（不像 Java Map 返回 null）

d.get("missing")            # None     键不存在返回 None，不抛异常
d.get("missing", 0)         # 0         ← 等价 Optional.orElse；第二个参数就是兜底值

# 陷阱：or 做默认值时，0/""/False 也会被替换
d = {"count": 0}            # 键存在，值是 0
d.get("count") or 100       # ❌ 得到 100  ← or 判断的是「真值性」，0 被视为假，于是走了右边
d.get("count", 100)         # ✅ 得到 0    ← get 的默认值只在键缺失时生效，与值的真假无关
```

### 增删改

```python
# ---- 本段讲：dict 的增删改与合并（对照 Map.put/putAll/remove/merge） ----
# 重点：赋值即插入或覆盖，不需要 put；setdefault 是"取不到就插入并返回"的原子写法，
# 这正是 Java 里 computeIfAbsent 的用途，但 Python 写起来更短。
d = {}                            # 从空字典开始
d["a"] = 1                        # 键不存在 → 插入；等价 map.put("a", 1)
d["a"] = 2                  # 覆盖，不报错；等价再 put 一次
d.setdefault("b", [])       # 不存在才插入：键 "b" 缺失时写入 []，并返回这个 list
d.setdefault("b", []).append(1)     # 经典用法：分组。第二次调用拿到的是已存在的同一个 list，可直接 append
d.update({"c": 3, "d": 4})  # putAll：批量写入，重复键被参数里的值覆盖
del d["a"]                  # 删除，不存在抛 KeyError；等价 map.remove 但没有返回值
d.pop("a", None)            # 安全删除：返回被删的值；键不存在时返回第二个参数的默认值而不报错
d.clear()                         # 清空所有键值，对象本身保留

merged = d1 | d2            # 3.9+ 合并，右边覆盖左边；返回新字典，d1/d2 都不变（相当于 Map 的 merge 集合运算）
d1 |= d2                    # 原地合并：等价 d1.update(d2)，会修改 d1 自身
```

### 遍历

```python
# ---- 本段讲：三种遍历姿势 + 遍历中删除的正确写法 ----
# 直接 for k in d 拿到的是键（不是键值对），这点和 Java 的 for (K k : map.keySet()) 一致。
# 需要键和值时用 d.items()，它每次产出一个 (k, v) 元组，循环里自动解包，等价 entrySet()。
for k in d:                     # 键：等价 for (K k : map.keySet())
for v in d.values():            # 值：等价 for (V v : map.values())
for k, v in d.items():          # 键值对 ← 最常用；等价 for (Map.Entry<K,V> e : map.entrySet())

# 遍历时不能改大小（会 RuntimeError，等价 Java 的 ConcurrentModificationException）
for k in list(d.keys()):        # ✅ 先复制键列表：list(...) 生成快照，遍历的是快照而不是原字典
    del d[k]                    # 删原字典的键；因为遍历对象已换成快照，所以不会触发"大小改变"检测
```

### 分组（替代 `Collectors.groupingBy`）

```python
# ---- 本段讲：用 defaultdict 一次遍历完成"分组"和"分组求和" ----
# 普通 dict 每次都要先判断键在不在，defaultdict 把这一步内置：取缺失键时自动调用工厂函数建默认值。
# Java 对照：groupingBy 需要 Stream 收集器；这里一个 for 循环即可，且没有中间对象。
from collections import defaultdict    # defaultdict 是 dict 子类，行为只差"缺失键自动初始化"

orders = [
    {"type": "A", "amount": 100},   # 每单：分类 + 金额
    {"type": "B", "amount": 200},
    {"type": "A", "amount": 300},
]

grouped = defaultdict(list)   # 工厂是 list：访问缺失键时自动插入一个空 list 并返回它
for o in orders:              # 遍历每一条订单
    grouped[o["type"]].append(o)   # 不用判断键是否存在，第一次访问就得到 []，随后 append 原始订单

print(dict(grouped))          # 转成普通 dict 再打印，避免输出里出现 defaultdict(...) 前缀
# {'A': [{...100}, {...300}], 'B': [{...200}]}

# 一次遍历完成"求和分组"
totals = defaultdict(float)   # 工厂是 float：缺失键默认 0.0，可直接做加法
for o in orders:
    totals[o["type"]] += o["amount"]   # 等价 totals[t] = totals.get(t, 0) + amount，但省掉判断
print(dict(totals))      # {'A': 400.0, 'B': 200.0}
```

`defaultdict` 的价值：**不用先判断 key 是否存在**，省掉一层分支。这比 Java 里 `computeIfAbsent` 还顺手。

```java
// Java 等价
Map<String, List<Order>> grouped = orders.stream()
    .collect(Collectors.groupingBy(Order::getType));
```

## 四、set

```python
# ---- 本段讲：set 的创建、增删与集合运算 ----
# set 底层是哈希表，等价 Java 的 HashSet：元素唯一、无顺序、in 判断 O(1)。
# 集合运算符（| & - ^）Java 只能靠 addAll/retainAll/removeAll 手工做，Python 是语法级支持。
s = {1, 2, 3}           # 字面量：花括号里只写值；Java: new HashSet<>(Set.of(1,2,3))
s = set([1, 2, 3])      # 从可迭代构造：自动去重，等价 new HashSet<>(list)
s = set()               # 空集合（不能用 {}）——空花括号是 dict

s.add(4)                # 添加元素，等价 set.add；已存在则无操作，不报错
s.discard(4)            # 不存在不报错：安全删除，等价 set.remove 但不抛异常
s.remove(4)             # 不存在抛 KeyError：比 Java 的 remove 更严格（Java 只是返回 false）
4 in s                  # O(1)  ← 比 list 快得多；哈希定位，与元素个数无关

a = {1, 2, 3}           # 左操作数
b = {2, 3, 4}           # 右操作数
a | b       # 并集 {1,2,3,4}    等价 a.union(b) / Java addAll
a & b       # 交集 {2,3}        等价 a.intersection(b) / Java retainAll
a - b       # 差集 {1}          等价 a.difference(b) / Java removeAll
a ^ b       # 对称差 {1,4}      等价 (a|b) - (a&b)：只出现在一边的元素
a <= b      # 子集：a 的所有元素是否都在 b 中，等价 b.containsAll(a)
a |= b      # 原地并：等价 a.update(b)，会修改 a 自身

frozenset({1, 2})       # 不可变，可当 dict 键：因为不可变 → 哈希值稳定（可变 set 不可哈希）
```

**性能提醒**：`x in list` 是 O(n)，`x in set` 是 O(1)。要去重的场景，先把大数据转 `set` 再判断，否则数据量一大就是灾难。

```python
# ---- 本段讲：去重同时保留首次出现顺序 ----
# set 去重会丢顺序，而业务上常常要"按原顺序去重"，于是用「set 做判重 + list 做输出」。
# Java 的等价物是 LinkedHashSet：new ArrayList<>(new LinkedHashSet<>(data))。
# 列表去重且保留顺序（高频需求）
seen = set()        # 判重集合：只关心"见过没有"，不关心顺序，所以用 set 保证 O(1) 查询
result = []         # 输出列表：按首次出现顺序累积
for x in [3, 1, 3, 2, 1]:   # 原始序列里 3 和 1 都重复
    if x not in seen:       # 没见过才处理 → 天然的"保留第一次"
        seen.add(x)         # 打标记
        result.append(x)    # 放入结果，顺序即首次出现顺序
print(result)       # [3,1,2]

# 或者用 dict.fromkeys（3.7+ 保证顺序）
list(dict.fromkeys([3, 1, 3, 2, 1]))    # [3,1,2]  字典键唯一且保插入序，借用这个特性一行去重
```

## 五、tuple：不只是"不可变列表"

```python
# ---- 本段讲：tuple 的五个实际用途（不可变只是表象） ----
# tuple 常被误解成"只读 list"，它真正的价值是：可哈希（能当键）、可解包（一次赋多值）、轻量记录。
# Java 对照：不可变 List 但不能当 Map 键；多返回值要靠自定义类/数组；命名访问要靠 record。
t = (1, 2, 3)           # 三元组，长度固定
t[0]            # 1            按下标读，和 list 一样
t[0] = 9        # ❌ TypeError 元组不支持元素赋值（没有 __setitem__）

# 1. 函数返回多值（非常常见）
def divmod2(a, b):      # 同时算整除和取余，类似内置 divmod
    return a // b, a % b    # 逗号分隔 → 实际返回一个 tuple (商, 余数)

q, r = divmod2(7, 2)    # 解包：左边两个变量按位置接收元组，q=3 r=1（Java 需要自己造 DTO）

# 2. 单个元素的元组必须带逗号
not_tuple = (1)         # ❌ 这是 int：括号在这里只是分组符号，不是元组构造
real_tuple = (1,)       # ✅ 逗号才是元组的标志；空元组写 ()

# 3. 可当 dict 键 / set 元素
cache = {}              # 空字典当缓存
cache[(1, 2)] = "value" # 复合键：元组不可变 → 哈希稳定，可作键（list 不行，会 TypeError）

# 4. 具名元组（Java record 的表亲）
from typing import NamedTuple    # 标准库 typing 提供，本质是"带字段名的 tuple 子类"

class Point(NamedTuple):    # 定义结构：字段名 + 类型注解
    x: int                  # 字段按声明顺序占据元组的下标 0
    y: int                  # 下标 1

p = Point(1, 2)         # 构造实例，等价 record Point(int x, int y) 的 new Point(1,2)
print(p.x, p.y)         # 1 2   ← 命名访问：编译器/IDE 可提示，比 p[0] 可读
print(p[0])             # 1     ← 位置访问也行：因为底层仍是 tuple
x, y = p                # 可解包：等价 x=p.x; y=p.y
print(p._replace(x=10)) # Point(x=10, y=2)  不可变对象"改字段"的方式：返回新实例（类似 record 的 with）

# 5. 现代 Python 更常用 dataclass（见 05 篇）
```

## 六、推导式：把 Java Stream 甩在后面的地方

```python
# ---- 本段讲：推导式的四种形态（list / dict / set / 生成器） ----
# 统一模板：[表达式 for 变量 in 可迭代对象 if 条件]，返回什么类型由最外层括号决定：[] / {} / ()。
# 关键区别：if 在末尾是"过滤"（决定要不要这个元素），if-else 在开头是"表达式"（每个元素都要，二选一）。
# 映射
[x * 2 for x in range(5)]                     # [0,2,4,6,8]  逐个把 x 映射成 x*2
# Java: IntStream.range(0,5).map(x -> x*2).boxed().toList()

# 过滤
[x for x in range(10) if x % 2 == 0]          # [0,2,4,6,8]  尾部 if 决定元素是否保留，表达式原样输出

# 映射 + 过滤
[x * 2 for x in range(10) if x % 2 == 0]      # 先过滤偶数，再乘 2；顺序不能反（反了会先算再丢，浪费）

# 嵌套（等价 flatMap）
[x for row in [[1,2],[3,4]] for x in row]     # [1,2,3,4]  两层 for 从左到右书写，等价 flatMap
# Java: rows.stream().flatMap(List::stream).toList()

# 字典推导
{k: v for k, v in [("a", 1), ("b", 2)]}        # {'a':1,'b':2}  从二元组序列建字典
{v: k for k, v in d.items()}                   # 反转键值：要求 value 可哈希，否则报错
{k: len(k) for k in ["a", "bb"]}               # {'a':1, 'bb':2}  键来自原元素，值由表达式算出

# 集合推导
{x % 3 for x in range(10)}                     # {0,1,2}  自动去重，所以只剩三种余数

# 条件表达式（if-else 都写）
[x if x > 0 else 0 for x in [-1, 0, 1]]        # [0,0,1]  x>0 保留原值，否则替换为 0；每个元素都保留

# 生成器表达式：惰性，省内存（见 04 篇）
total = sum(x * x for x in range(1_000_000))   # 不建中间列表：sum 边取边加，内存恒定
```

### 可读性边界

推导式超过一层 for + 一个 if，就该改写成普通循环。**不要为了"一行"牺牲可读性**——这是 Python 社区明确反对的（PEP 8）。

```python
# ---- 本段讲：推导式的可读性边界——超过两层就改普通循环 ----
# 这两段逻辑完全等价：嵌套推导式里第二个 for 的 if 属于内层，位置感很差，容易读错。
# 拆成循环后，continue 相当于"过滤"，缩进直接表达了嵌套层级，维护成本低得多。
# ❌ 过度嵌套
result = [f(x, y) for x in xs if p(x) for y in ys if q(y) and r(x, y)]   # 语法合法，但条件归属需要反复推敲

# ✅ 拆开
result = []              # 累加器，显式初始化
for x in xs:             # 外层遍历
    if not p(x):         # 过滤外层：条件不满足直接跳过，等价推导式里的 if p(x)
        continue
    for y in ys:         # 内层遍历：对每个通过筛选的 x 再展开
        if q(y) and r(x, y):    # 内层双重条件，可读性一目了然
            result.append(f(x, y))   # 满足条件才产出
```

## 七、可变性与拷贝（**Java 程序员最容易翻车的地方**）

Java 里"对象赋值是引用复制"你很清楚；Python 一样，但更隐蔽——因为**连字符串/元组/列表都用同样的 `=`**。

### 变量名是标签，不是盒子

```python
# ---- 本段讲：赋值只是贴标签，浅拷贝才产生新列表 ----
# `b = a` 不做任何复制，只让 b 这个名字也指向同一个 list 对象（等价 Java 的 List b = a;）。
# 想让两个名字各自独立，必须显式拷贝：copy() / 切片 / list(...) 三种写法等价，都是浅拷贝。
a = [1, 2, 3]       # 创建一个 list 对象，a 指向它
b = a               # b 和 a 指向同一个列表（不复制！只是多了一个引用）
b.append(4)         # 通过 b 修改对象本身，a 看到的是同一个对象，所以也变
print(a)            # [1,2,3,4]  ← a 也变了

# 浅拷贝
c = a.copy()        # 写法一：list.copy()，新建一个 list，只复制第一层的元素引用
c = a[:]            # 写法二：全切片，效果与 copy() 完全相同
c = list(a)         # 写法三：用内置 list() 构造，把可迭代对象物化成新列表
c.append(99)        # 改的是 c 这个新对象，a 完全不受影响
print(a)            # [1,2,3,4]  不受影响（此后 c 被重新赋值两次，只保留最后一个 list(a) 的结果）
```

### 浅拷贝的边界

```python
# ---- 本段讲：浅拷贝只复制第一层，嵌套容器仍然共享 ----
# shallow 和 nested 是两个不同的外层 list，但 shallow[0] 和 nested[0] 是同一个内层 list。
# 所以改 shallow[0][0] 会"穿透"到 nested；deepcopy 会递归复制每一层，才是真正独立。
import copy     # deepcopy 在标准库 copy 模块里，不是内置函数

nested = [[1, 2], [3, 4]]       # 二维列表：外层 list + 两个内层 list

shallow = nested.copy()         # 只复制外层：新建外层 list，两个元素仍指向原内层 list
shallow[0][0] = 99              # 先取 shallow[0]（共享的内层 list），再改它的第 0 格
print(nested)                   # [[99,2],[3,4]]  ❌ 内层被改了

deep = copy.deepcopy(nested)    # 完全独立：递归复制，每一层都是新对象
deep[0][0] = 77                 # 改的是副本里的内层 list
print(nested)                   # [[99,2],[3,4]]  ✅ 不受影响（注意 99 是上一步留下的）
```

**规则**：容器里装容器 → 需要 `deepcopy`。容器里只装不可变值（数字/字符串/元组）→ 浅拷贝够用。

### 函数参数是"传对象引用"

```python
# ---- 本段讲：默认参数陷阱 + 参数是"传引用" ----
# 两件事都源于同一个事实：Python 变量存的是对象引用，而 def 的默认值只求值一次。
# Java 没有默认参数、也没有可变默认值，所以这两个坑在 Java 里根本不存在，格外容易忽视。
def add_bad(item, lst=[]):      # ❌ 默认值只创建一次：这个 [] 绑定在函数对象上，所有调用共享
    lst.append(item)            # 每次都在同一个 list 上追加，于是跨调用累积
    return lst                  # 返回的也是这个共享对象

print(add_bad(1))    # [1]        第一次调用，空列表被追加 1
print(add_bad(2))    # [1, 2]   ← 不是 [2]！第二次复用了上次的 list

def add_good(item, lst=None):   # ✅ 标准写法：用不可变的 None 当哨兵
    if lst is None:             # 只有调用方没传时才新建，保证每次调用拿到干净列表
        lst = []
    lst.append(item)            # 之后逻辑一样
    return lst

# 传入可变对象会被改
def mutate(lst):                # 参数拿到的是引用副本，指向调用方的同一个 list
    lst.append(99)              # 通过引用改对象内容 → 调用方可见

data = [1]                      # 调用方自己的列表
mutate(data)                    # 传入引用
print(data)   # [1, 99]  ← Java 也是这样，但 Java 里你会警惕，Python 里容易忘
```

> 详见 [04 篇](04-函数与作用域.md) 的"默认参数陷阱"。

## 八、哈希契约：`__eq__` 与 `__hash__`

把对象放进 `set` 或做 `dict` 键时，Python 要求**可哈希**。这和 Java 的 `equals/hashCode` 契约完全一致，但默认行为不同：

```python
# ---- 本段讲：对象进 set / 当 dict 键，必须同时实现 __eq__ 和 __hash__ ----
# Java 的默认行为：equals 是身份比较、hashCode 是身份哈希，两者"配套"，放进 HashSet 不会崩。
# Python 的默认行为：__eq__ 是身份比较、__hash__ 是身份哈希，看起来一样；
# 但一旦你只重写 __eq__ 不重写 __hash__，Python 会把 __hash__ 置空 → 对象直接不可哈希。
class Order:
    def __init__(self, no):     # 构造方法，等价 Java 的构造函数（self 相当于 this）
        self.no = no            # 实例字段：不需要预先声明，赋值即创建（Java 要写 private String no;）

a = Order("A")                  # 第一个实例
b = Order("A")                  # 第二个实例，内容相同但是不同对象
print(a == b)               # False  ← 默认按身份比较（等价 Java 的 ==），没重写 __eq__ 就比 id
print(len({a, b}))          # 2      ← 两个都在：身份不同 → 哈希不同 → set 认为是两个元素

# 自定义类要实现值相等
class Order2:
    def __init__(self, no):
        self.no = no
    def __eq__(self, other):        # 定义"值相等"：等价 Java 重写 equals
        if not isinstance(other, Order2):   # 类型不同就没法比
            return NotImplemented           # 返回 NotImplemented 让 Python 尝试反向比较（比直接 False 更规范）
        return self.no == other.no          # 业务主键相同即视为相等
    def __hash__(self):             # 必须与 __eq__ 保持一致：等价 Java 重写 hashCode
        return hash(self.no)        # 用参与相等判断的字段算哈希，保证"相等则哈希相同"

print(Order2("A") == Order2("A"))       # True   值相等生效
print(len({Order2("A"), Order2("A")}))  # 1      哈希相同且相等 → set 去重

# 最省事：用 dataclass（自动生成 __eq__，frozen=True 还会生成 __hash__）
from dataclasses import dataclass   # 标准库装饰器，等价 Lombok 的 @Data/@Value

@dataclass(frozen=True)     # frozen=True → 字段只读，于是自动生成 __hash__（可哈希、可当键）
class Order3:
    no: str                 # 只声明字段名和类型，__init__/__eq__/__repr__ 全部自动生成

print(Order3("A") == Order3("A"))       # True   自动生成的 __eq__ 按字段逐个比较
print(len({Order3("A"), Order3("A")}))  # 1      自动生成的 __hash__ 按字段元组计算
```

> **坑**：定义了 `__eq__` 却没定义 `__hash__`，该类就变成不可哈希（Python 自动把 `__hash__` 置 None），扔进 set 会 `TypeError: unhashable type`。这比 Java 更"严格"——Java 是静默用身份哈希，导致 HashSet 行为诡异。

## 九、性能与复杂度速查

| 操作 | list | dict/set | 说明 |
|---|---|---|---|
| 按索引访问 | O(1) | — | |
| 按值查找 `in` | O(n) | O(1) | **能用 set 就别用 list 判断存在** |
| 头部插入 | O(n) | — | 需要队列用 `collections.deque` |
| 尾部追加 | O(1) 均摊 | O(1) 均摊 | |
| 删除任意位置 | O(n) | O(1) | |
| 排序 | O(n log n) | — | |

```python
# ---- 本段讲：需要当队列用时，用 deque 而不是 list ----
# list 是数组，头部插入/删除要整体搬移 O(n)；deque 是双向链表块结构，两端操作都是 O(1)。
# Java 对照：ArrayDeque / LinkedList，方法名 append/appendleft ↔ addLast/addFirst。
# 队列：别用 list.pop(0)
from collections import deque   # 标准库 collections 里的双端队列

q = deque([1, 2, 3])    # 从一个可迭代对象构造，初始 [1,2,3]
q.append(4)         # 右入：等价 addLast，队尾加 4 → [1,2,3,4]
q.appendleft(0)     # 左入：等价 addFirst，队头加 0 → [0,1,2,3,4]
q.pop()             # 右出：删除并返回队尾，O(1)
q.popleft()         # 左出 O(1)   ← list.pop(0) 是 O(n)，这是选用 deque 的核心理由
```

# ---- 本段讲：真实项目里的三种容器用法（Pydantic 模型 / 列表拼接 / dict 配置） ----

```python
# ---- 本段讲：可直接抄走的分组统计模板 ----
# 结构是「dict<分类, dict<指标, 数值>>」：外层用 defaultdict 免判空，内层用固定 schema 保证字段齐全。
# Java 对照：groupingBy + reducing，或自定义累加器；Python 这里靠一个 for 完成。
# 一个可以直接抄走的分组统计模板（业务代码高频）
from collections import defaultdict   # 缺失键自动创建默认值，省掉 if key not in acc

def summarize(records: list[dict]) -> dict[str, dict]:   # 入参是 dict 列表，返回二层 dict（注解仅提示，不校验）
    acc = defaultdict(lambda: {"count": 0, "total": 0.0})   # 工厂用 lambda：每个新分类都拿到一份全新的计数字典
    for r in records:            # 单趟遍历，同时完成分组、计数、求和
        slot = acc[r["category"]]    # 取该分类的累加槽；分类首次出现时自动建 {"count":0,"total":0.0}
        slot["count"] += 1           # 计数 +1
        slot["total"] += r["amount"] # 金额累加
    return dict(acc)            # 转普通 dict 返回，调用方拿到的是干净结构（不依赖 defaultdict 类型）
```
