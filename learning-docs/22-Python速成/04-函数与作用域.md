# 04 · 函数与作用域

> Java 里函数是"类的方法"，必须挂在类上；Python 里**函数是独立的一等对象**。
> 这一篇的所有内容（闭包、装饰器、生成器）都是从这个前提推出来的。理解了它，装饰器就一点都不玄。

---

## 一、函数是一等公民（Java 需要 lambda + 函数式接口才能模拟）

```python
def double(x):
    return x * 2

# 可以赋值给变量
f = double
print(f(3))          # 6

# 可以作为参数
def apply(fn, value):
    return fn(value)
print(apply(double, 5))      # 10

# 可以作为返回值
def make_multiplier(n):
    def inner(x):
        return x * n
    return inner

triple = make_multiplier(3)
print(triple(4))             # 12

# 可以放进容器
ops = {"double": double, "square": lambda x: x * x}
print(ops["square"](4))      # 16
```

```java
// Java 的等价写法：必须借助函数式接口
Function<Integer, Integer> double = x -> x * 2;
BiFunction<Function<Integer,Integer>, Integer, Integer> apply = (fn, v) -> fn.apply(v);
```

> **关键差异**：Java 的 lambda 只能"实现一个接口"，且无法在 lambda 里写多条语句（早期）、无法优雅地携带状态。Python 里函数就是对象，随便传随便存。

## 二、参数体系的全部花样

```python
def f(a, b=2, *args, c, d=4, **kwargs):
    print(a, b, args, c, d, kwargs)

f(1, 3, 5, 6, c=7, e=8)
# a=1  b=3  args=(5,6)  c=7  d=4  kwargs={'e':8}
```

参数顺序规则（从左到右）：

```text
位置参数 → 默认参数 → *args → 仅关键字参数 → **kwargs
```

### 各类型详解

```python
# ① 位置参数：必须按顺序传
def add(a, b):
    return a + b

# ② 默认参数：有默认值，可省略
def greet(name, greeting="你好"):
    return f"{greeting}，{name}"

# ③ *args：收集多余的位置参数成元组
def sum_all(*nums):
    return sum(nums)

sum_all(1, 2, 3)        # 6
nums = [1, 2, 3]
sum_all(*nums)          # 6      ← 解包（= 展开运算符）

# ④ 仅关键字参数：* 之后的必须用关键字传（防止位置传参导致的错位）
def transfer(from_acct, to_acct, *, amount, currency="CNY"):
    ...

transfer("A", "B", amount=100)                  # ✅
# transfer("A", "B", 100)                       # ❌ TypeError

# ⑤ **kwargs：收集多余的关键字参数成字典
def build_config(**options):
    return options

build_config(host="localhost", port=8000)
# {'host': 'localhost', 'port': 8000}

cfg = {"host": "localhost", "port": 8000}
build_config(**cfg)     # 解包

# ⑥ 位置-only 参数（3.8+）：/ 之前的只能按位置传
def div(a, b, /):
    return a / b
div(6, 2)               # ✅
# div(a=6, b=2)         # ❌ TypeError
```

### 默认参数陷阱（**必考**）

```python
# ❌ 错误：默认值在函数定义时求值一次，之后所有调用共享同一个对象
def append_item(item, lst=[]):
    lst.append(item)
    return lst

print(append_item(1))    # [1]
print(append_item(2))    # [1, 2]   ← 不是 [2]！

# ✅ 正确：用 None 哨兵
def append_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst
```

原因：`def` 语句执行时，`[]` 被创建**一次**，绑定到函数对象的默认值元组上。所有调用共享它。

其他不可变默认值（`0`、`""`、`None`、`()`）没问题，因为不可变，改不了。

### 为什么 Java 没有这个问题

Java 没有默认参数（靠重载），所以从没暴露这个坑。**这是 Python 特有的认知盲区**，务必记住。

## 三、作用域：LEGB 规则

Python 查找变量名的顺序：

```text
L  Local       当前函数内
E  Enclosing   外层函数（闭包）
G  Global      模块级
B  Builtin     内置（len、print 等）
```

```python
x = "global"

def outer():
    x = "enclosing"

    def inner():
        # x = "local"
        print(x)        # 先找 local（无）→ enclosing "enclosing"

    inner()

outer()
```

### global / nonlocal：什么时候必须写

```python
counter = 0

def inc():
    global counter      # 不写这行，下面的赋值会创建局部变量
    counter += 1

inc()
print(counter)          # 1
```

```python
def outer():
    count = 0

    def inc():
        nonlocal count      # 修改外层函数的变量
        count += 1
        return count

    return inc

c = outer()
print(c(), c())         # 1 2
```

> **实践建议**：`global` 基本不用（写多了是设计问题）。`nonlocal` 只在写闭包工厂时用，日常也很少。如果你发现自己频繁需要 `global`，说明该用类或参数传递了。

### 一个隐蔽的坑：函数内的名字是"编译期"确定的

```python
x = 10

def f():
    print(x)       # ❌ UnboundLocalError
    x = 20         # 这行让 x 在整个函数内成为局部变量

f()
```

Python 在编译函数时就扫描到 `x = 20`，于是 `x` 被判定为局部变量，`print(x)` 时它还没赋值 → 报错。Java 里类似代码是**编译错误**（"variable might not have been initialized"），Python 却在运行时才炸。

## 四、闭包（Java 里靠 effectively final 勉强模拟）

```python
def make_counter():
    count = 0

    def inc():
        nonlocal count
        count += 1
        return count

    return inc

c1 = make_counter()
c2 = make_counter()
print(c1(), c1(), c2())     # 1 2 1     ← 各自独立的状态
```

Java 里的限制：lambda 捕获的局部变量必须 effectively final，想改只能塞进 `AtomicInteger` 或数组。Python 的 `nonlocal` 直接解决。

### 循环变量延迟绑定（**经典坑**）

```python
# ❌ 全部返回 4
funcs = []
for i in range(3):
    funcs.append(lambda: i)
print([f() for f in funcs])      # [2, 2, 2]

# ✅ 用默认参数固定当前值
funcs = []
for i in range(3):
    funcs.append(lambda i=i: i)
print([f() for f in funcs])      # [0, 1, 2]

# ✅ 或者用闭包工厂
def make(i):
    return lambda: i

funcs = [make(i) for i in range(3)]
print([f() for f in funcs])      # [0, 1, 2]
```

原因：闭包捕获的是**变量本身**，不是值。循环结束后 `i` 是最后一个值，所有 lambda 都看到 2（`range(3)` 后 i=2）。

## 五、装饰器：本质就是"函数当参数 + 返回新函数"

### 先看不带语法糖的版本

```python
import time

def timer(fn):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = fn(*args, **kwargs)
        cost = time.perf_counter() - start
        print(f"{fn.__name__} 耗时 {cost:.4f}s")
        return result
    return wrapper

def slow_add(a, b):
    time.sleep(0.1)
    return a + b

slow_add = timer(slow_add)      # 手动包装
slow_add(1, 2)
# slow_add 耗时 0.1003s
# 3
```

### 语法糖版（`@` 只是省略了手动赋值）

```python
@timer
def slow_add(a, b):
    time.sleep(0.1)
    return a + b

slow_add(1, 2)      # 效果完全一样
```

### 完整正确写法（**必须加 `functools.wraps`**）

```python
import functools
import time

def timer(fn):
    @functools.wraps(fn)        # 保留原函数的 __name__ / __doc__ / 签名
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            cost = time.perf_counter() - start
            print(f"[{fn.__name__}] {cost*1000:.2f}ms")
    return wrapper

@timer
def fetch(url):
    """拉取远程数据"""
    return "data"

print(fetch.__name__)    # fetch   ← 没有 wraps 会变成 wrapper
print(fetch.__doc__)     # 拉取远程数据
```

> 为什么必须 `wraps`：不加的话，被装饰函数的元信息（名字、文档、签名）全被 `wrapper` 覆盖。pytest、FastAPI、logging 都依赖这些信息，会出各种诡异的 bug。

### 带参数的装饰器（多一层嵌套）

```python
def retry(max_attempts=3, delay=0.0, exceptions=(Exception,)):
    """失败重试装饰器 —— 思路与项目里的 Resilience4j @Retry 一致"""
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            last_exc = None
            for attempt in range(1, max_attempts + 1):
                try:
                    return fn(*args, **kwargs)
                except exceptions as e:
                    last_exc = e
                    print(f"第 {attempt} 次失败：{e}")
                    if attempt < max_attempts:
                        time.sleep(delay)
            raise last_exc
        return wrapper
    return decorator

@retry(max_attempts=3, delay=0.5, exceptions=(ConnectionError,))
def call_api():
    ...
```

```java
// Java 等价思路（Spring Retry / Resilience4j）
@Retryable(maxAttempts = 3, backoff = @Backoff(delay = 500))
public void callApi() { ... }
```

**读装饰器的口诀**：

```text
@A
@B
def f(): ...
```
等价于 `f = A(B(f))`，**从下往上**包装。调用时**从上往下**执行 `A` 的外层逻辑 → `B` 的外层逻辑 → `f` 本体 → `B` 的内层 → `A` 的内层。

### 标准库里的装饰器（你已经用过很多）

```python
from functools import lru_cache
import pytest

@lru_cache(maxsize=128)         # 缓存函数返回值（本项目 config.py 用这个做单例）
def expensive(n):
    ...

@pytest.fixture                 # 测试夹具
def client():
    ...

@staticmethod                   # 静态方法
@classmethod                    # 类方法
@property                       # 属性
```

## 六、生成器：省内存的惰性序列

### yield 是什么

```python
def count_up(n):
    i = 0
    while i < n:
        yield i          # 产出值，暂停在这里，下次从这里继续
        i += 1

for v in count_up(3):
    print(v)             # 0 1 2

g = count_up(3)
print(next(g))           # 0
print(next(g))           # 1
print(next(g))           # 2
# next(g)                # StopIteration
```

**核心区别**：普通函数 `return` 一次就结束；生成器 `yield` 产出一个值后**挂起**，保留全部局部状态。

### 为什么重要：内存

```python
# ❌ 建一个百万元素的列表，占几十 MB
def squares_list(n):
    return [i * i for i in range(n)]

# ✅ 一个都不建，边算边给
def squares_gen(n):
    return (i * i for i in range(n))   # 生成器表达式

import sys
print(sys.getsizeof(squares_list(1000)))    # 约 8856 字节
print(sys.getsizeof(squares_gen(1000)))     # 约 200 字节（与 n 无关）

# 生成器能处理"无限流"
def naturals():
    n = 0
    while True:
        yield n
        n += 1

import itertools
print(list(itertools.islice(naturals(), 5)))   # [0,1,2,3,4]
```

### 生成器的坑：只能遍历一次

```python
g = (x for x in range(3))
print(sum(g))       # 3
print(sum(g))       # 0    ← 已经耗尽，不会重置
```

需要多次遍历 → 用列表或重新创建。

### 实际案例：流式读取大文件

```python
def read_lines(path, encoding="utf-8"):
    with open(path, encoding=encoding) as f:
        for line in f:
            line = line.strip()
            if line:
                yield line

# 处理 10GB 文件，内存占用恒定
for line in read_lines("huge.log"):
    if "ERROR" in line:
        print(line)
```

这与本项目 `ai-cs-py-chat` 返回 SSE 流的思路一致（见 [11 篇](11-FastAPI实战-对着SpringBoot学.md)）：

```python
async def stream_reply():
    async for chunk in llm_stream():
        yield f"data: {chunk}\n\n"       # 逐块产出，不攒全量
```

## 七、lambda：只适合一行

```python
square = lambda x: x * x            # 相当于 def square(x): return x * x
add = lambda a, b: a + b

# 真正的用途：作为 key / 回调传给别的函数
sorted(orders, key=lambda o: o["amount"])
list(map(lambda x: x * 2, [1, 2, 3]))
list(filter(lambda x: x > 1, [1, 2, 3]))
```

**限制**：lambda 体内只能是单个表达式，不能有语句（不能 `if/else` 语句块、不能赋值、不能 `try`）。超过这个复杂度就写 `def`。

> 与 Java 的 lambda 对比：Java 的可以写多语句块 `x -> { ... }`，Python 的不行。所以 Python 里"复杂回调"都是 `def` + 具名函数。

```python
# 用 lambda 写条件表达式是允许的（因为是表达式不是语句）
label = lambda score: "及格" if score >= 60 else "不及格"
```

## 八、几个高频内置函数

```python
# map / filter / zip：能用推导式就别用它们
list(map(str, [1, 2, 3]))           # ['1','2','3']
list(filter(None, [0, 1, "", "a"])) # [1, 'a']    过滤掉假值
list(zip([1,2], ["a","b"]))         # [(1,'a'), (2,'b')]

# zip 建字典（高频）
dict(zip(["a","b"], [1,2]))         # {'a':1,'b':2}

# zip 转置矩阵
matrix = [[1,2,3],[4,5,6]]
list(zip(*matrix))                  # [(1,4), (2,5), (3,6)]

# any / all
any(x > 3 for x in [1, 2, 5])       # True    有一个满足
all(x > 0 for x in [1, 2, 5])       # True    全部满足
all(x > 3 for x in [1, 2, 5])       # False

# sorted 的高级用法
sorted(orders, key=lambda o: o["amount"], reverse=True)
sorted(words, key=len)                       # 按长度
sorted(words, key=str.lower)                 # 忽略大小写
sorted(records, key=itemgetter("dept", "name"))  # 多字段（比 lambda 快）

# enumerate 反向：不需要
# sum / min / max 支持 key
max(orders, key=lambda o: o["amount"])       # 返回整个元素，不是金额
sum(o["amount"] for o in orders)             # 求和

# 常用
abs(-3), round(3.567, 2), len([1,2])
```

```python
from operator import itemgetter, attrgetter

itemgetter("a", "b")({"a": 1, "b": 2})       # (1, 2)
attrgetter("name")(obj)                       # obj.name
```

## 九、递归与栈深度

```python
def factorial(n):
    return 1 if n <= 1 else n * factorial(n - 1)

print(factorial(5))      # 120
# factorial(2000)        # RecursionError: maximum recursion depth exceeded
```

Python 默认递归深度约 1000（`sys.getrecursionlimit()`），**且没有尾递归优化**。深度递归场景必须改写成迭代或显式栈：

```python
def factorial_iter(n):
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result

print(factorial_iter(2000) > 0)     # True，且 Python 大整数不会溢出
```

> Java 默认栈深度也在几千到几万之间（取决于栈大小），但 Java 程序员习惯用递归写树遍历；Python 里深度超过 1000 就会炸，这是个实际差异。

## 十、函数注解（类型提示，运行时不做检查）

```python
from typing import Callable

def process(
    items: list[dict],
    validator: Callable[[dict], bool] | None = None,
    *,
    strict: bool = False,
) -> tuple[list[dict], int]:
    ...

print(process.__annotations__)
# {'items': list[dict], 'validator': ..., 'strict': bool, 'return': tuple[...]}
```

注解**只是元数据**：Python 不会因为它做任何检查（除非你用 mypy/pydantic/FastAPI）。这与 Java 的编译期强制完全不同，详见 [09 篇](09-类型注解与工程化.md)。

```java
// Java：编译期就报错
public Tuple<List<Map<String,Object>>, Integer> process(List<Map<String,Object>> items, ...)
```
