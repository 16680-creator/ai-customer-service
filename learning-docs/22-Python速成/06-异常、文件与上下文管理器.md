# 06 · 异常、文件与上下文管理器

> 三件事放一篇，因为它们经常一起出现：`try` 里开文件、异常处理不当时文件句柄泄漏、编码错了抛 `UnicodeDecodeError`。
> **Windows 环境的编码问题**是本文重点之一——你在 Windows 上开发，这个坑踩一次会浪费半天。

---

## 一、异常体系对照

```text
Java                              Python
─────────────────────────────────────────────────────
Throwable                         BaseException
 ├── Error（OutOfMemoryError…）     ├── SystemExit / KeyboardInterrupt / GeneratorExit
 └── Exception                     └── Exception
      ├── RuntimeException               ├── ArithmeticError
      ├── IOException (checked)          ├── LookupError
      ├── SQLException (checked)         │    ├── IndexError
      └── 自定义                          │    └── KeyError
                                         ├── ValueError
                                         ├── TypeError
                                         ├── OSError（含 IOError）
                                         └── 自定义
```

| 概念 | Java | Python |
|---|---|---|
| 根 | `Throwable` | `BaseException` |
| 业务异常基类 | `Exception` | `Exception` |
| **checked exception** | 有（`IOException` 等必须处理或声明） | **完全没有** |
| `throws` 声明 | 必须 | 不需要，也不支持 |
| `finally` | 有 | 有 |
| try-with-resources | 有 | `with`（更通用） |
| 多异常捕获 | `catch (A \| B e)` | `except (A, B) as e` |
| 重新抛出 | `throw e;` | `raise` |
| 异常链 | `new X(msg, cause)` | `raise X(...) from e` |

### 最大的区别：**没有 checked exception**

```java
// Java：编译器逼你处理
public String read(String path) throws IOException {
    return Files.readString(Path.of(path));   // 必须声明
}
```

```python
# Python：随便抛，没人管
def read(path):
    return open(path).read()      # 可能抛 FileNotFoundError，但编译器不知道
```

**后果**：Python 的异常是**运行时契约**，README 和类型注解不会告诉你会抛什么。所以：

- 调第三方库前看一眼文档的 Raises 段
- 边界处（API 入口、任务入口、消息消费入口）必须兜底 `except Exception`
- 用 `raise ... from e` 保留原因，否则排查时看不到根因

## 二、try 的完整形态

```python
try:
    result = risky()
except ValueError as e:
    print(f"值错误：{e}")
except (KeyError, IndexError) as e:
    print(f"查找失败：{e}")
except Exception as e:
    print(f"未预期：{type(e).__name__}: {e}")
    raise                       # 重新抛出（保留原栈）
else:
    print("没有异常才执行")       # Java 没有
finally:
    print("无论如何都执行")
```

### `else` 子句的价值

```python
# ❌ 容易把"业务代码抛的异常"也 catch 掉
try:
    data = load()
    process(data)           # 这行抛的异常也会被下面的 except 捕获，误判为 load 失败
except OSError:
    print("加载失败")

# ✅ 用 else 分离
try:
    data = load()
except OSError:
    print("加载失败")
else:
    process(data)           # 只处理 load 的异常
```

### 异常链：`raise ... from`

```python
def load_config(path):
    try:
        return json.loads(Path(path).read_text(encoding="utf-8"))
    except (OSError, json.JSONDecodeError) as e:
        raise ConfigError(f"配置加载失败：{path}") from e   # 保留根因
```

输出会有两段栈：

```text
json.decoder.JSONDecodeError: Expecting value: line 1 column 1
The above exception was the direct cause of the following exception:
ConfigError: 配置加载失败：app.json
```

> 相当于 Java 的 `new ConfigException(msg, cause)`。**永远用 `from e`，不要用 `raise X(str(e))`**——后者丢栈。

### `raise X from None`：故意切断链

```python
try:
    int("abc")
except ValueError:
    raise BusinessError("参数非法") from None    # 不显示底层 ValueError
```

## 三、自定义异常：项目的正确做法

```python
# 1. 定义业务异常基类
class AppException(Exception):
    """所有业务异常的基类"""
    def __init__(self, code: str, message: str, *, detail: dict | None = None):
        super().__init__(message)
        self.code = code
        self.message = message
        self.detail = detail or {}

    def __str__(self):
        return f"[{self.code}] {self.message}"


# 2. 具体异常
class OrderNotFound(AppException):
    def __init__(self, order_no: str):
        super().__init__("ORDER_NOT_FOUND", f"订单不存在：{order_no}", detail={"order_no": order_no})

class InsufficientStock(AppException):
    def __init__(self, sku: str, required: int, available: int):
        super().__init__(
            "INSUFFICIENT_STOCK",
            f"库存不足：{sku} 需要 {required} 现有 {available}",
            detail={"sku": sku, "required": required, "available": available},
        )


# 3. 边界统一转换（FastAPI 里的异常处理器，见 11 篇）
try:
    do_business()
except AppException as e:
    return {"code": e.code, "message": e.message, "detail": e.detail}
```

### 对照项目的 Java 做法

```java
// 项目的 GlobalExceptionHandler
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(BusinessException.class)
    public Result handle(BusinessException e) {
        return Result.fail(e.getCode(), e.getMessage());
    }
}
```

Python 的 FastAPI 等价物：

```python
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

app = FastAPI()

@app.exception_handler(AppException)
async def handle_app_exception(request: Request, exc: AppException):
    return JSONResponse(
        status_code=200,          # 业务异常用 200 + code 表达（与 Java 侧一致）
        content={"code": exc.code, "message": exc.message, "detail": exc.detail},
    )
```

## 四、EAFP vs LBYL：两种编程哲学

| 缩写 | 全称 | 含义 | 对应 Java 习惯 |
|---|---|---|---|
| LBYL | Look Before You Leap | 先检查再操作 | `if (x != null)` |
| EAFP | Easier to Ask Forgiveness than Permission | 先做，出错再处理 | try-catch 兜底 |

**Python 社区推崇 EAFP**，因为检查和处理之间有竞态窗口：

```python
# LBYL：检查后文件可能被删（TOCTOU 竞态）
if Path(p).exists():
    content = Path(p).read_text()      # ❌ 这一步仍可能 FileNotFoundError

# EAFP：直接做
try:
    content = Path(p).read_text(encoding="utf-8")
except FileNotFoundError:
    content = ""
```

```python
# LBYL：字典检查
if "key" in d:
    v = d["key"]         # 两次哈希查找

# EAFP / Pythonic：一次
v = d.get("key")         # 或者 try: d["key"] except KeyError

# 类型转换
# ❌ 检查字符串是不是数字很麻烦
# ✅ 直接转，失败就处理
try:
    n = int(s)
except ValueError:
    n = 0
```

> **但在**以下场景仍应 LBYL：校验用户输入（要给明确错误信息）、幂等操作、代价高的异常。判断标准：**异常是否"预期内的常规分支"**。是 → EAFP；只是"非法输入" → 校验。

## 五、`with`：上下文管理器（Java 的 try-with-resources）

### 问题：不用 with 会怎样

```python
# ❌ 如果 write 抛异常，f 不会关闭
f = open("a.txt", "w")
f.write("x")
f.close()

# ✅ with 保证关闭（即使抛异常）
with open("a.txt", "w", encoding="utf-8") as f:
    f.write("x")
# 出了 with 块，f 自动 close()
```

`with` 能管的不只是文件——**任何实现了 `__enter__` / `__exit__` 的对象**都能用。这是 `try-with-resources` 的超集（Java 要求实现 `AutoCloseable`，Python 只要两个魔术方法，连继承都不需要）。

### 多资源

```python
with open("in.txt", encoding="utf-8") as src, \
     open("out.txt", "w", encoding="utf-8") as dst:
    for line in src:
        dst.write(line.upper())

# Python 3.10+ 可以用括号换行（更清晰）
with (
    open("in.txt", encoding="utf-8") as src,
    open("out.txt", "w", encoding="utf-8") as dst,
):
    ...
```

### 自己实现上下文管理器

```python
import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self                         # 返回值给 as 后面的变量

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.cost = time.perf_counter() - self.start
        print(f"耗时 {self.cost*1000:.2f}ms")
        return False                        # False = 不吞异常；True = 吞掉

with Timer():
    sum(range(1_000_000))
# 耗时 18.34ms
```

`__exit__` 的三个参数：

```text
exc_type  异常类（正常退出时为 None）
exc_val   异常实例
exc_tb    堆栈
```

**返回值决定是否吞异常**——这是最容易踩的坑：

```python
class Swallow:
    def __enter__(self): return self
    def __exit__(self, *args):
        return True          # ❌ 悄悄吞掉所有异常，调试时极其痛苦

with Swallow():
    raise ValueError("你看不到我")
print("继续执行")
```

### 用 `@contextmanager` 写更省事（生成器版）

```python
from contextlib import contextmanager

@contextmanager
def timer(label=""):
    start = time.perf_counter()
    try:
        yield                        # yield 之前 = __enter__，之后 = __exit__
    finally:
        print(f"[{label}] {time.perf_counter() - start:.4f}s")

with timer("计算"):
    sum(range(100_000))
```

**关键**：`yield` 必须放在 `try/finally` 里，否则异常发生时清理代码不执行。

### 实用模板：数据库事务

```python
@contextmanager
def transaction(conn):
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise               # 必须重新抛，别吞

with transaction(conn) as c:
    c.execute("INSERT ...")
```

## 六、文件读写：`pathlib` 优先

### 老写法 vs 新写法

```python
import os

# ❌ 老写法（字符串拼接路径，Windows 下坑多）
path = os.path.join("data", "sub", "a.txt")
content = open(path).read()

# ✅ 新写法（pathlib，跨平台）
from pathlib import Path

path = Path("data") / "sub" / "a.txt"     # 用 / 拼路径，自动处理分隔符
content = path.read_text(encoding="utf-8")
```

### `Path` 常用 API（对照 `java.nio.file.Path` + `Files`）

```python
from pathlib import Path

p = Path("D:/Projects/data/report.csv")

p.name              # 'report.csv'
p.stem              # 'report'
p.suffix            # '.csv'
p.parent            # Path('D:/Projects/data')
p.parents[0]        # 同上
p.parts             # ('D:', 'Projects', 'data', 'report.csv')

# 存在性 / 类型
p.exists()
p.is_file()
p.is_dir()

# 创建 / 删除
Path("a/b/c").mkdir(parents=True, exist_ok=True)    # 递归创建，已存在不报错
p.unlink(missing_ok=True)                            # 删文件
Path("dir").rmdir()                                  # 删空目录

# 读写（一行搞定）
p.read_text(encoding="utf-8")
p.write_text("内容", encoding="utf-8")
p.read_bytes()
p.write_bytes(b"...")

# 遍历
for f in Path(".").iterdir():           # 直接子项
    print(f)
for f in Path(".").rglob("*.py"):       # 递归匹配
    print(f)
for f in Path(".").glob("**/*.log"):    # 同上
    print(f)

# 信息
p.stat().st_size          # 字节数
p.stat().st_mtime         # 修改时间戳
from datetime import datetime
datetime.fromtimestamp(p.stat().st_mtime)

# 绝对路径 / 相对
p.resolve()
p.relative_to(Path("D:/Projects"))

# 改名 / 移动
p.rename(new_path)
```

### 大文件：必须逐行读

```python
# ❌ 一次读进内存，1GB 文件直接爆
lines = Path("huge.log").read_text(encoding="utf-8").splitlines()

# ✅ 逐行迭代，内存恒定
with open("huge.log", encoding="utf-8") as f:
    for line in f:
        process(line.rstrip("\n"))
```

### 模式说明

| 模式 | 含义 | 文件不存在 |
|---|---|---|
| `"r"` | 读（默认） | `FileNotFoundError` |
| `"w"` | 写（**清空**） | 创建 |
| `"a"` | 追加 | 创建 |
| `"x"` | 独占创建 | `FileExistsError`（安全写法） |
| `"r+"` | 读写 | 报错 |
| `"rb"` / `"wb"` | 二进制 | — |

> **`"w"` 会静默清空文件**。想"存在就报错"用 `"x"`，想"追加"用 `"a"`。这是生产事故高发点。

## 七、编码：**Windows 上的第一号坑**

### 问题现象

```python
# 在 Windows 上（系统默认编码 GBK）
Path("a.txt").write_text("中文")
# 然后读
Path("a.txt").read_text()
# UnicodeDecodeError: 'gbk' codec can't decode byte 0xad in position 3
```

或者在控制台 print 中文时报：

```text
UnicodeEncodeError: 'gbk' codec can't encode character '\u2014'
```

### 根因

```python
import locale, sys
print(locale.getpreferredencoding())     # Windows 上通常是 'cp936'（GBK）
print(sys.stdout.encoding)               # 也是 'cp936' / 'utf-8' 视终端而定
```

`open()` 不指定 `encoding` 时，用**系统默认编码**。Linux/macOS 是 UTF-8，Windows 是 GBK。所以同一份代码在 Linux 上跑得好好的，到 Windows 就炸。

**Java 的对照**：Java 的 `Files.readString(path)` 默认也是 UTF-8（JDK 18+），而 `FileReader` 早期版本用平台编码——同样的坑。但 Java 程序员被教育"永远指定 Charset"，Python 里这个教育不够普及。

### 正确做法（三条铁律）

```python
# ① 所有 open 都显式指定 encoding
with open("a.txt", encoding="utf-8") as f:
    ...

# ② pathlib 的读写方法也指定
Path("a.txt").read_text(encoding="utf-8")
Path("a.txt").write_text("中文", encoding="utf-8")

# ③ 处理不可信/历史文件时，用 errors 参数容错
Path("legacy.txt").read_text(encoding="utf-8", errors="replace")   # 坏字节变 �
# errors 可选值：'strict'(默认) 'ignore' 'replace' 'backslashreplace'
```

### 相关环境变量

```bash
# Windows 上开启 UTF-8 模式（3.7+）
set PYTHONUTF8=1

# 或者永久设置
setx PYTHONUTF8 1
```

更彻底的办法：Python 3.15 起 UTF-8 成为默认（PEP 686）。在那之前，**永远显式 `encoding="utf-8"`**。

### 其他编码坑

```python
# ① 子进程输出用系统编码
import subprocess
r = subprocess.run(["cmd", "/c", "echo 中文"], capture_output=True, text=True,
                   encoding="utf-8", errors="replace")   # 不指定会 UnicodeDecodeError

# ② json.dumps 默认转义中文成 \uXXXX
import json
print(json.dumps({"名": "中文"}))                        # {"\u540d": "\u4e2d\u6587"}
print(json.dumps({"名": "中文"}, ensure_ascii=False))    # {"名": "中文"}  ✅

# ③ CSV 用 utf-8-sig（Excel 才认）
import csv
with open("a.csv", "w", encoding="utf-8-sig", newline="") as f:
    csv.writer(f).writerows([["姓名", "金额"], ["张三", 100]])
```

> `utf-8-sig` 会写 BOM。**给 Excel 看的文件用 `utf-8-sig`，给程序读的文件用 `utf-8`**。用错了别人打开是乱码。

## 八、JSON：只用标准库就够

```python
import json

# 序列化
data = {"name": "张三", "amount": 100.5, "tags": ["a", "b"]}

json.dumps(data)                                    # → str
json.dumps(data, ensure_ascii=False, indent=2)      # 中文 + 美化
json.dumps(data, sort_keys=True)                    # 键排序（便于 diff）
json.dumps(data, default=str)                       # 遇到不可序列化对象时转 str

# 反序列化
obj = json.loads('{"a": 1}')
json.loads('{"a": 1}', parse_float=Decimal)         # 金额用 Decimal，避免浮点误差

# 文件
with open("a.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

with open("a.json", encoding="utf-8") as f:
    data = json.load(f)
```

### 常见异常

```python
try:
    json.loads("{bad json}")
except json.JSONDecodeError as e:
    print(e.msg, e.lineno, e.colno, e.pos)
```

### 与 Java Jackson 对照

| Jackson | Python json |
|---|---|
| `ObjectMapper.writeValueAsString` | `json.dumps` |
| `ObjectMapper.readValue` | `json.loads` |
| `@JsonProperty("xxx")` | 无（键名就是字段名，或自己组装 dict） |
| `@JsonIgnore` | 不放进 dict 即可 |
| `FAIL_ON_UNKNOWN_PROPERTIES` | 默认忽略未知键（更宽松） |
| `ObjectMapper` 单例 | 无需实例，模块函数 |

> **注意**：`json.loads` 对未知字段是**静默忽略**的，Java 的 Jackson 默认会报错。想严格校验用 pydantic。

## 九、`Decimal`：金额必须用它

```python
print(0.1 + 0.2)            # 0.30000000000000004   ← 浮点误差
print(0.1 + 0.2 == 0.3)     # False

from decimal import Decimal, ROUND_HALF_UP

a = Decimal("0.1")
b = Decimal("0.2")
print(a + b)                # 0.3        ✅

# 精确除法 + 舍入
total = Decimal("100") / Decimal("3")
print(total.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))    # 33.33

# 从 float 构造是陷阱
Decimal(0.1)                # Decimal('0.1000000000000000055511151231257827')
Decimal("0.1")              # Decimal('0.1')   ✅ 永远用字符串构造
```

```java
// Java 的对应
BigDecimal a = new BigDecimal("0.1");
a.add(new BigDecimal("0.2"));
```

> 项目里做订单、支付金额计算，**Python 必须用 `Decimal`**。这和 Java 用 `BigDecimal` 是同一个道理，但 Python 的 `float` 默认就是 Java 的 `double`，更容易忘记。

## 十、`assert`：只用于内部不变量，不用于校验入参

```python
def calc_ratio(a, b):
    assert b != 0, "除数不能为 0"      # ⚠️ 只在调试时生效
    return a / b
```

**关键**：`python -O script.py` 会**移除所有 assert**。所以：

- ❌ 不要用 `assert` 校验用户输入
- ❌ 不要用 `assert` 做权限检查
- ✅ 用它表达"这里不可能发生"的内部假设
- ✅ 用它写测试（pytest 的 `assert` 是特例，pytest 会重写字节码保留它）

## 十一、常见异常速查

| 异常 | 触发场景 | 常见修法 |
|---|---|---|
| `AttributeError` | 对象没有该属性/方法 | 检查拼写、`hasattr`、`getattr(obj, k, default)` |
| `TypeError` | 类型不对 / 参数个数不对 | 打印 `type(x)` |
| `ValueError` | 类型对但值非法（`int("abc")`） | 校验输入 |
| `KeyError` | dict 取不存在的键 | 用 `.get()` |
| `IndexError` | 列表越界 | 检查长度 / 用切片 |
| `NameError` | 变量未定义 | 作用域问题（见 04 篇） |
| `UnboundLocalError` | 函数内赋值导致局部化 | 用 `global/nonlocal` 或改名 |
| `ImportError` / `ModuleNotFoundError` | 包没装 / 路径不对 | 见 07 篇 |
| `FileNotFoundError` | 路径错 / 相对路径基准不是你想的 | 用 `Path.resolve()` 打印绝对路径 |
| `PermissionError` | 权限 / 文件被占用 | Windows 上常见：文件被 Excel 打开 |
| `UnicodeDecodeError` | 编码不匹配 | 显式 `encoding="utf-8"` |
| `RecursionError` | 递归过深 | 改迭代 |
| `RuntimeError` | 通用运行时错误（如 dict 遍历时改大小） | 复制一份再改 |
| `StopIteration` | 生成器耗尽 | 用 `for` 而非手动 `next` |
