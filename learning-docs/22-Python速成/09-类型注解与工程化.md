# 09 · 类型注解与工程化

> Java 的类型是**编译器强制**的；Python 的类型注解是**完全可选、运行时不检查**的元数据。
> 这句话决定了 Python 工程化的全部形态：类型检查靠外部工具（mypy/pyright），质量靠 lint + 测试 + CI 而不是编译器。

---

## 一、先破除一个误解

```python
def add(a: int, b: int) -> int:
    return a + b

print(add("hello", "world"))     # helloworld    ← 没报错！
```

注解**不会**阻止任何调用。它只是：

1. 给 IDE/类型检查器看的（Pylance、mypy）
2. 给框架看的（FastAPI 用它做校验和生成 OpenAPI；pydantic 用它做转换）
3. 给人看的（文档）

```python
print(add.__annotations__)
# {'a': <class 'int'>, 'b': <class 'int'>, 'return': <class 'int'>}
```

真正要在运行时校验，必须用 **pydantic** 或手写检查。

## 二、基础注解语法

```python
# 变量
name: str = "张三"
count: int = 0
ratio: float = 0.5
enabled: bool = True
items: list[str] = []           # 3.9+ 不用 from typing import List
mapping: dict[str, int] = {}
ids: set[int] = set()
point: tuple[float, float] = (0.0, 0.0)
point3: tuple[float, ...] = (0.0, 0.0, 0.0)    # 变长元组

# 函数
def greet(name: str, times: int = 1) -> str:
    return f"你好 {name}" * times

# 什么都不返回
def log(msg: str) -> None:
    print(msg)

# 类
class Order:
    order_no: str
    amount: float

    def __init__(self, order_no: str, amount: float) -> None:
        self.order_no = order_no
        self.amount = amount
```

> **3.9 之前**必须 `from typing import List, Dict` 并写 `List[str]`。现在全部小写内置即可。项目 `requires-python = ">=3.10"` 就意味着可以用新语法。

## 三、可空与联合类型

```python
# ❌ 老写法
from typing import Optional, Union
def find(id: int) -> Optional[str]: ...

# ✅ 3.10+ 新写法（推荐）
def find(id: int) -> str | None: ...

# 联合多类型
def parse(v: int | str | None) -> dict: ...

# 类型别名
UserId = int
JsonValue = dict[str, "JsonValue"] | list["JsonValue"] | str | int | float | bool | None
```

> `str | None` 与 `Optional[str]` 完全等价，后者只是前者的旧写法。项目里统一用一种，别混。

## 四、`Protocol`：结构化类型（替代 interface）

```python
from typing import Protocol

class SupportsClose(Protocol):
    def close(self) -> None: ...

class FileLike(Protocol):
    def read(self, n: int = -1) -> bytes: ...
    def write(self, data: bytes) -> int: ...

def flush_all(resources: list[SupportsClose]) -> None:
    for r in resources:
        r.close()

# 任何有 close() 的类都能传，不需要继承
class Conn:
    def close(self) -> None: ...

flush_all([Conn()])        # ✅ mypy 通过
```

这是 Python 版的 "duck typing + 静态检查"。与 Java 的 interface 相比：**不需要显式 implements**，好处是可以为第三方类"事后"定义接口。

## 五、`TypedDict` / `NamedTuple` / `dataclass`

```python
# ① TypedDict：给 dict 加结构（适合解析 JSON 后的中间数据）
from typing import TypedDict, NotRequired

class OrderDict(TypedDict):
    order_no: str
    amount: float
    remark: NotRequired[str]        # 可选键

o: OrderDict = {"order_no": "A", "amount": 1.0}
print(o["order_no"])                # IDE 能补全，mypy 能查错
# o["typo"]                         # mypy 报错，运行时不报

# ② NamedTuple：轻量不可变结构
from typing import NamedTuple

class Point(NamedTuple):
    x: float
    y: float

# ③ dataclass：首选（见 05 篇）
from dataclasses import dataclass

@dataclass(frozen=True)
class Money:
    amount: float
    currency: str = "CNY"
```

| 类型 | 何时用 |
|---|---|
| `TypedDict` | 数据结构就是 JSON（不需要方法，不需要转换） |
| `NamedTuple` | 需要元组特性（可解包、可当 dict 键）+ 少量字段 |
| `@dataclass` | 领域对象、内部传递（最常用） |
| pydantic `BaseModel` | 跨系统边界（HTTP/配置/消息），需要运行时校验 |

## 六、泛型

```python
from typing import TypeVar, Generic

T = TypeVar("T")

def first(items: list[T]) -> T | None:
    return items[0] if items else None

reveal = first([1, 2])          # mypy 推断为 int | None


class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T | None:
        return self._items.pop() if self._items else None

s: Stack[int] = Stack()
s.push(1)
```

```python
# 约束类型参数
Number = TypeVar("Number", int, float)            # 只能是这两者
def add(a: Number, b: Number) -> Number: ...

# 3.12+ 新语法（PEP 695）
# def first[T](items: list[T]) -> T | None: ...
# class Stack[T]: ...
```

> **实践建议**：业务代码里泛型用得很少（比 Java 少得多）。别为了"类型安全"把简单函数改成泛型——这是从 Java 带来的惯性，在 Python 里往往是过度设计。

## 七、`Callable` / `Iterable` / `Iterator`

```python
from typing import Callable, Iterable, Iterator, AsyncIterator, Awaitable
from collections.abc import Iterable as ABCIterable

# 回调
def apply(fn: Callable[[int, int], int], a: int, b: int) -> int:
    return fn(a, b)

apply(lambda x, y: x + y, 1, 2)

# 可迭代 / 迭代器（推荐用 collections.abc，更快）
def total(nums: Iterable[float]) -> float:
    return sum(nums)

def gen() -> Iterator[int]:
    yield 1

# 异步
async def agen() -> AsyncIterator[str]:
    yield "a"

async def run(task: Awaitable[None]) -> None:
    await task
```

> **`typing.Iterable` vs `collections.abc.Iterable`**：后者是标准库的实际基类，`isinstance` 检查也能用，推荐。前者已标记为 deprecated 别名。

## 八、`Literal` / `Final` / `ClassVar` / `overload`

```python
from typing import Literal, Final, ClassVar, overload

# 字面量类型：限定取值（等价 Java enum 的部分能力）
Mode = Literal["dev", "test", "prod"]

def connect(mode: Mode) -> None: ...
connect("dev")          # ✅
# connect("local")      # mypy 报错

# 常量
MAX_RETRY: Final = 3
# MAX_RETRY = 4         # mypy 报错

# 类变量（区别于实例变量）
class Config:
    version: ClassVar[str] = "1.0"

# 重载（仅类型层面，运行时只有最后一个实现生效）
@overload
def get(key: str) -> str: ...
@overload
def get(key: int) -> bytes: ...
def get(key):
    ...
```

`Literal` 在 FastAPI 里很实用——自动生成枚举型 OpenAPI schema。

## 九、类型检查工具

### mypy（老牌，最严格）

```bash
python -m pip install mypy
mypy app/
```

```ini
# pyproject.toml
[tool.mypy]
python_version = "3.10"
strict = true                    # 开启全部严格检查
warn_return_any = true
disallow_untyped_defs = true     # 每个函数必须有注解
ignore_missing_imports = true    # 没类型信息的库跳过
exclude = ["tests/"]
```

```python
# mypy 能抓到的问题
def f(x: int) -> str:
    return x                # error: Incompatible return value type (got "int", expected "str")

def g(lst: list[int]) -> None:
    lst.append("a")         # error: Argument 1 has incompatible type "str"; expected "int"
```

### pyright / Pylance（VSCode 内置，快）

```json
// .vscode/settings.json
{
  "python.analysis.typeCheckingMode": "strict",   // off | basic | strict
  "python.analysis.extraPaths": ["./app"]
}
```

`strict` 模式下和 mypy strict 接近，但速度更快。**VSCode 用户直接用 Pylance 就够，不用额外跑 mypy**。

### 渐进式策略（推荐）

不要一上来就 `strict = true`——存量代码会报几百个错。分三步：

```text
① 新代码必须带注解（团队约定 + CI 检查新文件）
② 关键模块（对外 API、核心领域）开启 strict
③ 存量代码逐步补，允许 # type: ignore
```

```python
# 局部忽略
result = legacy_call()  # type: ignore[no-untyped-call]
```

## 十、ruff：一个工具干 flake8 + isort + black + pylint 的活

```bash
python -m pip install ruff

ruff check .              # 检查
ruff check --fix .        # 自动修
ruff format .             # 格式化（替代 black）
ruff format --check .     # CI 里检查是否已格式化
```

```toml
[tool.ruff]
line-length = 100
target-version = "py310"
exclude = [".venv", "__pycache__"]

[tool.ruff.lint]
select = [
    "E",    # pycodestyle errors
    "W",    # pycodestyle warnings
    "F",    # pyflakes
    "I",    # isort（导入排序）
    "N",    # pep8-naming
    "UP",   # pyupgrade（用新语法）
    "B",    # flake8-bugbear（常见 bug）
    "SIM",  # flake8-simplify
    "C4",   # flake8-comprehensions
    "RUF",  # ruff 自己的规则
]
ignore = ["E501"]           # 行长度交给 formatter

[tool.ruff.lint.per-file-ignores]
"tests/*" = ["S101"]        # 测试里允许 assert（如果启用了 bandit 规则）
```

### 工具对照表

| Java 生态 | Python 生态 |
|---|---|
| Checkstyle | ruff (`E`/`W`/`N` 规则) |
| SpotBugs / PMD | ruff (`B`/`SIM`)、pylint、bandit（安全） |
| Spotless / google-java-format | `ruff format` / black |
| 编译器类型检查 | mypy / pyright |
| Maven Enforcer | pre-commit hooks |

## 十一、pytest：测试怎么写

```python
# tests/test_order.py
import pytest
from app.order import Order, calculate_total


def test_simple():
    assert calculate_total([10, 20]) == 30


# 参数化（替代 JUnit @ParameterizedTest）
@pytest.mark.parametrize("items,expected", [
    ([], 0),
    ([10], 10),
    ([10, 20], 30),
    ([10, -5], 5),
])
def test_total_param(items, expected):
    assert calculate_total(items) == expected


# 异常断言
def test_invalid():
    with pytest.raises(ValueError, match="不能为负"):
        calculate_total([-1])


# fixture（替代 @BeforeEach）
@pytest.fixture
def order():
    return Order("A", 100.0)


def test_order_large(order):
    assert not order.is_large


# 临时目录
def test_write(tmp_path):
    p = tmp_path / "a.txt"
    p.write_text("x", encoding="utf-8")
    assert p.read_text(encoding="utf-8") == "x"


# 打标记
@pytest.mark.slow
def test_slow():
    ...


# mock（本项目测试全 mock LLM，不花钱）
from unittest.mock import patch, AsyncMock

def test_with_mock():
    with patch("app.core.llm.get_llm_client") as m:
        m.return_value.create.return_value = "mocked"
        ...
```

```bash
pytest                          # 跑全部
pytest tests/test_order.py::test_simple   # 跑单个
pytest -k "order and not slow"  # 按名字过滤
pytest -x                       # 遇到失败就停
pytest -v                       # 详细
pytest --lf                     # 只跑上次失败的
pytest --cov=app --cov-report=term-missing    # 覆盖率
```

### 本项目 `tests/test_chat_api.py` 的真实模式

```python
import pytest
from httpx import ASGITransport, AsyncClient
from app.main import create_app

@pytest.fixture
async def client():
    app = create_app()
    transport = ASGITransport(app=app)
    async with AsyncClient(transport=transport, base_url="http://test") as c:
        yield c

@pytest.mark.asyncio
async def test_health(client):
    r = await client.get("/api/health")
    assert r.status_code == 200
    assert r.json() == {"status": "up"}
```

关键点：

- `ASGITransport` 直接调 app，**不起真实端口**（比 Java 的 `@SpringBootTest(webEnvironment=RANDOM_PORT)` 更轻）
- LLM 调用被 monkeypatch/mock，测试不花钱、不依赖网络
- `pytest-asyncio` 的 `asyncio_mode = "auto"` 让 `async def test_*` 自动被识别

```yaml
      - id: end-of-file-fixer
      - id: trailing-whitespace
```

```bash
pre-commit run --all-files    # 手动全跑
```

对照 Java：这就是 `git commit` 前自动跑 Spotless + Checkstyle，避免 CI 才发现格式问题。

```text
mvn verify  →  ruff + mypy + pytest（三步分开，失败信息更清楚）
```

## 十四、注解的"投入产出比"

| 场景 | 是否值得写全注解 |
|---|---|
| 对外 API / 公共库 | 必须 |
| Web 服务的路由层、schema | 必须（FastAPI 依赖它工作） |
| 业务核心逻辑 | 强烈建议 |
| 一次性脚本 | 不必 |
| 复杂泛型工具代码 | 值得，但要注意别过度设计 |

**推荐起步策略**：给所有**函数签名**加注解（参数 + 返回值），内部变量能推断就省。这样投入最小、收益最大（IDE 补全 + 重构安全 + 文档）。
