# 09 · 类型注解与工程化

> Java 的类型是**编译器强制**的；Python 的类型注解是**完全可选、运行时不检查**的元数据。
> 这句话决定了 Python 工程化的全部形态：类型检查靠外部工具（mypy/pyright），质量靠 lint + 测试 + CI 而不是编译器。

---

## 一、先破除一个误解

```python
# ---- 本段讲：注解不参与运行时检查（这是 Python 类型系统的根本前提）----
# 下面这个调用在 Java 里编译不过，在 Python 里却正常运行并输出 helloworld。
# 理解这一点，才能理解后面为什么需要 mypy / pydantic 这些外部工具。
def add(a: int, b: int) -> int:
    # : int 是参数注解，-> int 是返回值注解；它们只是存进 __annotations__ 的元数据
    # Java 的 int 是编译器强制类型；Python 的 int 注解只是"文档 + 给工具看"
    return a + b           # 实际执行时不做任何类型转换或校验

print(add("hello", "world"))     # helloworld    ← 没报错！
# 字符串 + 字符串在 Python 里是拼接，所以得到 helloworld；
# 解释器完全无视了 "必须传 int" 的注解
```

注解**不会**阻止任何调用。它只是：

1. 给 IDE/类型检查器看的（Pylance、mypy）
2. 给框架看的（FastAPI 用它做校验和生成 OpenAPI；pydantic 用它做转换）
3. 给人看的（文档）

```python
# ---- 本段讲：注解在运行时确实存在，只是被存进 __annotations__ 字典 ----
# 这条输出说明"注解不是被丢弃的注释"，第三方工具/框架可以读到它 ——
# FastAPI / pydantic 正是靠读这个字典来做校验和生成 OpenAPI 的。
# Java 的注解同样能在运行时通过反射读取（@Retention(RUNTIME)），思路一致。
print(add.__annotations__)
# 函数对象的 __annotations__ 属性是 dict：参数名 → 类型对象，'return' 键存返回值类型
# {'a': <class 'int'>, 'b': <class 'int'>, 'return': <class 'int'>}
```

真正要在运行时校验，必须用 **pydantic** 或手写检查。

## 二、基础注解语法

```python
# ---- 本段讲：变量 / 函数 / 类三处的注解写法 ----
# 与 Java 的最大差别：注解可以只写不赋值（仅作声明），也不会强转类型。
# 下面的 list[str] / dict[str,int] 是 3.9+ 的内置泛型写法，不必再 from typing import List。
# 变量
name: str = "张三"                # 变量注解；等价 Java 的 String name = "张三"
count: int = 0                    # 对应 int count = 0
ratio: float = 0.5                # 对应 double ratio = 0.5（Python 只有 float，即双精度）
enabled: bool = True              # 对应 boolean enabled = true
items: list[str] = []           # 3.9+ 不用 from typing import List
# 对应 Java 的 List<String> items = new ArrayList<>()；[] 是空列表字面量
mapping: dict[str, int] = {}      # 对应 Map<String,Integer>；{} 是空字典字面量
ids: set[int] = set()             # 对应 Set<Integer>；set() 建空集合（{} 是空字典，不是空集合）
point: tuple[float, float] = (0.0, 0.0)        # 固定长度二元组；Java 没有内置元组
point3: tuple[float, ...] = (0.0, 0.0, 0.0)    # 变长元组
# 省略号 ... 表示"任意个 float"，不是占位符；这里注解的是"元素类型为 float 的任意长度元组"

# 函数
def greet(name: str, times: int = 1) -> str:
    # times 有默认值，调用时可省略；Java 需要用重载方法模拟默认参数
    return f"你好 {name}" * times
    # 字符串 * 整数 = 重复拼接；times=2 得到"你好 张三你好 张三"

# 什么都不返回
def log(msg: str) -> None:
    # -> None 对应 Java 的 void；Python 里所有函数都返回对象，None 就是"没有值"
    print(msg)

# 类
class Order:
    # 类体里只写"注解 + 不赋值"是合法的：这些是给类型检查器看的字段声明，
    # 运行时不会创建类属性（Java 里字段声明会真的分配存储）
    order_no: str
    amount: float

    def __init__(self, order_no: str, amount: float) -> None:
        # __init__ 是构造方法；第一个参数 self 相当于 Java 的 this，但必须显式写出
        # -> None 表示构造函数不返回值（Java 构造函数也没有返回类型，写法不同但语义一致）
        self.order_no = order_no       # 把参数存到实例属性；Python 不需要提前声明字段
        self.amount = amount
```

> **3.9 之前**必须 `from typing import List, Dict` 并写 `List[str]`。现在全部小写内置即可。项目 `requires-python = ">=3.10"` 就意味着可以用新语法。

## 三、可空与联合类型

```python
# ---- 本段讲：可空类型与联合类型的两种写法（新旧对照）----
# 注意这段是"对照示例"，前后定义了两次 find，实际代码里只保留一种写法。
# ❌ 老写法
from typing import Optional, Union
# Optional[T] 等价 T | None；Union[A,B] 等价 A | B。3.10 之后都不再需要
def find(id: int) -> Optional[str]: ...
# ... 是函数体占位符（Ellipsis），表示"实现省略"；等价 Java 接口里的抽象方法声明

# ✅ 3.10+ 新写法（推荐）
def find(id: int) -> str | None: ...
# str | None 用位或运算符表达联合类型；完全是 Optional[str] 的等价写法

# 联合多类型
def parse(v: int | str | None) -> dict: ...
# 表示参数可以是 int、str 或 None 三者之一；返回 dict（这里没写键值类型，等价 Map<Object,Object>）

# 类型别名
UserId = int
# 起个别名，让签名更有语义；运行时它就是一个普通变量，指向 int 这个类
JsonValue = dict[str, "JsonValue"] | list["JsonValue"] | str | int | float | bool | None
# 递归类型别名：JSON 可以是对象/数组/标量/None。
# 字符串 "JsonValue" 是前向引用（避免自己定义自己时报未定义），mypy 能解析它
```

> `str | None` 与 `Optional[str]` 完全等价，后者只是前者的旧写法。项目里统一用一种，别混。

## 四、`Protocol`：结构化类型（替代 interface）

```python
# ---- 本段讲：Protocol = 结构化类型（"长得像就算"），替代 Java 的 interface ----
# 关键差别：Java 必须显式 implements 才能赋值给接口类型；Protocol 只要方法签名匹配就行，
# 所以能给第三方库的类"事后"套一个接口，不需要改它的源码。
from typing import Protocol

class SupportsClose(Protocol):
    # 协议类只声明方法签名，不写实现；方法体用 ... 占位
    def close(self) -> None: ...
    # 意为"任何有 close() 方法的对象都满足本协议"，等价 Java 的 interface SupportsClose { void close(); }

class FileLike(Protocol):
    # 模拟文件对象协议：read / write 两个方法
    def read(self, n: int = -1) -> bytes: ...
    # n=-1 表示读全部；返回 bytes（字节串），Java 里对应 byte[]
    def write(self, data: bytes) -> int: ...
    # 返回写入的字节数，与 Java 的 OutputStream.write 语义一致

def flush_all(resources: list[SupportsClose]) -> None:
    # 参数声明为"SupportsClose 列表"，但运行时不检查，mypy 才检查
    for r in resources:
        r.close()          # 静态检查保证每个元素都有 close()，无需强转

# 任何有 close() 的类都能传，不需要继承
class Conn:
    # 注意：没有写 (SupportsClose)，即没有显式实现协议
    def close(self) -> None: ...

flush_all([Conn()])        # ✅ mypy 通过
# 因为 Conn 有匹配的 close() 签名，结构上满足协议；Java 里这样写编译不过，必须 implements
```

这是 Python 版的 "duck typing + 静态检查"。与 Java 的 interface 相比：**不需要显式 implements**，好处是可以为第三方类"事后"定义接口。

## 五、`TypedDict` / `NamedTuple` / `dataclass`

```python
# ---- 本段讲：三种"轻量数据结构"的选择：TypedDict / NamedTuple / dataclass ----
# 它们运行时行为差异很大，但在类型检查器眼里都能提供"字段名 + 字段类型"的约束。
# ① TypedDict：给 dict 加结构（适合解析 JSON 后的中间数据）
from typing import TypedDict, NotRequired
# TypedDict：本块演示"字典的形状"；NotRequired：3.11+ 标记可选键（早期用 total=False）

class OrderDict(TypedDict):
    # 只声明键名和值类型，运行时仍然是普通 dict，没有方法、没有实例
    order_no: str                  # 必填键，值必须是 str
    amount: float                  # 必填键，值必须是 float
    remark: NotRequired[str]        # 可选键
    # 标记为可选：可以没有这个键，但一旦有就必须是 str

o: OrderDict = {"order_no": "A", "amount": 1.0}
# 字面量仍然是 dict；注解只影响静态检查，不会创建类实例
print(o["order_no"])                # IDE 能补全，mypy 能查错
# o["typo"]                         # mypy 报错，运行时不报
# 这行被注释掉了：若取消注释，运行时会抛 KeyError —— 因为运行时没有任何键校验

# ② NamedTuple：轻量不可变结构
from typing import NamedTuple

class Point(NamedTuple):
    # 会自动生成 __init__ / __repr__ / 元组解包能力，且创建后不可修改
    x: float                       # 字段顺序即元组下标顺序
    y: float

# ③ dataclass：首选（见 05 篇）
from dataclasses import dataclass

@dataclass(frozen=True)
# 装饰器自动生成 __init__ / __repr__ / __eq__；frozen=True 表示不可变（类似 Java 的 record）
class Money:
    amount: float                  # 字段声明即构造参数
    currency: str = "CNY"          # 有默认值的字段必须排在无默认值字段之后
```

| 类型 | 何时用 |
|---|---|
| `TypedDict` | 数据结构就是 JSON（不需要方法，不需要转换） |
| `NamedTuple` | 需要元组特性（可解包、可当 dict 键）+ 少量字段 |
| `@dataclass` | 领域对象、内部传递（最常用） |
| pydantic `BaseModel` | 跨系统边界（HTTP/配置/消息），需要运行时校验 |

## 六、泛型

```python
# ---- 本段讲：TypeVar / Generic 与 Java 泛型 <T> 的对应 ----
# 这是本章泛型的核心：Java 用 <T> 声明类型参数，Python 用一个"占位类型" TypeVar 来模拟，
# 泛型类再显式继承 Generic[T]；目的与 Java 完全相同——让检查器把 T 绑定到调用/实例化时的具体类型。
from typing import TypeVar, Generic      # TypeVar=类型参数占位符；Generic=让类支持泛型（≈ Java 的 class Foo<T>）

T = TypeVar("T")                         # 声明类型变量 T；等价 Java 在方法/类上的 <T>，但在这里是一个真实对象

def first(items: list[T]) -> T | None:   # 等价 Java 的 static <T> T first(List<T> items)：T 由传入实参推断
    return items[0] if items else None   # 非空取首元素，空列表返回 None（Java 里通常返回 null 或抛异常）

reveal = first([1, 2])          # mypy 推断为 int | None
# ↑ 传入 list[int] 后 T 被绑定为 int，返回类型即 int | None；Java 编译器做的是同一套类型推断


class Stack(Generic[T]):                 # 等价 Java 的 class Stack<T>；Generic[T] 声明"本类使用了 T"
    def __init__(self) -> None:          # 构造方法，返回 None（≈ Java 构造函数，本就没有返回类型）
        self._items: list[T] = []        # 实例字段：等价 Java 的 List<T> items = new ArrayList<>()

    def push(self, item: T) -> None:     # 入栈，参数类型即 T；等价 Java 的 void push(T item)
        self._items.append(item)         # list.append ≈ ArrayList.add

    def pop(self) -> T | None:           # 出栈：空栈时返回 None，所以返回类型是 T | None（≈ Java 可能返回 null）
        return self._items.pop() if self._items else None   # 非空才 pop 并返回，否则返回 None

s: Stack[int] = Stack()                  # 声明 s 为 Stack[int]；等价 Java 的 Stack<Integer> s = new Stack<>()
s.push(1)                                # 传 1 合法；若传 "a"，mypy 会报错，而运行时不做任何检查
```

```python
# ---- 本段讲：给类型参数加约束，以及 3.12 的新泛型语法（以注释形式给出）----
# 约束（constraints）指"只能取指定几个类型之一"，与 Java 的 <T extends Number> 目的相同。
# 约束类型参数
Number = TypeVar("Number", int, float)            # 只能是这两者
# 传 str 时 mypy 会报错；注意约束是"枚举具体类型"，不同于 bound= 的"上界"
def add(a: Number, b: Number) -> Number: ...
# 两个参数必须是同一个具体类型（都 int 或都 float），返回同类型

# 3.12+ 新语法（PEP 695）
# def first[T](items: list[T]) -> T | None: ...
# class Stack[T]: ...
# 这两行是注释形式的新语法示例：把类型参数直接写在名字后面的方括号里，
# 更接近 Java 的写法，也不需要预先定义 TypeVar 变量
```

> **实践建议**：业务代码里泛型用得很少（比 Java 少得多）。别为了"类型安全"把简单函数改成泛型——这是从 Java 带来的惯性，在 Python 里往往是过度设计。

## 七、`Callable` / `Iterable` / `Iterator`

```python
# ---- 本段讲：函数类型、可迭代对象、生成器、异步版本的注解写法 ----
# Callable 对应 Java 的 Function/BiFunction；Iterable/Iterator 对应 Iterable/Iterator。
# 关键区分：Iterable 是"能遍历的"，Iterator 是"遍历游标"（有 __next__，只能走一遍）。
from typing import Callable, Iterable, Iterator, AsyncIterator, Awaitable
from collections.abc import Iterable as ABCIterable
# 同一名字导两次，后者起别名；实际项目里统一用 collections.abc 版本

# 回调
def apply(fn: Callable[[int, int], int], a: int, b: int) -> int:
    # Callable[[参数类型...], 返回类型]：前一个列表是参数，后一个是返回值
    # Java 对应：BiFunction<Integer, Integer, Integer>
    return fn(a, b)                 # 在 Python 里函数是一等公民，可以像值一样传参和调用

apply(lambda x, y: x + y, 1, 2)
# lambda 是匿名函数；这里传进去的就是 (x,y) -> x+y，结果是 3（返回值没被打印）

# 可迭代 / 迭代器（推荐用 collections.abc，更快）
def total(nums: Iterable[float]) -> float:
    # Iterable 表示"任何能 for 遍历的对象"：list / tuple / set / 生成器都行，比 list 更宽松
    return sum(nums)                # sum 内部就是遍历累加；等价 Java 的 stream().mapToDouble().sum()

def gen() -> Iterator[int]:
    # 含 yield 的函数是生成器函数：调用它返回生成器，惰性产出值
    yield 1                         # 每次 next() 产出一个 1，产出后暂停在此处
    # Java 对应：Iterator<Integer>，但要自己维护状态；生成器自动保存了执行位置

# 异步
async def agen() -> AsyncIterator[str]:
    # 异步生成器：既能 await 又能 yield，用于流式场景（如 SSE）
    yield "a"                       # 必须用 async for 消费

async def run(task: Awaitable[None]) -> None:
    # Awaitable 表示"可以被 await 的对象"，协程、Task、Future 都满足
    await task                      # 等它完成；这里不关心返回值（None）
```

> **`typing.Iterable` vs `collections.abc.Iterable`**：后者是标准库的实际基类，`isinstance` 检查也能用，推荐。前者已标记为 deprecated 别名。

## 八、`Literal` / `Final` / `ClassVar` / `overload`

```python
# ---- 本段讲：四个"让注解表达力更强"的工具 ----
# Literal 限定取值、Final 禁止重新赋值、ClassVar 标记类变量、overload 声明重载签名。
# 它们都只在静态检查期起作用，运行时不强制（除了 overload 的最后一个实现会被真正调用）。
from typing import Literal, Final, ClassVar, overload

# 字面量类型：限定取值（等价 Java enum 的部分能力）
Mode = Literal["dev", "test", "prod"]
# 值只能是这三个字符串之一；比 Enum 轻量，但不是真正的枚举类型（没有方法和身份）

def connect(mode: Mode) -> None: ...
# 参数注解为 Mode，mypy 会校验传入值是否在白名单里
connect("dev")          # ✅
# connect("local")      # mypy 报错
# 这行被注释：取消注释后 mypy 报错，但运行时不会 —— 注解永不参与运行时检查

# 常量
MAX_RETRY: Final = 3
# Final 表示"不许再赋值"；对应 Java 的 final 字段，但 Java 是编译器强制，Python 只有检查器管
# MAX_RETRY = 4         # mypy 报错

# 类变量（区别于实例变量）
class Config:
    version: ClassVar[str] = "1.0"
    # ClassVar 告诉检查器：这是类级别字段，不要在实例上赋值
    # Java 对应：static String version = "1.0";

# 重载（仅类型层面，运行时只有最后一个实现生效）
@overload
def get(key: str) -> str: ...
# 第一份签名：传 str 返回 str；函数体是 ... 没有实现
@overload
def get(key: int) -> bytes: ...
# 第二份签名：传 int 返回 bytes
def get(key):
    # 真正的实现，前面不能加 @overload；运行时只有这一个函数存在
    # 实现里的 key 不需要写联合类型（但写了更好，方便检查实现是否覆盖所有分支）
    ...
```

`Literal` 在 FastAPI 里很实用——自动生成枚举型 OpenAPI schema。

## 九、类型检查工具

### mypy（老牌，最严格）


```ini
# pyproject.toml

warn_return_any = true

exclude = ["tests/"]
```

```python
# ---- 本段讲：mypy 能抓到的两类典型错误（这些代码运行时都能跑通）----
# 注意：这两段故意写错，用来演示静态检查的价值；直接运行 Python 不会报错。
# mypy 能抓到的问题
def f(x: int) -> str:
    return x                # error: Incompatible return value type (got "int", expected "str")
    # 注解声明返回 str，实际返回 int；mypy 报错，解释器照跑不误
    # Java 里等价于 return int 到 String 方法，编译期直接失败

def g(lst: list[int]) -> None:
    lst.append("a")         # error: Argument 1 has incompatible type "str"; expected "int"
    # 往 List<Integer> 里塞 String；mypy 报错，运行时 list 完全不做元素类型检查
    # Java 泛型在编译期就会拒绝这行（类型擦除只影响运行时，不影响编译期检查）
```

### 渐进式策略（推荐）

不要一上来就 `strict = true`——存量代码会报几百个错。分三步：

```text
① 新代码必须带注解（团队约定 + CI 检查新文件）
② 关键模块（对外 API、核心领域）开启 strict
③ 存量代码逐步补，允许 # type: ignore
```

```python
# ---- 本段讲：用 type: ignore 做局部豁免（并带上错误码）----
# 建议写成 # type: ignore[具体错误码]，这样"只压这一条"，其他错误仍会暴露。
# 对应 Java 的 @SuppressWarnings("unchecked")，但 Java 的抑制范围是注解所在声明。
# 局部忽略
result = legacy_call()  # type: ignore[no-untyped-call]
# legacy_call 没有类型注解，mypy 在 strict 下会报 no-untyped-call；
# 这行注释让检查器跳过这一条错误，运行行为完全不变
# 不加错误码的裸 # type: ignore 会屏蔽整行的所有错误，容易掩盖真问题
```

## 十一、pytest：测试怎么写

```python
# ---- 本段讲：pytest 的六种基本写法（断言 / 参数化 / 异常 / fixture / 临时目录 / mock）----
# 与 JUnit 5 的对应：assert ↔ assertEquals、parametrize ↔ @ParameterizedTest、
# fixture ↔ @BeforeEach、pytest.raises ↔ assertThrows、unittest.mock ↔ Mockito。
# 最大差别：不需要继承测试基类，也不需要 @Test 注解 —— 函数名 test_ 开头就会被发现。
# tests/test_order.py
import pytest                       # 测试框架；同时提供 fixture / mark / raises
from app.order import Order, calculate_total
# 直接 import 业务代码；注意项目要用 python -m pytest 从根目录跑，否则会 ModuleNotFoundError


def test_simple():
    # 普通 assert 即可，失败时 pytest 会自动改写断言并打印两边的值
    # Java 里要写 assertEquals(30, calculate_total(List.of(10,20)))
    assert calculate_total([10, 20]) == 30


# 参数化（替代 JUnit @ParameterizedTest）
@pytest.mark.parametrize("items,expected", [
    # 第一个参数是"参数名逗号分隔的字符串"，第二个参数是"用例列表的列表"
    # 每组用例都会独立跑一次，失败时报告里能看出是哪一组
    ([], 0),
    ([10], 10),
    ([10, 20], 30),
    ([10, -5], 5),
])
def test_total_param(items, expected):
    # 形参名必须与 parametrize 里声明的名字一致（items, expected）
    assert calculate_total(items) == expected


# 异常断言
def test_invalid():
    with pytest.raises(ValueError, match="不能为负"):
        # with 块内必须抛出指定异常，否则测试失败；match 是对异常消息的正则匹配
        # Java 对应：assertThrows(ValueError.class, () -> calculate_total(List.of(-1)))
        calculate_total([-1])


# fixture（替代 @BeforeEach）
@pytest.fixture
def order():
    # fixture 是被"注入"到测试函数参数里的准备函数；默认每个测试都新建一次
    # Java 对应：@BeforeEach void setUp() { order = new Order("A", 100.0); }
    return Order("A", 100.0)        # 返回值会作为同名参数传进测试函数


def test_order_large(order):
    # 参数名 order 与 fixture 名一致，pytest 自动注入，无需手动调用
    assert not order.is_large       # 断言"不是大额订单"；not 是整个表达式的取反


# 临时目录
def test_write(tmp_path):
    # tmp_path 是 pytest 内置 fixture，提供每个测试独立的临时目录（pathlib.Path）
    # Java 对应：@TempDir Path tempDir
    p = tmp_path / "a.txt"          # / 运算符被 Path 重载为"拼接路径"，等价 Paths.get(dir, "a.txt")
    p.write_text("x", encoding="utf-8")   # 写文本文件；显式指定编码避免平台差异
    assert p.read_text(encoding="utf-8") == "x"   # 读回来校验，证明写入成功


# 打标记
@pytest.mark.slow
def test_slow():
    # 自定义标记需要在配置里注册（strict-markers 会校验），用于 -m "not slow" 过滤
    # Java 对应：@Tag("slow")
    ...


# mock（本项目测试全 mock LLM，不花钱）
from unittest.mock import patch, AsyncMock
# patch 用于替换被测代码里的符号；AsyncMock 用于 mock 异步函数

def test_with_mock():
    with patch("app.core.llm.get_llm_client") as m:
        # 字符串形式指定"要替换哪个模块里的哪个名字"，在 with 块内生效，退出后自动还原
        # Java 对应：Mockito.mock / @MockBean
        m.return_value.create.return_value = "mocked"
        # 逐层设置返回值：get_llm_client() 返回的 mock 对象，其 .create() 再返回 "mocked"
        ...
```

```bash
pytest                          # 跑全部
pytest tests/test_order.py::test_simple   # 跑单个
pytest -k "order and not slow"  # 按名字过滤
pytest -x                       # 遇到失败就停
pytest -v                       # 详细
pytest --lf                     # 只跑上次失败的
pytest --cov=app --cov-report=term-missing    # 覆盖率
```

### 本项目 `tests/test_chat_api.py` 的真实模式

```python
# ---- 本段讲：用 httpx + ASGITransport 做不占端口的接口测试 ----
# 与 Java 的 @SpringBootTest(webEnvironment=RANDOM_PORT) 相比：这里连端口都不用起，
# 直接把请求"喂"给 ASGI 应用对象，速度快很多，也不会和别的测试抢端口。
import pytest
from httpx import ASGITransport, AsyncClient
# httpx：异步 HTTP 客户端；ASGITransport 让它绕过网络直连 app
from app.main import create_app

@pytest.fixture
async def client():
    # async fixture：用 async def 定义，pytest-asyncio 负责驱动它
    app = create_app()
    # 工厂函数构造应用实例（而不是 import 全局 app），保证每个测试拿到干净实例
    transport = ASGITransport(app=app)
    # 把 ASGI 应用包装成 transport，请求不会真的走 socket
    async with AsyncClient(transport=transport, base_url="http://test") as c:
        # base_url 是必填的占位域名，实际不会解析 DNS
        yield c
        # yield 之前是 setup，yield 之后是 teardown：
        # 测试跑完回到这里，async with 负责关闭连接池
        # Java 对应：@BeforeEach 里建 RestTemplate，@AfterEach 里释放

@pytest.mark.asyncio
async def test_health(client):
    # 标记为异步测试；若配置了 asyncio_mode = "auto" 可省略这个装饰器
    # client 参数来自上面的 fixture，由 pytest 注入
    r = await client.get("/api/health")     # 真异步请求，但走内存直连
    assert r.status_code == 200              # 校验 HTTP 状态码
    assert r.json() == {"status": "up"}      # r.json() 把响应体解析成 dict，再与期望值比较
```

关键点：

- `ASGITransport` 直接调 app，**不起真实端口**（比 Java 的 `@SpringBootTest(webEnvironment=RANDOM_PORT)` 更轻）
- LLM 调用被 monkeypatch/mock，测试不花钱、不依赖网络
- `pytest-asyncio` 的 `asyncio_mode = "auto"` 让 `async def test_*` 自动被识别

## 十四、注解的"投入产出比"

| 场景 | 是否值得写全注解 |
|---|---|
| 对外 API / 公共库 | 必须 |
| Web 服务的路由层、schema | 必须（FastAPI 依赖它工作） |
| 业务核心逻辑 | 强烈建议 |
| 一次性脚本 | 不必 |
| 复杂泛型工具代码 | 值得，但要注意别过度设计 |

**推荐起步策略**：给所有**函数签名**加注解（参数 + 返回值），内部变量能推断就省。这样投入最小、收益最大（IDE 补全 + 重构安全 + 文档）。
