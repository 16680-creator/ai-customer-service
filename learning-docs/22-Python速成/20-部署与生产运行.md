# 20 · 部署与生产运行

> 开发时 `uvicorn --reload` 能跑，不等于能上线。Python 服务上线要解决的是：**进程模型、配置、依赖可复现、日志、健康检查、优雅退出和资源边界**。

---

## 一、开发命令与生产命令分开

```bash
# 开发：自动重载、单进程、详细日志
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# 生产：去掉 reload，按核数配置 worker，监听容器端口
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4
```

`--reload` 会额外启动监控进程、反复 import 模块，**生产禁用**。

### worker 数量不是越大越好

```text
IO 密集、全异步：1~2 × CPU 核数起步，按压测调整
含较多同步代码：worker 可以增加，但线程池与 DB 连接池也会成倍放大
CPU 密集：接近物理核数，同时控制每进程内并发
```

多 worker 的注意点：

- 每个进程独立内存、独立缓存、独立事件循环
- `asyncio.Lock` / `threading.Lock` 只保护**单进程**
- DB 连接池总连接数 ≈ `worker 数 × 每池上限`
- 本地会话、内存限流、内存熔断在 worker 间不共享

这正是 Java 侧库存扣减不能靠 JVM 内锁、要落 DB 原子更新的同一道理。

## 二、依赖必须可复现

### 最小方式

```text
requirements.txt：写直接依赖与兼容范围
requirements-lock.txt：pip freeze 固定完整环境（可选）
```

### 推荐方式：uv

```bash
uv lock
uv sync --frozen
```

`--frozen` 在 lock 文件与配置不一致时直接失败，避免 CI 静默装出另一套依赖。

构建时分两步复制，利用 Docker 层缓存：

```dockerfile
FROM python:3.12-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PYTHONUTF8=1

WORKDIR /app

COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

COPY app ./app

RUN useradd --create-home --uid 10001 appuser
USER appuser

EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "2"]
```

要点：

- 先装依赖再复制源码，改业务代码不必重装依赖
- 非 root 用户运行
- 不复制 `.env`、`.venv`、测试缓存进镜像
- `PYTHONUNBUFFERED=1` 让日志及时输出到容器 stdout
- 基础镜像固定到明确版本，重要项目进一步固定 digest

`.dockerignore`：

```text
.venv
__pycache__
.pytest_cache
.mypy_cache
.ruff_cache
.env
*.log
.git
tests
```

## 三、配置与密钥

优先级建议：

```text
环境变量 / 密钥管理器  >  本地 .env（仅开发）  >  代码默认值
```

规则：

- `.env` 不进 Git、不进镜像
- 启动时对必需配置 fail fast
- 不在日志打印完整配置，尤其 API key、连接串
- 配置项带类型和范围校验

```python
class Settings(BaseSettings):
    llm_api_key: SecretStr
    llm_timeout: float = Field(default=30.0, gt=0, le=120)
    cors_origins: str = ""

    @property
    def cors_list(self) -> list[str]:
        return [x.strip() for x in self.cors_origins.split(",") if x.strip()]
```

生产 CORS 不要使用 `* + allow_credentials=True`。明确列出来源。

## 四、日志与可观测性

生产日志至少包含：

```text
时间戳 / 级别 / logger / traceId / method / path / status / 耗时 / 错误类型
```

请求日志注意：

- 不记录完整 LLM prompt、用户隐私、Authorization
- SSE 不把每个 token 都打成 INFO
- 错误日志带异常栈，但响应体不暴露堆栈
- 日志输出到 stdout，由容器平台收集，不在容器里写无限增长的本地文件

对照 Java 侧 MDC，Python 可以用 `contextvars.ContextVar` 保存 traceId。注意中间件在请求结束时 reset，避免上下文复用。

## 五、健康检查要分两种

| 类型 | 用途 | 应检查什么 |
|---|---|---|
| liveness | 进程是否还活着，是否需要重启 | 应用自身，不依赖下游 |
| readiness | 是否能接流量 | 必需配置、关键资源是否就绪 |

```python
@app.get("/health/live")
async def live():
    return {"status": "up"}

@app.get("/health/ready")
async def ready():
    # 只检查真正必要的条件，避免 LLM 抖动导致服务频繁摘流量
    return {"status": "ready"}
```

liveness 不要调用 LLM/DB。否则下游一次抖动，会让容器平台把所有健康实例也重启掉。

## 六、优雅停机

停止服务时应：

1. 停止接收新连接
2. 等待在途请求完成（有超时）
3. 取消后台任务
4. 关闭 HTTP Client、DB 连接、线程池
5. 释放生成器/流式响应资源

用 lifespan 管理生命周期：

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app):
    client = httpx.AsyncClient(timeout=10)
    app.state.http = client
    try:
        yield
    finally:
        await client.aclose()

app = FastAPI(lifespan=lifespan)
```

K8s 还要配置：

- preStop / terminationGracePeriodSeconds
- readiness 先摘流量，再终止进程
- 不把 termination 超时设得比最长请求还短

## 七、反向代理与 SSE

Nginx 关键点：

```nginx
location /api/ {
    proxy_pass http://python_app;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

    # SSE
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;
}
```

应用 SSE 响应仍建议带：

```python
headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"}
```

生产 `uvicorn` 若运行在代理后，按部署方式配置 `--proxy-headers` 与允许的 forwarded IP，避免客户端 IP/协议识别错误。**不要在不可信网络上 blindly trust 所有 forwarded header**。

## 八、资源与故障边界

必须设置：

- HTTP 连接/读/写/池超时
- LLM 总超时与流式 idle 超时
- DB 连接池上限、获取连接超时
- 请求体大小限制
- 每实例并发上限与队列上限
- 外部调用重试次数、退避、熔断、降级

容器 CPU/内存 limit 要与 worker 数一起评估。一个 worker 一份模型/缓存时，内存很容易按 worker 线性增长。

## 九、上线检查清单

### 构建

- [ ] CI 跑过 ruff、类型检查、pytest
- [ ] 依赖锁定，镜像可重复构建
- [ ] 镜像不含 `.env`、密钥、缓存、本机路径
- [ ] 非 root 运行

### 运行

- [ ] 无 `--reload`
- [ ] worker/连接池/容器资源匹配
- [ ] 所有外部 IO 有超时
- [ ] liveness/readiness 分开
- [ ] 日志含 traceId，敏感字段脱敏
- [ ] 启动能验证必需配置，缺失即失败
- [ ] 停机有关闭资源与等待在途请求的策略

### 验证

- [ ] `/docs` 在生产按需要关闭或鉴权
- [ ] CORS 收敛到真实前端来源
- [ ] SSE 经过真实代理验证，不只在本地测
- [ ] 压测观察 P95/P99、错误率、内存，而不只看平均耗时
- [ ] 演练下游超时、DB 断开、实例重启与回滚

## 十、docker-compose 最小示例

```yaml
services:
  py-chat:
    build: .
    ports:
      - "8000:8000"
    environment:
      LLM_BASE_URL: ${LLM_BASE_URL}
      LLM_API_KEY: ${LLM_API_KEY}
      LLM_MODEL: ${LLM_MODEL:-deepseek-chat}
      CORS_ORIGINS: ${CORS_ORIGINS:-http://localhost:5173}
    restart: unless-stopped
    read_only: true
    tmpfs:
      - /tmp
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/api/health')"]
      interval: 30s
      timeout: 3s
      retries: 3
```

只读根文件系统下，如果应用需要写 SQLite/导出文件，必须显式挂载可写数据目录，并把路径做成配置。
