# 24 · Java 项目迁移 Python 的策略与边界

> 学完语法后最容易犯的错，是**把整个 Java 系统重写一遍**。
> 真正该做的是判断：哪些模块迁移收益高、哪些必须留在 Java、两边如何共存。

---

## 一、先回答三个问题

在写任何 Python 代码之前：

```text
① 这个模块的瓶颈是语言，还是架构/数据库/流程？
② 迁移后，团队能不能长期维护 Python 的部署、监控、排查、招聘？
③ 两边共存时，契约、数据一致性、故障边界谁来负责？
```

如果第 ① 题答案是“不是语言”，迁移大概率只会增加复杂度。

---

## 二、适合 / 不适合迁移的判断表

| 模块特征 | 倾向 | 理由 |
|---|---|---|
| AI/LLM 编排、数据处理、离线评估 | **Python** | 生态与迭代速度优势明显 |
| 爬虫、文档解析、图片处理、批处理 | **Python** | 库丰富、脚本化快 |
| 内部工具、运营后台小服务、原型 | **Python** | 开发成本低 |
| 强事务订单/支付主链路 | **保留 Java** | 现有事务、幂等、对账、团队经验成熟 |
| CPU 密集、低延迟核心服务 | **保留 Java** | JVM JIT/并发模型更合适；Python GIL 是硬约束 |
| 已稳定运行、无新需求的模块 | **不动** | 重写没有业务收益 |
| 权限、认证、网关 | **保留现有** | 安全边界集中，不重复实现 |
| 需要和大量 Java 内部 SDK 深度耦合 | **保留或先抽协议** | 直接迁移会拖入整条依赖链 |

一个实用结论：

> **Python 适合做“外围、异步、AI、数据、工具”，Java 适合做“核心交易、强一致、低延迟”。**
> 不要为了统一语言而统一语言。

---

## 三、三种共存形态

### 1. 旁路服务（风险最低，适合起步）

```text
前端 / 网关 ──> Java 主链路（订单、支付、权限）
     └──────> Python 旁路（AI 对话、文档解析、报表）
```

特点：

- Python 服务独立部署，不参与核心事务
- 契约用 HTTP/JSON 或 SSE
- 失败不影响主链路
- 最适合你现在的 `ai-cs-py-chat`

### 2. 网关后共存（对外统一入口）

```text
客户端 -> Java 网关（鉴权、限流、审计）-> Java 服务
                                   └──> Python 服务
```

要点：

- 鉴权在网关做，Python 不重复实现一套
- 网关透传用户身份时，内部要签名/校验，不能裸信 header
- 超时、重试、熔断在网关和 Python 两侧都要有边界
- 日志要能跨语言串起 traceId

### 3. Strangler Fig（逐步替换）

```text
新功能 -> Python 新实现
旧功能 -> Java 保留，按流量/租户逐步切
最终   -> 旧实现下线
```

必须有：

- 契约测试（同一请求，两边响应语义一致）
- 灰度开关与回滚路径
- 双跑对比（shadow traffic）与差异告警
- 数据迁移脚本的可重放与校验

**不要**一上来做全量双写。双写失败补偿、顺序、幂等会把收益吃光。

---

## 四、契约必须先定，代码后写

跨语言最容易出问题的不是语法，而是字段和语义。

### 1. JSON 命名

Java/前端习惯 camelCase，Python 内部 snake_case：

```python
class ChatRequest(BaseModel):
    model_config = ConfigDict(populate_by_name=True)
    session_id: str | None = Field(None, alias="sessionId")
```

契约文档写清楚：

- 字段名、类型、是否必填、长度/范围
- `null` 与缺省的区别
- 时间格式（ISO 8601，带时区）
- 金额用字符串 Decimal，还是分为单位的整数
- 枚举值与未知值处理
- 错误码与 HTTP 状态码

### 2. SSE 流式

必须逐字对齐：

```text
data: {"delta":"..."}\n\n
data: [DONE]\n\n
```

包括：分帧空行、`[DONE]` 收尾、错误帧格式、代理是否缓冲、断线重连行为。Java 侧 `Flux<ServerSentEvent>` 与 Python 侧 `StreamingResponse` 的差异要在契约测试里锁住。

### 3. 错误语义

| 场景 | HTTP | 业务码 | 是否可重试 |
|---|---|---|---|
| 参数非法 | 422/400 | INVALID_ARGUMENT | 否 |
| 未认证 | 401 | UNAUTHORIZED | 否 |
| 无权限 | 403/404 | FORBIDDEN/NOT_FOUND | 否 |
| 资源冲突 | 409 | CONFLICT | 视业务 |
| 下游超时 | 504/200+业务码 | UPSTREAM_TIMEOUT | 幂等时可 |
| 系统异常 | 500 | INTERNAL | 视情况 |

跨语言最忌讳：Java 返回 `200 + code`，Python 返回 `500`，前端要写两套判断。**先定契约，再写实现。**

## 五、数据一致性边界

### 推荐

- 每个服务拥有自己的数据，不跨语言直接写对方库
- 跨服务用 API/消息，带幂等键
- 需要最终一致时用 outbox / 消息，不用“业务代码里双写”
- Python 侧写库也要明确事务边界，不能因为脚本简单就每条 commit

### 不推荐

```text
Java 写订单表 + Python 也写订单表
→ 锁、事务、字段语义、迁移脚本全部要两边同步
```

如果必须共享数据库（过渡期），至少：

- 明确唯一写入方
- 另一方只读，或只写自己的表
- 字段变更走同一份迁移脚本
- 有对账任务发现不一致

---

## 六、身份与权限

- 认证留在 Java 网关/认证服务，Python 只消费已验证身份
- 内部调用带签名或 mTLS，不能只靠内网
- Python 服务也要做资源归属校验，不能假设网关已经做完
- 多租户场景每个查询都带 tenant 条件
- 管理接口单独鉴权，不靠隐藏路径

---

## 七、性能与容量边界

| 维度 | Java | Python |
|---|---|---|
| CPU 密集 | JIT 后强 | 纯 Python 慢，需进程池/C 扩展 |
| IO 并发 | 线程池/响应式/虚拟线程 | asyncio 单线程事件循环 |
| 启动 | 秒级到十几秒 | 毫秒到秒级 |
| 内存 | JVM 堆 + 元空间 | 每 worker 独立，缓存易翻倍 |
| 打包 | fat jar | 源码 + 依赖，镜像更大 |
| 调优 | GC/JVM 参数 | worker/连接池/事件循环 |

迁移前必须做：

1. 现有 Java 接口的 P50/P95/P99 基线
2. Python 版本同场景压测
3. 连接池总连接数核算（worker × pool size）
4. 下游限流与超时演练

**不要用本机单请求耗时对比生产吞吐。**

---

## 八、测试迁移是否成功的标准

### 1. 契约测试

同一组请求分别打 Java 与 Python，比较：

- 状态码、业务码
- 关键字段与类型
- 错误语义
- SSE 分帧与结束帧

### 2. 黄金样本

保存真实脱敏请求/响应，作为回归基线。改 Python 实现后必须仍匹配。

### 3. 对账 / 影子流量

- 影子流量：复制请求给 Python，不返回给用户，只比较结果
- 对账：定时比较两边写入的关键数据
- 差异必须可解释，不能“差不多”

### 4. 故障演练

- Python 服务挂掉，主链路是否不受影响
- 下游超时，是否有降级
- 重启/发布时 SSE 是否给客户端明确结束
- 回滚是否能在分钟级完成

## 九、针对本项目的一个务实结论

结合当前仓库：

| 模块 | 建议 |
|---|---|
| `ai-cs-order` / `ai-cs-pay` | **保留 Java**。交易、幂等、对账、事务边界成熟，迁移收益低、风险高 |
| `ai-cs-chat` 的 RAG 与 AI 编排 | 可评估 Python 旁路做实验/评测，核心对话仍可留 Java |
| `ai-cs-knowledge` 文档解析/分块/评测 | Python 适合做离线流水线；向量写入仍统一走一个写入方 |
| `ai-cs-py-chat` | 定位为**独立实验服务**，不要悄悄变成第二套生产核心 |
| 数据导出、报表、运维脚本 | Python 优先 |
| 网关、认证 | 保留 Java，不在 Python 重做 |

**判断口诀**：

```text
有强事务 → Java
有 AI/数据/解析 → Python
两边都要 → 先定契约，再做旁路，不做双写
不确定 → 不迁，先写基准和契约测试
```

## 十、迁移检查清单

### 决策

- [ ] 迁移目标能用一句话说明（不是“想用 Python”）
- [ ] 有 Java 侧性能基线
- [ ] 有团队维护 Python 的现实方案
- [ ] 明确不迁移的模块与理由
- [ ] 有回滚路径

### 契约

- [ ] JSON 字段、类型、可空、时间、金额格式已定
- [ ] 错误码与 HTTP 状态一致
- [ ] SSE 分帧、结束帧、错误帧一致
- [ ] 分页、排序、幂等键一致

### 数据

- [ ] 单一写入方明确
- [ ] 事务边界明确
- [ ] 幂等与重试策略明确
- [ ] 有对账/影子对比

### 运行

- [ ] 超时、重试、熔断、限流齐全
- [ ] traceId 跨语言可追踪
- [ ] 健康检查与优雅停机
- [ ] 容量与连接池核算
- [ ] 安全清单（见 [23 篇](23-安全编码与常见漏洞.md)）通过
