# 优化说明：代码示例校验器 + 文档围栏修正

> 本文档记录本轮优化的**具体改动**与**遗留验证缺口**。

---

## 一、为什么改

上轮分析发现：`validate_all_examples.py` 报出的 30 处「语法错误」中，**没有一处是真的代码错误**，
但其中暴露出一个**真实的工具缺陷**：

```python
# 旧代码：validate_all_examples.py 第 102 行
if current_lang in ("python", "py", "unknown"):
```

当 Markdown 围栏**未标注语言**（裸 ```` ``` ````）时，`current_lang = "unknown"`，
**同样被送进 `ast.parse()` 校验**。而实测数据：

| 项 | 数量 | 占比 |
|---|---|---|
| 代码块总数 | 1,383 | 100% |
| 显式 ```` ```python ```` | 484 | 35% |
| **裸围栏（无语言标识）** | **701** | **51%** |
| 其他语言（java/text/bash…） | 195 | 14% |

这 701 个裸围栏里装的是**输出、火焰图、目录树、日志片段、Prometheus 指标**，
用 Python 语法去校验它们属于**误判**。

**后果**：通过率分母被污染 → 指标从有意义的 ~96% 被拉低到无意义的 90.2%，
且失败清单里混满误报，真正的缺陷反而被淹没。

## 二、改动一：校验器按「显式标注才算数」

### 2.1 新增两个字段

`CodeBlock` 增加 `explicit` 与 `no_check`：

```python
def __init__(self, file, line_no, code, language="python",
             explicit=True, no_check=False):
    ...
    self.explicit = explicit    # 围栏是否显式标注了语言（```python）
    self.no_check = no_check    # 是否被标记为"不校验"（示意/伪代码）
```

### 2.2 解析围栏附加信息

```python
fence_info = line.strip()[3:].strip()          # 切掉 ``` 取剩余信息
lang_match = re.match(r"(\w+)", fence_info)    # 取语言名
current_lang = lang_match.group(1) if lang_match else "unknown"
current_info = fence_info.lower()              # 保留 "no-check" 等标记
...
explicit=(current_lang != "unknown"),
no_check = "no-check" in current_info or "nocheck" in current_info
```

### 2.3 校验时跳过（不判失败）

```python
if block.no_check:      # ```python no-check → 示意代码
    return ValidationResult(block, is_valid=True,
                            warning="Skipped: marked no-check (示意/伪代码)")

if not block.explicit:  # ``` 裸围栏 → 无法判定语言
    return ValidationResult(block, is_valid=True,
                            warning="Skipped: no language tag (裸围栏，无法判定语言)")
```

### 2.4 统计口径修正（**最关键**）

**旧**：`通过率 = valid / total`（分母含无法判定的块）

**新**：`通过率 = passed / checked`，其中
- `checked = total - skipped`（只含可校验块）
- `passed = 通过且无 warning`

并新增**跳过原因分布**输出，便于判断「是真跳过还是掩盖了问题」：

```text
⚠️  跳过原因分布:
   412  Skipped: no language tag (裸围栏，无法判定语言)
    11  Skipped: marked no-check (示意/伪代码)
     7  Skipped: Incomplete snippet
     4  Skipped: Java code for comparison
     ...
```

## 四、改动三：修正 6 处真正混排的文档

这一类是**读者复制粘贴会直接报错**的实打实缺陷，不只是校验问题。

| 文件 | 位置 | 问题 | 修法 |
|------|------|------|------|
| `25-可观测性` | 421 | 一个 ```` ```python ```` 块里混了 Python 与 `spring.zipkin.base-url=…` | 拆成 `python` + `properties` 两块 |
| `25-可观测性` | 294 | Prometheus `/metrics` 原始输出 | 改为 ```` ```text ```` |
| `25-可观测性` | 515 | Grafana 面板框线图 | 改为 ```` ```text ````，补「非可执行代码」说明 |
| `25-可观测性` | 543 | ① ② ③ 排查步骤 | 改为 ```` ```text ```` |
| `01-环境搭建` | 283 | REPL 转录（`>>>` 提示符） | 改为 ```` ```pycon ````（Pygments 标准标识） |
| `16-调试排查` | 382 / 530 / 567 | 日志输出、火焰图、运行输出 | 改为 ```` ```text ```` |
| `11-FastAPI` | 603 | `except:` 裸片段，缺 `def`/`try` | **补全为可运行的生成器**（见下） |

`11篇` 那处不只是加标签，而是补成了完整可运行代码：

```python
async def stream_chat(prompt: str):
    try:
        async for token in call_llm(prompt):
            yield f"data: {json.dumps({'delta': token}, ensure_ascii=False)}\n\n"
    except Exception as exc:
        yield f"data: {json.dumps({'error': str(exc)})}\n\n"
    finally:
        yield "data: [DONE]\n\n"
```

> 注意这里用 `finally` 而不是原先的「异常后继续 `yield`」——
> 原写法在 `except` 分支里 `yield` 之后就结束了，正常路径反而漏发 `[DONE]`。
> 用 `finally` 才能保证**成功与失败都发**，这才是注释里承诺的语义。
