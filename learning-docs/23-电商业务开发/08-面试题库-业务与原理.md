## A. 电商业务与商品模型（1-10）

### 1. 典型电商交易主链路是什么？
**答题要点：** 商品发布/上架 → 搜索/详情 → 加购 → 结算试算 → 下单与扣库存 → 支付 → 履约 → 售后/退款；标出每步的主数据和一致性要求。项目当前覆盖商品、购物车、订单、支付、搜索及售后申请部分能力，履约链路不完整：`01-电商系统全景与技术地图.md` §3。

### 2. SPU 与 SKU 的区别？
**答题要点：** SPU 描述商品抽象款式，SKU 是具体可售卖规格组合；价格、条码、库存通常落实到 SKU。项目 product 表是单商品模型，没有独立 SKU 表，因此不能声称支持颜色/尺码维度库存：`ai-cs-product/src/main/java/com/aics/product/entity/Product.java:19-46`。

### 3. 商品表为什么要有逻辑删除？
**答题要点：** 业务删除不一定立即物理清除，需保留引用和审计；查询必须自动排除 deleted，唯一键和重建流程也要考虑历史行。项目 Product 使用 `@TableLogic deleted`：`ai-cs-product/src/main/java/com/aics/product/entity/Product.java:45-46`。

### 4. 商品详情和订单商品为什么需要不同模型？
**答题要点：** 商品是会变化的主数据，订单项应保存成交时名称、价格、规格等快照，避免商品后来改价/改名改变历史订单。项目订单项写入商品名和价格快照：`ai-cs-order/src/main/java/com/aics/order/service/impl/OrderCreateTxService.java:119-129`。

### 5. 商品类目树怎么存？
**答题要点：** 邻接表易维护但递归查询较多；路径枚举/闭包表读子树更快但维护成本更高；按查询和更新频率选型。项目 product_category 用 parent_id 表示父子关系：`deploy/mysql/product-init.sql:10-20`。

### 6. 商品状态和库存状态是否应该混在一个字段？
**答题要点：** 上下架是运营可见状态，库存是可售数量/库存策略，两者语义和变化频率不同；可售判断通常综合状态、库存、活动、区域和风控。项目 Product 有 status 与 stock 两字段：`Product.java:19-37`。

### 7. 商品搜索结果为什么不能作为成交依据？
**答题要点：** ES 是异步读模型，可能有延迟；订单提交时须重新校验价格、上下架和库存。CDC 消费端写入 `product_catalog`，但 Canal 编排未落地：`ai-cs-search/src/main/java/com/aics/search/cdc/ProductCdcConsumer.java:14-18`、`learning-docs/14-数据工程与OLAP/04-CDC与实时同步链路.md:19`。

### 8. 逻辑删除会带来哪些索引问题？
**答题要点：** 删除事件需要传播到搜索、缓存和向量索引；重放与全量重建不能让已删除数据复活。消费者对 DELETE 或 deleted=1 执行 ES 删除：`ProductCdcConsumer.java:43-60`。

### 9. 商品推荐和商品搜索有什么区别？
**答题要点：** 搜索响应显式 query 与 filters；推荐根据上下文/用户/业务目标生成候选与排序。项目有价格区间、关键词、销量的规则推荐，不是协同过滤：`ai-cs-product/src/main/java/com/aics/product/service/impl/ProductRecommendServiceImpl.java:22-30,73-89`。

### 10. 商城有哪些典型业务角色？
**答题要点：** 买家、商家/运营、平台客服、财务/风控；从不同角色看商品、订单、库存、营销、售后和结算边界。项目暂无完整商家端/履约平台，回答时注明边界：`01-电商系统全景与技术地图.md` §3。

## B. 库存与购物车（11-20）

### 11. 数据库条件更新如何防止超卖？
**答题要点：** `UPDATE product SET stock=stock-? WHERE id=? AND stock>=?`，只认影响行数；不能先读库存再无条件写回。项目以条件更新扣 DB 库存并检查失败原因：`ai-cs-product/src/main/java/com/aics/product/service/impl/ProductServiceImpl.java:190-211`。

### 12. 为什么 Redis 库存不能天然成为最终账本？
**答题要点：** Redis 预扣可以削峰，但需处理 DB 失败、消息丢失、缓存重建与对账；若业务要求可审计库存，必须明确权威账本。项目商品服务以 DB 原子扣减为准，再同步 Redis：`ProductServiceImpl.java:195-211`。

### 13. 扣库存时机有哪些取舍？
**答题要点：** 下单预扣体验可靠但需超时释放；支付后扣可能产生支付成功无库存；Redis 预扣吞吐高但需补偿；按交易风险和可接受锁定时长选择。项目下单事务里实时调用商品服务扣库存：`ai-cs-order/src/main/java/com/aics/order/service/impl/OrderCreateTxService.java:87-95`。

### 14. 为什么库存扣减使用原子 SQL？
**答题要点：** 读-改-写存在竞态；条件更新将判断与扣减放在一条语句中，受影响行数就是抢占结果。项目实现使用 stock>=quantity 条件并在零行时区分商品不存在/库存不足：`ProductServiceImpl.java:195-208`。

### 15. 下单扣多个商品如何降低死锁？
**答题要点：** 所有事务按稳定顺序锁定 SKU，缩短事务，控制批量大小；捕获死锁后仅对幂等操作有限重试；监控锁等待。项目扣减循环按购物车返回顺序执行，未看到统一排序：`OrderCreateTxService.java:93-95`（改进建议 ⚠️）。

### 16. 购物车重复添加同一商品如何处理？
**答题要点：** 以用户+商品/SKU 唯一键合并数量，并在并发插入时处理唯一键冲突后重试更新。项目表有 `uk_user_product`：`deploy/mysql/order-init.sql:19-21`；具体服务存在先查再插的并发窗口，见 `CartServiceImpl.java:58-107`。

### 17. 购物车价格能否直接作为成交价？
**答题要点：** 购物车价格是展示快照，不应作为不可变成交依据；下单要读权威价格、做差异确认或报价有效期。项目当前使用 CartItem.productPrice 算订单金额：`OrderCreateTxService.java:97-101`（价格新鲜度风险 ⚠️）。

### 18. 购物车接口如何防越权？
**答题要点：** 每次按当前认证用户过滤资源，不信任客户端传来的 item id；批量查询也必须校验结果全属于当前用户。项目下单处按 cartItemIds 查询后，该片段未按 userId 再过滤：`OrderCreateTxService.java:80-85`（需重点验证/修复 ⚠️）。

### 19. 库存缓存如何与数据库同步？
**答题要点：** 明确 DB 权威、缓存预热/失效、并发更新和重建方式；不能只在 Redis 扣而漏写 DB。项目有 stock cache 同步接口与历史事故注释：`ProductServiceImpl.java:233-241`。

### 20. 如何为库存扣减写测试？
**答题要点：** 覆盖库存足够成功、刚好为零边界、库存不足、商品不存在、并发请求只允许不超过库存数量成功；集成环境验证真实 SQL 条件和 affected rows。项目单测覆盖成功/库存不足/不存在：`ai-cs-product/src/test/java/com/aics/product/service/ProductServiceTest.java:268-312`；并发真实数据库验证仍需补充。

## C. 订单、状态机与优惠（21-30）

### 21. 订单创建事务要保证什么？
**答题要点：** 用户购物车归属、商品可售、库存占用、价格/优惠重算、订单和明细快照、幂等、超时释放；拆清本地事务和跨服务事务边界。项目订单创建使用 Seata 全局事务+本地事务：`ai-cs-order/src/main/java/com/aics/order/service/impl/OrderCreateTxService.java:78-95`。

### 22. 订单状态机能解决什么问题？
**答题要点：** 限定合法状态迁移，避免不同接口各自改状态；迁移由单一入口执行并记录拒绝。项目通过 `OrderStateTransitionService.transit` 同步保护并拒绝非法事件：`ai-cs-order/src/main/java/com/aics/order/statemachine/OrderStateTransitionService.java:21-35`。

### 23. 订单号为什么不能用进程内计数器？
**答题要点：** 多实例计数器相互独立、重启重置、计数回绕，存在碰撞风险；可采用 DB sequence、号段、雪花 ID 或业务日期+分布式序列，并配唯一约束。项目生成器含 AtomicInteger：`OrderCreateTxService.java:51,160-164`（⚠️）。

### 24. 订单列表为什么需要分页？
**答题要点：** 用户历史订单持续增长，全量返回会放大 DB、网络和前端内存成本；需要稳定排序、游标/页码与总数策略。项目 `listOrders` 当前无分页：`ai-cs-order/src/main/java/com/aics/order/service/impl/OrderServiceImpl.java:62-76`（⚠️）。

### 25. 订单超时取消如何保证可靠？
**答题要点：** 延迟消息只是快速触发，数据库扫描兜底；消费幂等、重新检查状态和到期时间，防止取消已支付订单；库存/券恢复也幂等。项目下单发延迟消息：`OrderCreateTxService.java:143-146`；订单超时流程见 `OrderServiceImpl.java:166-176`。

### 26. 订单创建为什么要有幂等？
**答题要点：** 客户端超时重试可能重复创建；用用户+幂等 token/业务请求号唯一约束，首次结果可复用；不要仅依赖按钮禁用。项目公共幂等注解使用 Redis NX 并声明 Redis 故障 fail-open：`ai-cs-common/src/main/java/com/aics/common/idempotent/Idempotent.java:12-17,31-34`（结合 DB 唯一约束设计）。

### 27. 满减规则重叠时如何选？
**答题要点：** 明确叠加、互斥、最优解与门槛基数；留规则版本与命中明细。项目筛选达门槛规则后选减免金额最大的一条，不叠加：`ai-cs-order/src/main/java/com/aics/order/service/impl/PromotionServiceImpl.java:88-106`。

### 28. 为什么优惠券核销要 CAS？
**答题要点：** 先读再改可能两个订单都读到 UNUSED；用 `WHERE status='UNUSED' AND user_id=?` 条件更新并检查 affected rows，数据库是最终裁决。项目当前 selectById 再 updateById，无 CAS：`OrderCreateTxService.java:132-141`（⚠️）。

### 29. 取消订单后优惠券如何恢复？
**答题要点：** 恢复前检查订单是否确实取消、券是否已占用、是否过期；动作需幂等并处理并发支付。项目取消路径将 USED 改回 UNUSED 并清理 useTime/orderNo：`ai-cs-order/src/main/java/com/aics/order/service/impl/OrderServiceImpl.java:237-245`。

### 30. 为什么金额用 BigDecimal？
**答题要点：** 十进制金额不应用二进制浮点；用字符串或最小货币单位构造、明确舍入模式，比较用 compareTo；支付、订单、优惠一致使用最终金额。项目金额字段/数据库精度和门槛比较见 `PriceCalcBO.java:13-29`、`PromotionServiceImpl.java:75-80`、`deploy/mysql/order-init.sql:28-33`。

## D. 支付、退款与对账（31-40）

### 31. 支付成功以谁的通知为准？
**答题要点：** 不能信任前端跳转；验渠道回调签名、金额、商户单号与订单状态，必要时主动查单；回调只作为可信渠道证据进入幂等状态迁移。项目支付回调由 `PayNotifyService.processNotify` 解析渠道通知：`ai-cs-pay/src/main/java/com/aics/pay/service/PayNotifyService.java:32-44`。

### 32. 支付回调为什么会重复？
**答题要点：** 渠道按至少一次语义重试，响应丢失或超时导致重放；以订单号/渠道交易号唯一约束和状态迁移防止重复记账，成功后快速返回成功应答。项目流水成功态重复会返回 false：`ai-cs-pay/src/main/java/com/aics/pay/service/impl/PayTransactionServiceImpl.java:53-70`。

### 33. 支付流水为什么要独立于订单表？
**答题要点：** 一个订单可能多次支付尝试、渠道交易号、退款和对账，需要保存支付过程与状态；订单状态不能替代资金流水。项目 pay_transaction 由启动期 schema initializer 创建并以 order_no 唯一：`ai-cs-pay/src/main/java/com/aics/pay/config/PaySchemaInitializer.java:22-40`。

### 34. 支付成功但订单仍待支付怎么处理？
**答题要点：** 可靠消息/事务消息通知订单服务，主动查单和补偿扫描兜底；告警并保留可重放记录。项目支付成功可走 RocketMQ 事务消息，并有补偿服务扫描成功流水查订单：`ai-cs-pay/src/main/java/com/aics/pay/service/PayNotifyService.java:57-73`、`PayCompensationServiceImpl.java:55-66`。

### 35. 跨服务支付如何避免分布式事务？
**答题要点：** 支付本地流水事务 + 可靠事件 + 订单幂等消费 + 补偿/查单；每步有可观测状态，不要求把第三方支付纳入 DB 原子事务。项目 `PaySuccessTransactionListener` 实现事务消息本地状态检查：`ai-cs-pay/src/main/java/com/aics/pay/mq/PaySuccessTransactionListener.java:34-68`。

### 36. 主动查单为什么也要验金额？
**答题要点：** 主动查询是渠道状态确认，不应跳过订单金额/币种/商户号核验；空金额不能当通过。项目 `syncByQuery` 在成功时传 null 金额到统一通知方法，形成金额校验缺口：`ai-cs-pay/src/main/java/com/aics/pay/service/PayNotifyService.java:46-55`（⚠️）。

### 37. 退款与取消订单有什么区别？
**答题要点：** 取消通常是未支付订单关闭与资源释放；退款是已支付资金逆向流程，需要渠道退款单、部分/全额金额、退款状态与对账。项目有退款状态服务但真实渠道退款 REST 闭环未完成，见 `04-支付退款与资金对账.md` §7。

### 38. 退款幂等键为什么重要？
**答题要点：** 渠道超时重试不能产生多笔退款；稳定 refundRequestId/outRefundNo 持久化并唯一，不能每次重试重新拼当前时间。项目微信退款号含 currentTimeMillis：`ai-cs-pay/src/main/java/com/aics/pay/channel/WechatNativeChannel.java:176-195`（⚠️）。

### 39. 对账要比哪些账？
**答题要点：** 内部订单、支付流水、渠道账单三方按商户单号/渠道单号/金额/状态/日期匹配；覆盖长款、短款、单边账、金额不符，输出差异工单与可审计修复。项目补偿目前比对内部流水和订单，没有完整渠道账单三向对账：`ai-cs-pay/src/main/java/com/aics/pay/service/impl/PayCompensationServiceImpl.java:35-73`。

### 40. 如何避免退款重复或超额？
**答题要点：** 退款申请记录唯一幂等键、行锁/CAS 累计已退金额、限制不超过实付金额，渠道返回后再迁移状态；部分退款按原订单分摊优惠和运费。

## E. 搜索、推荐与一致性（41-50）

### 41. ES 索引与 MySQL 的关系是什么？
**答题要点：** MySQL 是写模型权威，ES 是可重建读模型；CDC 保持最终一致并通过对账修复差异。项目消费者订阅 `c-product-sync` 写 `product_catalog`：`ai-cs-search/src/main/java/com/aics/search/cdc/ProductCdcConsumer.java:23-24`。

### 42. 消息重放如何做到幂等？
**答题要点：** 固定业务主键作为 ES id，upsert 覆盖，delete 可重复；还要额外防止旧版本乱序覆盖。项目用 product id 作为文档 id：`ProductCdcConsumer.java:43-64`。

### 43. CDC 失败会不会丢消息？
**答题要点：** 失败抛异常让 MQ 重试；超过重试上限要进 DLQ、告警和人工/自动重放；仅写重试不够。项目消费者异常抛出触发 MQ 重试：`ProductCdcConsumer.java:61-64`。Canal 部署仍未落地：`14-数据工程与OLAP/04-CDC与实时同步链路.md:19`。

### 44. BM25 与向量检索如何融合？
**答题要点：** BM25 擅长精确词项，向量擅长语义近似；原始分数不可直接相加，可用 RRF 融合排名。项目知识库检索两路 Top-20、RRF_K=60：`ai-cs-search/src/main/java/com/aics/search/hybrid/HybridSearchServiceImpl.java:40-73`。

### 45. 项目 RRF 是商品检索吗？
**答题要点：** 不是；现有 HybridSearchService 按 knowledgeBase 过滤，服务知识库文档检索。商品 CDC/推荐是不同链路，不能混淆：`HybridSearchServiceImpl.java:19-32,49-73`。

### 46. 当前商品推荐是怎样的？
**答题要点：** 以基准价±tolerance 召回上架商品，可选类目；关键词全部匹配，按关键词命中、价格接近、销量排序。不是个性化协同过滤：`ai-cs-product/src/main/java/com/aics/product/service/impl/ProductRecommendServiceImpl.java:44-89`。

### 47. 为什么商品向量存储不能直接上生产？
**答题要点：** 内存 SimpleVectorStore 无持久化、跨实例共享与重启恢复保证；生产要验证存储、备份、更新、过滤、召回延迟。项目配置：`ai-cs-product/src/main/java/com/aics/product/config/VectorStoreConfig.java:14-20`。

### 48. 搜索分页有哪些风险？
**答题要点：** 深分页成本、排序不稳定、索引更新造成翻页重复/遗漏；可用 search_after/PIT 和稳定 tie-breaker。项目知识库 hybrid 是先取 page*size 再内存分页，不等于商品海量目录方案：`ai-cs-search/src/main/java/com/aics/search/controller/SearchController.java:41-62`。

### 49. 如何衡量搜索质量？
**答题要点：** 零结果率、点击/加购/转化、Recall/NDCG（有标注集时）、P95/P99、索引延迟、DLQ 和数据差异率；按 query 类别、位置和实验组分层。

### 50. 商品下架后如何尽快从搜索中消失？
**答题要点：** 事件传播删除/过滤、查询层可售校验、同步延迟监控和定时对账共同兜底；明确一致性 SLA 和极端故障策略。

## F. 稳定性、安全与面试表达（51-60）

### 51. 大促容量如何估算？
**答题要点：** 按访问漏斗拆 endpoint 到达率、峰值窗口、热点和重试，再用实测单实例安全吞吐估算副本，并核 DB/MQ/Redis/ES 预算；静态估算不能冒充压测结果。项目性能报告标记实测数据待回填：`docs/27-性能基线报告.md:3-9`。

### 52. 为什么不对 POST 下单盲目自动重试？
**答题要点：** 服务可能已完成副作用但响应丢失，盲重会重复建单/扣库存；写操作须有幂等键并确认最终状态。项目网关只对 GET 做两次重试：`ai-cs-gateway/src/main/java/com/aics/gateway/config/RouteConfig.java:174-180`。

### 53. 网关限流键如何选？
**答题要点：** 登录用户按可信 userId，匿名按 IP；考虑代理头可信边界、NAT 误伤和绕过风险。项目 `userKeyResolver` 优先 X-User-Id，否则取 remote IP：`RouteConfig.java:151-166`。

### 54. Redis 锁适合解决哪些问题？
**答题要点：** 限制同用户并发创建等短临界区，但仍需 DB 唯一约束/状态条件保证正确性；注意租约、续期、异常释放和锁粒度。项目创建订单锁使用用户级 Redisson 快速失败，详见 `03-购物车与交易下单链路.md` §4。

### 55. 日志里应避免记录什么？
**答题要点：** 密码、完整 token、银行卡/身份证、支付密钥和敏感个人数据；使用脱敏、traceId、最小必要字段与访问控制。支付验签密钥应来自安全配置，不应写入日志。

### 56. 如何保护支付回调接口？
**答题要点：** 验签、来源/时间戳校验、金额/商户/订单校验、幂等状态迁移、限流与审计；响应按渠道协议返回，防止无意义重试风暴。项目渠道抽象要求验签失败抛异常：`ai-cs-pay/src/main/java/com/aics/pay/channel/PayChannel.java:52-58`。

### 57. 多个电商微服务之间如何保证一致性？
**答题要点：** 先划本地事务边界，跨服务用 Saga/事务消息/补偿/幂等，不把第三方系统放进长数据库事务；每个中间态可观测可恢复。项目下单使用 Seata AT，但 MQ 不属于 Seata 资源：`OrderCreateTxService.java:78-95`。

### 58. 如何讲一个项目问题而不粉饰？
**答题要点：** 说清现象、影响范围、定位证据、根因、修复、回归测试和遗留风险；区分已修复与未验证。项目故障案例库提供四段式叙事模板：`docs/28-故障案例库.md:262-289`。

### 59. 面试官问「你们系统支持多少 QPS」怎么答？
**答题要点：** 只报可复现实测值，并说明机器、版本、数据规模、场景、延迟/错误阈值和核账结果；没有实测就坦诚给静态配置/待测计划。`docs/27-性能基线报告.md:7-9` 明确禁止将理论值当实测值。

### 60. 如何把本项目讲成电商后端项目？
**答题要点：** 用真实职责串商品/库存、订单状态、支付流水、消息/搜索；每个数字和技术点有代码证据，主动承认未做的履约、秒杀、SKU 和生产级对账。项目能力矩阵见 `01-电商系统全景与技术地图.md` §3。

## 复习方法

2. 每个「本项目」事实都要能打开对应源码定位；不确定就说不确定。
3. 练习时记录不会的题目，回到 `02`~`07` 对应专题补基础，再用自己的话重答。
4. 不要照抄代码行号作为答案；先解释业务不变量，再用行号证明项目现状。
