# learning-docs 写作规范（所有 agent 必须严格遵守）

> 目的：让一个**完全没接触过 Spring 源码**的 Java 开发者，按顺序读完后能讲清楚「框架是怎么实现的、为什么这么设计、出问题该看哪行代码」。
> 本文件是校验器的判据来源，`node tools/check-doc.mjs` 会检查 §3、§4、§5 的硬性要求。

---

- 引用源码必须写清 `仓库@tag`，例如 `spring-framework@v7.1.0`。

- 不确定的版本细节，先查：`node tools/fetch-source.mjs` 抓真实文件（见 §4），或者去看对应 tag 的 `README.adoc` / `build.gradle`。

## 3. 源码引用硬规则（校验器会拦）

### 3.1 先把原文入库（Maven 方式，最稳）

不要凭记忆写源码。所有源码从 **Maven Central 的 `-sources.jar`** 抓取，落到 `assets/source/`：

```powershell
# 在 learning-docs/24-源码分析 目录下执行
node tools/fetch-source.mjs --from maven --gav org.springframework:spring-aop:7.1.0 `
  --path org/springframework/aop/framework/CglibAopProxy.java `
  --out assets/source/CglibAopProxy.java.md
```

**不知道 jar 内路径时，先列目录**：

```powershell
node tools/list-jar.mjs org.springframework:spring-aop:7.1.0 "aop/framework/.*\.java$"
```

已实测可用的坐标（`-sources.jar` 均为 HTTP 200）：

| 模块 | Maven 坐标（`--gav`） |
| --- | --- |
| Spring Core / Beans / Context / AOP / TX / JDBC / Web / WebMVC / Expression | `org.springframework:{spring-core,spring-beans,spring-context,spring-aop,spring-tx,spring-jdbc,spring-web,spring-webmvc,spring-expression}:7.1.0` |
| Spring Boot 核心 / 自动配置 / WebMVC / Web 容器抽象 / Tomcat / Health / Actuator | `org.springframework.boot:{spring-boot,spring-boot-autoconfigure,spring-boot-webmvc,spring-boot-web-server,spring-boot-tomcat,spring-boot-health,spring-boot-actuator}:4.2.0` |
| MyBatis / MyBatis-Spring / Boot Starter | `org.mybatis:mybatis:3.6.0`、`org.mybatis:mybatis-spring:3.0.5`、`org.mybatis.spring.boot:mybatis-spring-boot-autoconfigure:4.1.0` |
| Spring Cloud Commons / LoadBalancer / OpenFeign / Gateway / Context | `org.springframework.cloud:{spring-cloud-commons,spring-cloud-loadbalancer,spring-cloud-openfeign-core,spring-cloud-gateway-server-webflux,spring-cloud-context}:5.1.0` |
| Nacos / Sentinel | `com.alibaba.nacos:nacos-client:3.3.0`、`com.alibaba.csp:sentinel-core:1.8.10` |
| Spring Security Web / Config / Core（方法级安全在这里） | `org.springframework.security:{spring-security-web,spring-security-config,spring-security-core}:7.2.0` |
| Spring AI Chat Client | `org.springframework.ai:spring-ai-client-chat:2.1.0` |
| OTel API | `io.opentelemetry:opentelemetry-api:1.50.0` |

> ⚠️ Seata 2.7.0 在 Maven Central **没有 sources jar**（`seata-all` / `seata-spring` 均 404）。Seata 那一篇请以**图 + 概念 + 官方文档级结论**为主，源码部分只引用你**确实成功入库**的文件；没有入库就不许贴代码块（`check-doc` 会拦）。
> ⚠️ Boot 4 已把 servlet 容器抽成独立模块：`ServletWebServerApplicationContext` **不在** `spring-boot` 里，先 `list-jar` 确认后再 fetch。

入库文件是机械抓取的原文，**禁止手工修改其中的代码行**。只需要读取、引用（`read` 工具按行号范围读）。

### 3.2 正文里用锚点

```markdown
`AbstractBeanFactory#doGetBean` 先查三级缓存 [[源码:AbstractBeanFactory.java#L230-L260]]
```

- 格式固定：`[[源码:文件名#L起-L止]]`，单行可写 `[[源码:AbstractBeanFactory.java#L249]]`（示例里的文件名必须是 `assets/source/` 中真实存在的摘录，不要写 `X.java` 这类占位，校验器会报错）。
- 文件名必须与 `assets/source/` 中已入库文件一致，行号必须落在摘录范围内，否则校验失败。

### 3.3 引用代码块要可追溯

```markdown
```java (src: AbstractAutowireCapableBeanFactory.java#L331-L345)
	protected Object createBean(String beanName, RootBeanDefinition mbd, @Nullable Object[] args) ... {
		...
	}
```
```

- 代码块首行标注 `src: 文件名#L起-L止`，**代码块内容必须与原文逐字符一致（缩进/Tab 都要一致）**。
- **允许省略**：块内单独写一行 `...`（或 `// ...`）表示"中间代码略过"，校验器会自动跳到下一个匹配位置继续逐行比对。这样你可以只贴关键行，不必整段贴。
- 代码块首行必须是从 `(src: ...)` 声明里 `L起` 那一行**开始**的原文（不要从 `@Override` 上一行开始写却声明下一行）。如果起始行偏了，校验器会**告警**并自动纠偏，但你需要把标注改对。
- **讲解必须写在代码块外**：不要在带 `src:` 的代码块里加中文注释（会导致逐字符比对失败）。需要注释版就另起一个**不带 `src:`** 的 `java` 代码块，并在正文写明"上方为原文，下方为我加了注释的版本"。
- 单块建议 ≤ 60 行；大方法按"逻辑分段"拆成多个块，并说明"这是第 N 段"。

## 4. 图表规范

- 用 **Mermaid**（GitHub/IDEA 均可渲染）：`sequenceDiagram` 画调用时序，`flowchart TD` 画条件分支，`classDiagram` 画类关系，`stateDiagram-v2` 画生命周期状态。
- 每张图下面必须有一句"读图说明"，指出图中最关键的 1~2 个箭头。
- Mermaid 节点文字含括号、`#`、`<` 等特殊字符要加引号，例如 `A["beanFactory.getBean()"]`。

## 5. 文件与命名

- 目录：`NN-主题/MM-子主题/NN-篇名.md`，`NN` 两位数字。
- 文件名：小写 kebab-case + 英文，或中文短语，不要用空格，**文件名不要出现大写字母**（校验器会告警），例如 `04-bean-生命周期-源码全流程.md`。
- **多 agent 并行协作规则（重要）**：
  1. 只写你负责的目录；**绝不修改别人的文件**。
  2. `assets/source/` 是共享的：同名文件已存在就直接复用（`fetch-source.mjs` 会走 `.source-cache` 缓存，很快）；不要删除他人入库的文件。
  3. 一个 class 尽量只入库一次（文件名 = 类名 + `.java.md`）。
  4. 每篇文末必须 `## 小结` 与 `## 自测题`（10 题以上，附 `<details><summary>参考答案</summary>`）。
- 每个子目录必须有 `README.md`，内容是这一组文章的学习目标、顺序、依赖关系和"学完能做到什么"（README 里的示例锚点也会被校验，别写占位符）。

## 6. 质量红线

1. **不许编造**：类名、方法签名、行号、版本号都要能对上真实代码；拿不准就抓源码。
2. **不许抄旧文章**：Boot 3 时"`spring-boot-starter-web` 一包搞定一切"的说法，在 Boot 4 要按 POM 事实重写——它仍传递 `spring-boot-webmvc`（因此老代码还能跑），但已是 deprecated 路径，新代码用 `spring-boot-starter-webmvc`；servlet 容器实现（`spring-boot-tomcat` 等）也已独立成模块。凡是"版本变了所以行为一定变"的推断，都要先抓那个版本的 POM/源码确认。
3. **不许只贴代码不解释**：每个代码块至少 3 段说明（做了什么、为什么、坑）。
4. **不许只画图不讲实现**：图后面必须落到具体类和方法的源码。
5. **交稿前必须运行**：

```bash
node tools/check-doc.mjs <你负责的目录>
```

错误数必须为 0；警告要在交付说明里解释原因。
